## 0. 一页速览

三个最高频的"别扭"，对应三组糖：

| 作者的痛点（原生 ERB） | 糖的形态 | 编译产物 |
| --- | --- | --- |
| `PRINTFORMW` / `PRINTFORMDL` / `PRINTFORMDW` / `PRINTFORML`… 十几种变体选不对 | 一行文本就是一行文本；编辑器按"是不是台词、要不要等"自动选变体 | 精确到某一个 `PRINTFORM*` |
| `IF/ELSEIF/ELSE` 必须人工配对 `ENDIF`，漏一个就全哑 | `如果 / 否则如果 / 否则` + 缩进，编辑器自动补 `ENDIF` | `IF … ENDIF` 块 |
| `%变量%`、`{数值}`、`\@ 条件 ? A # B \@` 三套记号 | 统一 `{…}`，条件写法 `{条件 ? A : B}` | 按内容自动落成 `%…%`、`{…}` 或 `\@…\@`；**整行只有条件且假分支为空 → `IF` 块**（不产生空行） |
| `PRINTBUTTON "文本", "返回值"` 参数顺序 + 手工维护返回值 | `选项：` 块，编辑器分配返回值并生成 `INPUTS` + 分支 | `PRINTBUTTON` + `INPUTS` + `SELECTCASE RESULTS` |
| 函数名 `M_KOJO_家族_…_K{角色号}_{编号}` 手抄必错（口上"全哑"第一原因） | `时机 指令 311：` 一行声明，函数名由工具生成 | 完整函数骨架（含 `_1` 包装与登记函数） |

一句话规则（作者的视角）：

> **写台词就用引号，写旁白就不加引号；想让玩家按一下，就什么都不加；想一口气铺完，行尾写 `续`。**

## 1. 证据基础

设计不靠直觉，靠语料。以下数字直接决定了每一条语法规则的取舍。

### 1.1 指令分布（决定优先级）

`個人口上` 全量统计（按行首指令精确匹配）：

| 家族 | 关键指令与行数 | 合计 | 占比判断 |
| --- | --- | --- | --- |
| **文本输出** | `PRINTFORML` 362,384 / `PRINTFORMW` 331,545 / `PRINTFORMDW` 161,002 / `PRINTFORMDL` 144,239 / `PRINTL` 23,086 / `PRINTFORM` 5,997 / `PRINTFORMD` 1,754 / `PRINT` 743 | ≈ 103 万行 | **第一优先级**（约 28% 语料） |
| **条件分支** | `IF` 205,276 / `ENDIF` 205,268 / `ELSEIF` 101,075 / `ELSE` 99,406 / `SIF` 9,516 | ≈ 62 万行 | 第二优先级 |
| **多值选择** | `SELECTCASE` 46,427 / `CASE` 175,368 / `CASEELSE` 9,165 / `ENDSELECT` 46,425 | ≈ 28 万行 | 第二优先级 |
| 变量插值 | `%…%` 命中 237,502 行；`{…}` 3,447 行；`\@…\@` 15,458 行 | — | 第三优先级 |
| 调用 | `CALL` 135,478 / `RETURN` 206,836 / `TRYCALLFORM` 835 | — | 逃生舱即可 |
| 演出 | `SETCOLOR` 22,488 / `RESETCOLOR` 6,312 / `CALL HPH_PRINT` 68,062 | — | 轻量糖 |
| 交互 | `INPUT` 1,188 / `INPUTS` 74 / `PRINTBUTTON` 264 / `GOTO` 2,167 | — | 表单化即可 |
| **循环** | `FOR` 420 / `WHILE` 44 / `REPEAT` 36（≈ 0.02%） | ≈ 0.02% | **不做糖**（详见 §7） |

结论：**"输出 + 条件 + 选择 + 插值"覆盖 90% 以上书写量；循环、TRY/CATCH（24 处）等不是口上作者的日常**。糖必须只在这四项上做到极致，其余交给逃生舱。

### 1.2 等待与续行：真 50/50

`PRINTFORM*W`（等待玩家）与 `PRINTFORM*L`（不等待）的总量比约为 **49 : 51**；按文件统计（输出行 ≥ 20 的 1,830 个文件）：全部等待的文件 475 个（26%），全部不等待的 119 个，其余散布各档。

结论：**不存在能同时服务两种风格的默认值，必须有一个极轻的行级标记**。本设计取"默认等待 + `续` 标记不等待"（理由见 §7.1）。

### 1.3 「」引号 = 台词 = 作者色：99% 相关律

交叉统计（行首指令 × 文本是否以引号 `「`/`｢` 开头）：

| 指令 | 无引号 | 有引号 |
| --- | --- | --- |
| `PRINTFORMW`（作者色·等待） | 108,792 | 212,208 |
| `PRINTFORML`（作者色·续行） | 105,532 | 241,298 |
| `PRINTFORMDW`（默认色·等待） | 159,299 | **1,109** |
| `PRINTFORMDL`（默认色·续行） | 135,518 | **1,622** |
| `PRINTFORMD`（默认色·不换行） | 1,739 | **14** |

即：
- **带引号的行里，99.4% 不使用 `D`（不忽略作者色）**；
- **使用 `D` 的行里，99.1% 不带引号**。

样本验证（小伞 K40 指令口上）：全部 `「…」` 台词用 `PRINTFORMW`（角色色），全部动作/心理描写用 `PRINTFORMDW/DL`（默认色）。

结论：**"有引号 = 台词 = 作者色；无引号 = 旁白 = 默认色"是社区自己已经在用的心智模型**，糖把它显式化（可整体关掉，见 §3.1 `旁白色`）。

### 1.4 函数命名：家族名带前导下划线（被实证的坑）

分发器模板（`KOJO_MESSAGE.ERB` 逐行核实）：

```
TRYCALLFORM M_KOJO%KOJO_NAME%_MESSAGE_%LOCALS%_K{NO:TARGET}_{LOCAL}     ; 主体
TRYCALLFORM M_KOJO%KOJO_NAME%_MESSAGE_MESSAGECHECK_%LOCALS%_K{NO:TARGET}_{LOCAL}
TRYCALLFORM M_KOJO%KOJO_NAME%_COLOR_K{NO:TARGET}
```

而 `KOJO_NAME` 来自 `KOJO_ACTIVE_INFO` 调用的登记函数 `@M_KOJO_K{No}`（`COMMON_KOJO.ERB:14`）：

```
@KOJO_ACTIVE_INFO(ARG)
RESULTS =
IF CFLAG:ARG:口上セレクタ
    TRYCALLFORM M_KOJO_K{NO:ARG}_{CFLAG:ARG:口上セレクタ}
ELSE
    TRYCALLFORM M_KOJO_K{NO:ARG}
ENDIF
```

真实语料证实两件事：

1. **标准版**：`RESULTS` 保持为空 → 函数名形如 `@M_KOJO_MESSAGE_COM_K12_310`、`@M_KOJO_COLOR_K12`（露米娅）。
2. **别人版**：作者在登记函数里写 `RESULTS = _破空自制`（**前导下划线是名字的一部分**）→ 函数名 `@M_KOJO_破空自制_MESSAGE_COM_K14_100`（琪露诺 AA 版）。

即：**漏写或错写下划线 = 满屏口上"全哑"却零报错**。这是糖收益最大的一处：`口上: 破空自制` 一行声明，工具负责拼装全部函数名。

### 1.5 生态的其他三个高发失败点

| 失败点 | 原生写法 | 糖的处置 |
| --- | --- | --- |
| 概率不均 | `IF RAND:3 == 0` / `== 1` 连写（同一随机数被多次比较） | `随机：` 块编译为 `LOCAL = RAND:n` + `SELECTCASE`（严格等概率） |
| 按钮参数顺序 | `PRINTBUTTON "文本", "值"` + 手工 `INPUTS` + `SELECTCASE RESULTS` 手抄值 | `选项：` 块自动分配返回值 |
| 配色漏配 | `SETCOLOR` / `RESETCOLOR` 手工配对（22,488 / 6,312，明显不成对） | `着色 …：` 块自动成对；时机级颜色由 `口上色:` 生成 `COLOR` 函数 |

（另：分发器在 37 个调用面的返回路径上都有 `RESETCOLOR`（源码实测 37 处），所以作者**不需要**在时机末尾手工恢复颜色——糖不再生成多余的 `RESETCOLOR`。该覆盖性待实测确认，见 §9 第 5 条。）

## 2. 设计原则

1. **中文表层，Kotlin/C# 结构内核**。有价值的是`插值 / when / 命名参数 / 扩展属性 / 范围与集合`这五种**结构**，不是英文词汇。结构全部保留，词汇用中文表达。
2. **英文关键字是隐藏别名**。`if / when / else / cont` 等输入即生效，但补全面板默认只显示中文；不允许中英在视觉上对等展示。
3. **糖要"薄"**。每一条糖都有唯一、可读、可手写的 1:1 转译规则（§5）；转译产物与社区手写风格一致，作者随时能"毕业"回原生 ERB。
4. **克制**。只借五种结构（对照 §2.1），不引入类型系统、泛型、协程、闭包、lambda、数据结构——口上作者不需要接触它们。
5. **读出来像人话**。关键字标准是"读起来像剧本"：`如果 / 否则 / 当 / 是 / 续 / 心形 / 选项`。读起来别扭的词不进入关键字表（例如第一人称 `我` 因歧义被排除，见 §7.2）。
6. **逃生舱永远存在**。任何原生 ERB 行都能原样直通（§3.10），所以糖的覆盖面永远不会成为瓶颈，也不会绑架资深作者。

### 2.1 五种结构的中文落点

| Kotlin/C# 的结构 | 糖中的落点 | 不借什么 |
| --- | --- | --- |
| 字符串插值 | `{…}`；行内条件 `{条件 ? A : B}` | 不做格式化说明符、不做 raw string |
| `when` / 模式分派 | `当 表达式：` + `是 值：` + `否则：`；`如果/否则如果/否则`；**含赋值位置的表达式形态**（`目标 = 当 …：是 v -> 值`，§3.5/§3.6） | 不做守卫子句链、不做解构 |
| 命名参数 | `时机 指令 311 成否: 游戏判定：`、`「标签」 返回: "x"` | 不做可选参数默认值机制 |
| 扩展属性 / 扩展函数 | 代词扩展：`她的恋慕` → `TALENT:TARGET:恋慕`；引擎函数中文别名：`心形` → `HPH_PRINT`；**`别名`**（作者私有变量名 / 角色引用，§3.8） | 不做用户自定义扩展**函数/属性**（`别名` 只是名字映射，不含扩展体）、不做链式调用 |
| 范围 / 集合字面量 | `是 0 到 99：` → `CASE 0 TO 99`；`随机 甲, 乙, 丙` | 不做列表/映射数据结构（口上不需要） |

## 3. 语法规范

### 3.1 文件结构与头部声明

一个 `.kojo` 源文件 = 若干"时机"块 + 文件头部声明。头部（front-matter）由编辑器的"新建向导"生成，作者几乎不用手写。

```
; 露米娅 · 摸屁股（310）
角色: 12                    ; 必填：角色编号（用于 K{No} 与 CFLAG:{No}）
口上: 破空自制               ; 选填：别人版家族名。省略 = 标准版（RESULTS 保持为空）
显示名: 的AA琪露诺版          ; 选填：RESULTS:1（口上选择列表里的显示名）
简介: 国人自制<br>…          ; 选填：RESULTS:2（列表里的简介）
口上色: 0xE4FC08            ; 选填：生成 @M_KOJO_COLOR_K{No} 的 SETCOLOR
旁白色: 默认                ; 选填：默认 = 旁白用 D 系；作者色 = 旁白也用角色色
开关:                       ; 选填：生成 @M_KOJO_FLAGSETTING_K{No}
    眠姦口上有: 是
    時間停止口上有: 否

别名 今天已触发 = CFLAG:TARGET:1088   ; 变量别名：正文里 `今天已触发` 的读与写都解析到它
别名 上次见面日 = TCVAR:TARGET:20     ; 变量别名（任意变量族，不限于 CFLAG）
别名 朋友 = 角色 15                   ; 角色别名：`{朋友}` → %CALLNAME:15%
别名 冷淡 = 0                          ; 字面量别名（只读）：正文里 `冷淡` 即常量 0
别名 昵称 = "小露"                     ; 字面量别名（只读）：字符串字面量
```

`别名` 的**四种右值形式**：

| 形式 | 例 | 读写性 |
| --- | --- | --- |
| 变量引用 | `别名 X = CFLAG:TARGET:1088` | **可读可写**（`X = 1` 合法，转译为 `CFLAG:TARGET:1088 = 1`） |
| 角色引用 | `别名 X = 角色 15` | 仅可读（`{X}` → `%CALLNAME:15%`；不可作赋值左值） |
| 数值字面量 | `别名 X = 0` | **只读**（转译中直接展开为 `0`；`X = 1` 会展开成 `0 = 1`，故编辑器**报编译错误**） |
| 字符串字面量 | `别名 X = "冷淡"` | **只读**（同上） |

- **字面量别名（后两种）是只读的**：它们只在**表达式位置**（含 `当`/`如果` 的分支值、条件右值、插值内容）展开为字面量；一旦出现在**赋值左值**位置，编辑器报错（"只读别名不能赋值"）。这是"用具名常量（`别名 冷淡 = 0`）"能成立的前提，也堵住了 `0 = 1` 这类无意义产物。

规则：
- 以上声明共同生成"登记函数 + 颜色函数 + 开关函数"三件套，作者不再手抄 `@M_KOJO_K12` 之类。
- `口上:` 的值**必须写不带下划线的人名**（如 `破空自制`），工具负责补前导下划线；这是 §1.4 那个坑的根治点。
- 未声明的可选项，工具不生成对应函数（引擎侧自然回退：无色则用默认色，无开关函数则按默认关处理）。
- **`别名` 三约束**（详见 §3.8）：① 只能出现在文件头（所有 `时机` 块之前）；② 不得与保留代词 `她`/`你` 同名、不得重名；③ 只在当前文件生效，不跨文件。另：**字面量别名与角色别名只读**，不得作赋值左值（见上表）。

### 3.3 输出：一行文本就是一行文本

**核心规则表**（这是全部设计里最重要的一张表）：

| 作者写 | 判定 | 编译产物 | 说明 |
| --- | --- | --- | --- |
| `「今天也来训练了？」` | 有引号 → 台词；无 `续` → 等待 | `PRINTFORMW 　「今天也来训练了？」` | 角色色（不忽略 SETCOLOR） |
| `她点了点头。` | 无引号 → 旁白；无 `续` → 等待 | `PRINTFORMDW 她点了点头。` | 默认色 |
| `「……」 续` | 台词 + 不等待 | `PRINTFORML 「……」` | 续行 |
| `她叹了口气。 续` | 旁白 + 不等待 | `PRINTFORMDL 她叹了口气。` | 续行 |
| `空行` | 整行恰为该词（隐藏别名 `blank`）→ 输出空行 | `PRINTFORMDW`（**无尾随空格**） | **v1.4 新增**：打空行的显式写法。旁白系（与"无引号 → 旁白"同一条规则） |
| `空行 续` | 空行 + 不等待 | `PRINTFORMDL` | 标记仍走 `CONT_MARKS` 那一组（`续`/`~`/`⏎`/`cont`/`continue`），自造说法不认 |
| `{她的恋慕 ? "她的耳朵红了。" : ""}` | 行内**只有**这一个条件插值，且假分支为空 → 走"纯条件行"规则 | `IF TALENT:TARGET:恋慕` / `PRINTFORMDW 她的耳朵红了。` / `ENDIF` | 条件旁白（不产生空行，见下） |

补充规则：

- **引号**：`「」` 与 `｢｣` 均可输入，产物统一为 `「」` 风格的原文照抄。引号内部是文本，不做任何转义（除 `%` 见 §5.2）。
- **`续`（不等待）**：行尾标记，必须写在引号/句号之外。中文主形 `续`；隐藏别名 `~`、`⏎`、`cont`、`continue`。等价于 ERB 的 `L` 后缀（换行但不等待）。
- **纯条件行**（假分支为空 → 编译为 `IF` 块）。判定条件是**整行除空白与注释外，只含一个条件插值**，且**假分支为空或省略**：

  ```
  {她的恋慕 ? "她的耳朵红了。" : ""}
  ```

  直接落成 `\@…?…\@` 会在条件为假时输出**空字符串**，而 `W` 后缀无条件换行 + 等待——玩家会看到"莫名其妙停一下"。故此类整行条件一律编译为块：

  ```
  IF TALENT:TARGET:恋慕
      PRINTFORMDW 她的耳朵红了。
  ENDIF
  ```

  边界（**只处理"整行"**）：条件插值混在其它文本里（如 `「嗯…{她的恋慕 ? "脸红" : ""}」`）**不适用**本规则——它无法变成块，仍走行内 `\@…\@`（此时假分支为空是安全的：整行仍有其它文本，不存在空行等待）。作者如需让"整行条件"出现两种文本，写 `{条件 ? "A" : "B"}`（两侧非空）也可，产物为行内 `\@条件?A#B\@`。
- **能力边界：糖没有"不换行"标记**。EraBasic 的 `N` 后缀（以及完全不写 `L/W` 后缀，如 `PRINTFORM` 5,997 行、`PRINTFORMD` 1,754 行）表示"输出后既不换行也不等待"，用于**把一句话分成多段拼出来**：
  ```
  PRINTFORMD 灵梦
      IF TALENT:恋人
          PRINTFORMD 带着温柔的笑容
      ENDIF
      PRINTFORMDW 看着%CALLNAME:MASTER%。      ; → "灵梦带着温柔的笑容看着你。"
  ```
  糖**不提供**等价标记，理由是"拼句"在口上里应写成一行、用行内条件分段：
  ```
  灵梦{她的恋人 ? "带着温柔的笑容" : ""}看着{你}。
  ```
  **无法改写成一行**的用法（表格/状态面板逐格排版、一行内逐段 `SETCOLOR` 切色）走**原生直通**（§3.10）。覆盖率的实测见 §9。
- **`RESETCOLOR`（待实测）**：分发器在每个调用面的返回路径上都有 `RESETCOLOR`（`KOJO_MESSAGE.ERB` 实测 37 处，与 37 种调用面一一对应），故糖**不生成**时机末尾的多余 `RESETCOLOR`；但该文件内 `RETURN` 共 80 处，是否存在跳过 `RESETCOLOR` 的提前返回路径需实机确认（见 §9）。`着色` 块内部的自配对 `RESETCOLOR`（§3.9）不受此影响。
- **文本里的 `%`**：作者写"耐久度 50%"这类文本时，半角落单 `%` 由编辑器按引擎规则转义（FORM 字符串里 `%…%` 是变量记号）；编辑器同时在行内高亮落单 `%`，防止作者误写出 `%变量%` 却忘了收尾。

### 3.4 插值：统一 `{…}`

原生的三套记号（`%字符串%`、`{数值}`、`\@条件?A#B\@`）在糖里统一为 `{…}`：

```
「{她}，今天也来训练了？」
「好感度是{她的好感度}。」
「{她的恋慕 ? "只有你，我不讨厌。" : "别靠太近。"}」
```

转译规则（"编辑器根据内容自动选择"）：

| 糖 | 内容类别 | 产物 |
| --- | --- | --- |
| `{她的好感度}` | 数值表达式 | `{CFLAG:TARGET:好感度}` |
| `{她}` / `{你}` | 字符串值 | `%CALLNAME:TARGET%` / `%CALLNAME:MASTER%` |
| `{条件 ? "A" : "B"}` | 行内条件（C# 风格三元） | `\@条件?A#B\@` |
| `{条件 ? "A"}` | 省略假分支 | `\@条件?A\@` |

- 分类由 L0 知识数据包完成（变量名 → 变量族与类型）：命中字符串族（`CALLNAME` 等）走 `%…%`，命中数值族（`CFLAG/TALENT/ABL/EXP/MARK/BASE/PALAM/TEQUIP/TCVAR/FLAG/TFLAG`）走 `{…}`；两者在 FORM 字符串里语义等价，作者不需要知道区别。
- 行内条件的分支是 FORM 片段：字面量原样、变量引用按上一行规则降糖后嵌入（与真实语料中 `\@…?%CALLNAME:MASTER%#…\@` 的写法一致）。
- 嵌套插值不出现（`{…}` 内不再写 `{}`），需要嵌套时用行内条件的分支表达。

### 3.5 条件：`如果 / 否则如果 / 否则`

```
如果 她的恋慕：
    「……只有你，我不讨厌。」
否则如果 她的思慕：
    「别、别靠太近。」
否则：
    「……」
```

- **缩进即块**，编辑器自动补 `ENDIF`（原著中 `IF` 205,276 与 `ENDIF` 205,268 差 8 个——这 8 个未闭合就是"口上全哑"的隐性来源，糖从语法上消灭它）。
- **单行形式**：块头行尾直接跟内容
  ```
  如果 FLAG:70： 「（……这是……）」
  ```
  编译为 `IF … / 内容 / ENDIF` 三行（**故意不用 `SIF`**：`SIF` 只能管一行，是后续维护的陷阱；糖产物统一块结构）。
- 英文别名：`if` / `elif`、`elseif` / `else`。
- 条件表达式里可直接使用原生 ERB 变量与运算符；中文运算符为糖（见 §4 对照表），两者可混写。

**`如果` 作为表达式**（赋值位置）：`如果` 不仅能作语句块，也能出现在**赋值右侧**，把分支结果直接赋给目标变量——这是 Kotlin 允许 `if` 作表达式的核心结构，本糖保留：

```
她的心情 = 如果 她的好感度 >= 500：
    "热情"
否则：
    "冷淡"
```

- 编译为对**左值**赋值的 `IF` 块（左值 = 赋值号前的目标变量；各分支体写成 `左值 = 分支值`）：

  ```
  IF CFLAG:TARGET:好感度 >= 500
      CFLAG:TARGET:1088 = "热情"
  ELSE
      CFLAG:TARGET:1088 = "冷淡"
  ENDIF
  ```

- **表达式位置的 `如果` 必须有 `否则` 分支**——否则左值存在"未赋值路径"，与 Kotlin 要求 `if` 表达式穷尽的理由一致。编辑器把"缺 `否则`"报为**编译错误**。
- 识别规则：行首是**目标变量 + `=`**、且赋值号右侧以 `如果` 开头、行尾是全角 `：` → 按表达式 `如果` 处理；普通语句块的 `如果 条件：` 不受影响（二者靠"是否在赋值右侧"区分，无歧义）。
- **只允许出现在赋值位置**，不允许写进插值 `{…}`（原因见 §3.6 末的边界说明）。

**`不在`（范围取反）**：`是 … 到 …` 的否定写法，让否定条件读起来像自然语言：

```
如果 她的好感度 不在 0 到 99：
    她皱了皱眉。
```

→ `IF !(CFLAG:TARGET:好感度 >= 0 && CFLAG:TARGET:好感度 <= 99)`

- 英文别名：`notin`。转译规则固定为 `X 不在 a 到 b` → `!(X >= a && X <= b)`（取反形式），**不要**转成 `X < a || X > b`。
- **为什么选 `!(...)` 而不是 `X < a || X > b`**：两者在 ERB 里对 `X` 的求值次数**相同**（`&&`/`||` 不短路，两种形式的两个子表达式都会求值），所以取舍理由是**语义直接映射**（"不在"就是"在"的取反，读/改都直观），而不是求值次数。
- **`X` 是复杂表达式时先赋临时变量**（这是真正消除重复求值的手段，对两种形式同样必要）：

  ```
  LOCAL = 她的好感度
  如果 LOCAL 不在 0 到 99：
  ```

  → `LOCAL = CFLAG:TARGET:好感度` + `IF !(LOCAL >= 0 && LOCAL <= 99)`。糖不做自动转写（避免擅自引入临时变量），仅在 `X` 含 `+`/`-`/函数调用时由 lint 给出提示。
- 与之配对的 `直到`（排他上界）**本期不加**——`CASE a TO b-1` 在 `b` 是变量/表达式时需要额外括号处理（否则可能被解析为 `(a TO b) - 1`，语义完全不同），脆弱；理由与转译规则记于 §7.2。

### 3.6 选择：`当 / 是 / 到 / 否则`（Kotlin `when` 的中文形态）

```
当 TFLAG:193：
    是 1：
        「不、不要……！」
    是 2, 3：
        她红着脸，小声嘟囔着。 续
        「……就、就一下哦。」
    是 5 到 8：
        「呜……」
    否则：
        她什么也没说，只是微微眯起了眼睛。
```

- `当 表达式：` → `SELECTCASE 表达式`；`是 v：` → `CASE v`；`是 a 到 b：` → `CASE a TO b`；`是 a, b：` → `CASE a, b`；`否则：` → `CASEELSE`；块结束 → `ENDSELECT`。
- 英文别名：`when` / `is` / `to` / `else`。
- 值可以是数字、`「字符串」`（→ `CASE "…"`）。

**`当` 作为表达式**（赋值位置）：Kotlin 的 `when` 之所以优雅，核心不在分支语法，而在它是**表达式而非语句**——能出现在任何需要值的位置。本糖保留这一结构：`当` 出现在**赋值右侧**时，各分支用 `->` 直接给出该分支的值：

```
她的心情 = 当 她的好感度：
    是 0 到 99 -> 0
    是 100 到 499 -> 1
    否则 -> 2
```

- 编译为对**左值**赋值的 `SELECTCASE` 块（若左值是 §3.1 的 `别名`，先按 §5.0 展开）：

  ```
  SELECTCASE CFLAG:TARGET:好感度
      CASE 0 TO 99
          CFLAG:TARGET:1088 = 0
      CASE 100 TO 499
          CFLAG:TARGET:1088 = 1
      CASEELSE
          CFLAG:TARGET:1088 = 2
  ENDSELECT
  ```

- **表达式位置的 `当` 必须有 `否则` 分支**（Kotlin 的 `when` 表达式同样要求穷尽，这是它的安全保证——有 `否则` 才能保证左值在所有路径上都被赋值）。编辑器把"缺 `否则`"报为**编译错误**。
- 分支体是**单个表达式**（数字、`"字符串"`、变量引用），写成 `是 值 -> 表达式`；需要多语句时用上面的**语句块形态**（`是 值：` + 缩进），两种形态不混用。
- 识别规则：与表达式 `如果` 同——行首是"目标变量 + `=`"、右侧以 `当` 开头且行尾为全角 `：`。
- 值想写成具名常量（如以 `心形` 之类的词代指 `0`），先用 `别名` 起名（§3.8）；糖**不引入符号表 / 常量表 / 枚举**（见 §7.2）。

> **边界：插值 `{}` 内不可写 `当` / `如果`。** ERB 的行内条件 `\@…\@` **不支持嵌套**，插值里的多分支 `当` 无法转译。因此表达式 `当` / `如果` **只存在于赋值位置**。需要"在文本里按分支显示不同内容"时，用行内条件 `{条件 ? A : B}`（§3.4），或把它提成整行的"纯条件行"（§3.3）。这个边界是硬约束，实现者不要尝试在 `{…}` 内解析 `当`。

**随机块**（等概率，修掉 `RAND` 连写的概率坑）：

```
随机：
    「……呼。」
    「再、再摸摸嘛。」
```
→
```
LOCAL = RAND:2
SELECTCASE LOCAL
    CASE 0
        PRINTFORMW 「……呼。」
    CASE 1
        PRINTFORMW 「再、再摸摸嘛。」
ENDSELECT
```

行内简写（集合字面量形态，适合一句话的随机）：

```
随机 「嗯。」,「哦？」,「……」
```

随机块嵌套或同文件多次使用时，编译器为每块分配独立的 `LOCAL:N` 槽位，互不覆盖。

### 3.7 交互：`选项` 块

```
选项：
    「用亲吻代替回答」：
        「……唔。」
        心形 「虽然，还不太明白……但是、不讨厌。」
    「摸摸头」：
        「……好。」
    「什么也不做」：
        「……回去吧。」
```

编译为完整的菜单交互（顺序由工具保证，作者不再碰参数顺序）：

```
PRINTBUTTON "用亲吻代替回答", "1"
PRINTBUTTON "摸摸头", "2"
PRINTBUTTON "什么也不做", "3"
INPUTS
SELECTCASE RESULTS
    CASE "1"
        …
    CASE "2"
        …
    CASE "3"
        …
ENDSELECT
```

- 返回值由工具按书写顺序分配 `"1".."n"`；**v1 不提供手写返回值**（这正是消灭顺序/数值陷阱的设计），需要自定义值时用原生 ERB 直通。
- **每个时机只允许一个 `选项` 块，且不允许嵌套**。原因：`INPUTS` 把结果写进引擎约定的 `RESULTS`，两个 `INPUTS` 共用同一个变量，嵌套也解决不了冲突（内层选完 `RESULTS` 已被覆盖，外层分支无法再判断）。
- **多轮选择**（选完再选一轮）用原生直通写 `$标签` + `GOTO` 回跳，或拆成两个时机。这是 v1 的明确边界，不是缺陷。
- 英文别名：`choice:`；条目内可写任意语句（可含 `如果`/`当`/`随机`/`着色` 等其它块，但**不含** `选项` 块）。
- 原生 `PRINTBUTTON` 的字符串返回值语义（语料实测为 `"0"`、`"1"` 等字符串，配合 `INPUTS`/`RESULTS`）在产物中被完整保留。

### 3.8 变量引用：代词与属性访问（扩展属性）

| 糖 | 产物 | 说明 |
| --- | --- | --- |
| `{她}` | `%CALLNAME:TARGET%` | 口上主显示名；**只在插值内生效**（分发器已把 `TARGET` 指向发言人） |
| `{你}` | `%CALLNAME:MASTER%` | 玩家显示名（同上） |
| `{她的恋慕}` | `{TALENT:TARGET:恋慕}` | 变量名由 L0 数据包解析到所属族（数值族 → `{}`，字符串族 → `%%`） |
| `{她的诶嘿嘿}` | `{CFLAG:TARGET:诶嘿嘿}` | 同上（含中文变量名，与游戏 CSV 一致） |
| `{她的名字}` | `%CALLNAME:TARGET%` | **v1.3**：`CALLNAME` 以角色号为索引，没有"名字的索引"；与 `{她}` 同产物，两者都可用 |
| `{角色12的名字}` | `%CALLNAME:12%` | 引用**其它角色**的显示名（编辑器按角色编号补全，免手写数字） |
| `角色12的好感度` | `CFLAG:12:好感度` | **v1.3 新增**：其它角色的属性引用（表达式与插值内均可，插值里写作 `{角色12的好感度}`） |
| 正文裸文本（含"她""你"） | 原样 | 不做替换；代词必须写进 `{}` 才生效（见下） |

- 只引入**无歧义**的代词。第一人称 `我` **不提供**：在台词里指角色、在旁白里指玩家，歧义无法消解。
- **`角色<数字>的<属性名>` 的三条边界（v1.3，用户 2026-10-12 拍板扩写）**：
  - **数字必须是字面角色号**（`角色12的…`）。`角色X的…`（X 是变量）**不提供**——动态角色作用域
    糖里没有承诺写法，作者写不出、读者也认不出是谁；引擎的 `ARG` / `LOCAL` 作用域同理（要引用
    就用 `别名` 声明，§3.1）。
  - 属性名仍走 L0 查表：查不到名字 → 报 `unknown-identifier`（不静默造名）。
  - 全局族不适用：`FLAG` / `TFLAG` / `GLOBAL` 是**全局**变量，没有"某角色的 FLAG"。
  - 为什么值得加：真实语料里三段式引用的 **33.6%** 是数字角色号作用面（实测 108,968 次引用中
    36,601 次），此前糖一律无能为力——`CFLAG:1:好感度` 只能留着给读者看。
  - **反向（糖视图投影）同源**：`CFLAG:13:好感度` 显示为 `角色13的好感度`；`CALLNAME:13` 显示为
    `角色13的名字`；`CFLAG:PLAYER:x` 显示为 `你的x`（`PLAYER` 是 `MASTER` 的引擎别名，不新造代词）。
- **`她` / `你` 只在插值 `{…}` 内生效，且是"口上主 / 玩家"的专用代词**，不承担"任意女性第三人称"。正文裸文本里的"她"**不做任何替换**，因此"她的母亲""她朋友"这类写法天然安全（不会被误拼成 `%CALLNAME:TARGET%母亲`）。需要显式引用时：
  - 引用**口上主 / 玩家**：`{她}` → `%CALLNAME:TARGET%`、`{你}` → `%CALLNAME:MASTER%`。
  - 引用**其它角色**：`{角色12的名字}` → `%CALLNAME:12%`（编辑器按角色编号补全，免手写数字）；或原生 `%CALLNAME:12%`。
  - 引用**没有引擎变量的关系词**（母亲、朋友、故乡…）：直接写中文，糖不臆造映射。
- 变量族命中不唯一时（个别名字在多个族里存在），编辑器弹出选择并把解析结果记入文件（可复查），不静默猜测。
- **`别名` 声明（§3.1）**：`她的X` 走 L0 数据包查表（已注册的中文/日文变量名）；作者**自定义的私有变量名**与**常用角色引用**走文件头 `别名` 声明。两者关系如下：
  - `别名 X = CFLAG:TARGET:1088`（变量别名）→ 正文里 `X` 的**读与写**都解析到 `CFLAG:TARGET:1088`：`如果 X：`、`X = 1` 均可，转译见 §5.0。
  - `别名 X = 角色 N`（角色别名）→ 插值里 `{X}` 编译为 `%CALLNAME:N%`。它与本节上方的 `{角色N的名字}` 是**同一能力的两种粒度**：一次性引用用 `{角色N的名字}`，反复引用用 `别名`。
  - `别名 X = 0` / `别名 X = "冷淡"`（**字面量别名，只读**）→ 正文里 `X` 在**表达式位置**直接展开为字面量。这是"想用具名常量就先用 `别名`"能成立的前提（它替代被 §7.2 排除的枚举/常量表）；因只读，`X = 1` 会被编辑器报错（否则展开成 `0 = 1`）。
  - **`别名` 优先于 L0 查表**：同名冲突时，作者显式声明覆盖默认解析。
  - 三条约束（§3.1）：① 只能在文件头（所有 `时机` 块之前）；② 不得与保留代词 `她`/`你` 同名、不得重名；③ 只在当前文件生效，不跨文件。
  - **为什么用 `别名` 而不是 `旗标`**：`旗标` 只服务 `CFLAG` 一族，而 `别名` 是通用机制，同时覆盖 `CFLAG`/`TCVAR`/`TALENT` 等任意变量族（与 Kotlin 的 `typealias`、C# 的 `using` 别名同构），作者只需记一个关键字。

### 3.10 注释、折行、原生直通

| 形态 | 规则 |
| --- | --- |
| 注释 | `;` 起至行尾（与 ERB 一致，可写行内注释）；编辑器显示为灰色。**注释会原样保留到产物**（2026-10-12 修订，见文首）：文件头注释排在产物最前，体内注释随所在层级缩进 |
| 源折行 | 行尾 `\` 表示"物理折行、逻辑同一行"（工具合并后只生成一条 PRINT，防止长段落被误拆成多条输出） |
| 原生直通（行） | 行首（忽略缩进）是**全大写英文指令**（如 `SETCOLOR`、`IF`、`CALL`、`RAND`、`TFLAG:193 = 0`）或 `$标签` 时，整行原样透传到产物对应位置；编辑器以"源码色"（等宽/偏灰）显示，提示作者这是原生代码 |
| 原生直通（块） | 行首 `@` 开始一个**原生函数块**：从该行起直到下一个 `@` 行或文件末尾，**整块逐行原样透传**（块内不解析糖语法，可含 `#DIM`/`#FUNCTION` 等预处理行与任意中文文本）。用于写附录 C 中 v1 未覆盖的入口（如 `@M_KOJO{t}_IRAI_K{n}`）或自定义工具函数 |
| 空行 | 源文件里的空白行仅用于分隔，**不进入产物**（注释保留，空行不保留）。**要在游戏里打一行空行，写 `空行`**（v1.4，见 §3.3） |

直通的意义：**糖不是围栏**。任何原生 ERB 片段都可以嵌在时机正文里或写成独立的 `@` 函数块，包括 `FOR` 循环、`TRYCALLFORM`、菜单 `$标签` + `GOTO` 回跳等本期不做糖的写法，以及附录 C 里那 25 个尚未有糖形态的调用面。

## 5. 转译细则（算法化）

### 5.0 别名预处理（全局第 0 步，先于一切降糖）

在 §5.1 之前，先做一次**文件内别名替换扫描**：

```
0. 读文件头所有 `别名 X = 目标` 声明，建立 {X → 目标, 类别} 表：
   - `别名 X = CFLAG:TARGET:1088`  → 变量别名（读写皆替换为目标变量引用）
   - `别名 X = 角色 N`             → 角色别名（只读；插值里替换为 %CALLNAME:N%）
   - `别名 X = 0` / `= "冷淡"`      → 字面量别名（只读；表达式位置纯文本替换为字面量）
1. 逐个时机扫描正文：
   a) 裸标识符 X（词边界匹配，不进入字符串字面量与注释）出现在
      赋值左值、条件、表达式位置 → 替换为其目标
      - 变量别名：读写皆替换
      - 字面量 / 角色别名出现在**赋值左值** → 报错（只读，§3.1）
   b) 插值 `{X}` 内，若 X 是角色别名 → 替换为 `%CALLNAME:N%`
2. 未在别名表命中、且不在 L0 变量字典中的标识符 → 报错（§5.2）
```

- 字面量别名是**纯文本替换**：`是 0 到 99 -> 冷淡` 直接得到 `CFLAG:TARGET:1090 = 0`，不产生任何运行时开销。
- 别名替换**先于所有其它降糖**执行，因此别名与 `她的X`、原生变量写法可自由混用（替换后得到的就是普通变量引用，后续按常规规则处理）。
- 别名**不跨文件**：每个文件独立扫描、独立建表，工具不合并不同文件的别名。
- 别名与保留代词 `她`/`你` 重名、别名之间重名 → 在扫描前即报错（§3.8 三约束）。

### 5.1 PRINT 变体选择算法（更新的核心）

输入：一条糖文本行 → 输出：唯一确定的 `PRINT` 家族指令。

```
1. 取行尾标记：是否有 `续`（或别名）→ wait = false / true（默认 true）
2. 判定台词：去除插值后的首个非空白字符是否 `「`/`｢` → speech = true / false
3. 选色：d = (旁白色 == 默认) 且 (not speech)
4. 组装指令名：
     base = "PRINTFORM"
     后缀 = (d ? "D" : "") + (wait ? "W" : "L")
     即：PRINTFORMW / PRINTFORML / PRINTFORMDW / PRINTFORMDL
5. 文本体转译（§5.2），缩进按产物规则归一为 TAB
```

边界：

- 原文行以**行内条件开头**（`{条件 ? …}`）但**后面还有其它文本**时，也走第 2 步——无引号即旁白。若整行只有这一个条件插值，则先由 §5.2 第 0 步拦下、编译为 `IF` 块。若作者需要"条件台词"，把条件写进引号内：`「{条件 ? "…" : "…"}」`。
- 若整行只含空白或只有注释，不产出任何指令。
- 与真实语料的对应关系：`PRINTFORMW`（台词 64% / 旁白 36%）、`PRINTFORMDW`（旁白 99.3%）——算法产物与社区习惯一致。

### 5.2 插值与文本体转译

**前置判定（在 §5.1 之前执行）——"纯条件行"**：

```
0. 整行除空白与注释外，是否恰好只含一个 `{条件 ? X : ""}`（或 `{条件 ? X}`）？
     是 → 不生成 PRINT 行，改生成块：
            IF 条件
                PRINTFORMDW X        ; 旁白；若 X 是 `「…」` 则用 PRINTFORMW
            ENDIF
          行尾 `续` 时，块内指令改用 L 后缀（PRINTFORMDL / PRINTFORML）
     否 → 进入 §5.1 的常规流程
```

理由见 §3.3：空假分支 + `W` 会产生"空行 + 无用等待"。**只处理"整行"**，混在文本中的条件插值仍走下面的行内规则。

**常规文本体转译**：

```
逐字符扫描文本体：
  `{` … `}`：
      解析内容：
        a) 含顶层 `?` 与 `:` → 行内条件 → `\@条件?真值片段#假值片段\@`（假值为空则省略 `#` 段）
        b) 命中字符串族变量 → `%表达式%`
        c) 否则（数值表达式）→ `{表达式}`
  `%`（半角，落单）：
      按引擎 FORM 规则转义，并在编辑器内高亮告警
  其他字符：原样（保留全角标点、空格、`「」`）
```

- 表达式内部先做糖降糖：代词（`她`/`你`）、属性（`她的X`）、中文运算符 → ERB 表达式；不识别的标识符一律报错（不是"原样输出"），因为口上里绝大多数拼写错误会表现为"口上静默失效"。
- `{…}` 内容的类别判定来自 L0 数据包（变量族 + 类型）；判定失败时编辑器给"消歧弹窗"，不做静默猜测。

### 5.3 块与缩进的配对

- 块头以全角冒号 `：` 结尾；块体缩进必须比块头深（编辑器自动维护缩进）。
- `如果/否则如果/否则` → `IF/ELSEIF/ELSE/ENDIF`；`当/是/否则` → `SELECTCASE/CASE/CASEELSE/ENDSELECT`；`随机`/`选项`/`着色` 各自成块。
- 缩进异常（回缩不齐、块头无体）→ 编辑器报错并阻止编译，**不生成半成品 ERB**。
- 产物缩进统一为 TAB，与语料一致（缩进只影响可读性，不影响引擎）。

### 5.4 槽位分配

| 糖 | 分配的临时变量 | 冲突处理 |
| --- | --- | --- |
| `随机` 块 | `LOCAL:N`（N 从 0 起） | 每个块独占槽位；嵌套时深层递增 |
| `选项` 块 | `RESULTS`（引擎约定） | **一个时机内最多一个 `选项` 块，且不可嵌套**（两个 `INPUTS` 争用同一 `RESULTS`；多轮选择走原生 `$标签` + `GOTO`） |

### 5.5 命名生成

**完整拼接公式**（严格复刻分发器 `KOJO_MESSAGE.ERB`，不使用缩写模板）：

```
家族段 = ""                 ; 标准版：`口上:` 省略
家族段 = "_" + 口上名        ; 别人版：`口上: 破空自制` → 家族段 = "_破空自制"

函数名 = "M_KOJO" + 家族段 + "_" + 分野段 + "_K" + 角色号 + [ "_" + 编号 ]
```

- **`M_KOJO` 与 `分野段` 之间那一个下划线由公式提供**，不由 `家族段` 提供。故标准版是 `M_KOJO_MESSAGE_COM_K12_310`（`M_KOJO` 后仅一个下划线），**不是** `M_KOJO__MESSAGE_COM_…`；别人版是 `M_KOJO_破空自制_MESSAGE_COM_K12_310`。
- 依据（源码原文）：`TRYCALLFORM M_KOJO%KOJO_NAME%_MESSAGE_%LOCALS%_K{NO:TARGET}_{LOCAL}`（`KOJO_MESSAGE.ERB:227` 一带）；`TRYCALLFORM M_KOJO%RESULTS%_SUCCESS_%LOCALS%_K{NO:TARGET}_{LOCAL}`（`:640`）。同一文件里两个变量 `%KOJO_NAME%` 与 `%RESULTS%` 并存，取值同为登记函数写入的家族段（`KOJO_MESSAGE.ERB` 内有 `KOJO_NAME '= RESULTS` 的赋值），实现时以**登记函数 `RESULTS` 的内容**为唯一真源。
- **分野段**取值如 `ENCOUNTER` / `MESSAGE_COM` / `MESSAGE_SCOM` / `EVENT` / `SPEVENT` / `SUCCESS_COM` / `MESSAGE_PALAMCNG_B` / `DAILY_EVENT`；**编号**的有无与形态（`_{编号}` / `_{编号}_{部位}` / 无）随分野而定。完整 37 种见 **附录 C**。

登记 / 配色 / 开关三件套（**不带家族段**，只有 `K{角色号}`）：

```
@M_KOJO_K{角色号}                ; 登记函数：RESULTS = 家族段；RESULTS:1 = 显示名；RESULTS:2 = 简介
@M_KOJO_FLAGSETTING_K{角色号}    ; 开关函数（写了 `开关:` 时生成）
@M_KOJO_COLOR_K{角色号}          ; 配色函数（写了 `口上色:` 时生成）
```

主体两函数模式（承接 §1.4 实证）：

```
@M_KOJO…_{编号}       ; 包装：CALL @M_KOJO…_{编号}_1 → RETURN RESULT
@M_KOJO…_{编号}_1     ; 正文：記入チェック（LOCAL = 0/1）+ 内容 + RETURN 1
```

每个 `时机` 生成的内容：

1. 成否判定函数（`成否:` 非 `游戏判定` 时才生成非默认值；默认也生成，保持结构一致）；
2. （可选）MESSAGECHECK 函数（写了 `隐藏情景/隐藏口上` 时）；
3. 主体包装函数 + `_1` 正文函数。`_1` 开头的 `LOCAL = 1`（記入チェック）在时机**尚无正文**时写 `0`，保留社区"占位"习惯（返回 `1`，静默而不触发 `_00` 兜底）。

### 6.1 例一：露米娅 · 摸屁股（310）

**`.kojo` 源文件**

```
; 露米娅 · 摸屁股（310）—— 反应三态
角色: 12
口上色: 0xE4FC08

时机 指令 310 成否: 游戏判定：
    「呀……！」
    露米娅猛地一缩，随后慢慢转过身来。 续
    {她的胆怯 ? "眼眶里浮起一点泪光。" : ""}

    当 TFLAG:193：
        是 1：
            「不、不要……！」
            「突然这样，太狡猾了啦……」
        是 2, 3：
            「呜……真是的。」
            她红着脸，小声嘟囔着。 续
            「……就、就一下哦。」
        否则：
            她什么也没说，只是微微眯起了眼睛。
```

**编译产物（`M_KOJO_K12_指令.ERB`）**

```
; 露米娅 · 摸屁股（310）—— 反应三态

@M_KOJO_SUCCESS_COM_K12_310
TFLAG:192 = 0

@M_KOJO_MESSAGE_COM_K12_310
CALL M_KOJO_MESSAGE_COM_K12_310_1
RETURN RESULT

@M_KOJO_MESSAGE_COM_K12_310_1
;-------------------------------------------------
;記入チェック（=0, 非表示、1, 表示）
LOCAL = 1
;-------------------------------------------------
IF LOCAL
	PRINTFORMW 「呀……！」
	PRINTFORMDL 露米娅猛地一缩，随后慢慢转过身来。
	IF TALENT:TARGET:胆怯
		PRINTFORMDW 眼眶里浮起一点泪光。
	ENDIF
	SELECTCASE TFLAG:193
		CASE 1
			PRINTFORMW 「不、不要……！」
			PRINTFORMW 「突然这样，太狡猾了啦……」
		CASE 2, 3
			PRINTFORMW 「呜……真是的。」
			PRINTFORMDL 她红着脸，小声嘟囔着。
			PRINTFORMW 「……就、就一下哦。」
		CASEELSE
			PRINTFORMDW 她什么也没说，只是微微眯起了眼睛。
	ENDSELECT
ENDIF
RETURN 1

@M_KOJO_COLOR_K12
SETCOLOR 0xE4FC08
```

（`@M_KOJO_K12` 登记函数由文件头生成：`口上:` 为空时 `RESULTS` 保持空串，别人版时写 `RESULTS = _破空自制`。关闭"口上色"开关时 `COLOR` 函数不生成。）

### 6.3 例三：`别名` + 表达式 `当`

演示 v1.2 新增的 `别名`（变量别名 + 角色别名）与赋值位置的表达式 `当`。

**`.kojo`**

```
; 露米娅 · 摸屁股（310）—— 记账与心情分档
角色: 12
口上色: 0xE4FC08

别名 今天已触发 = CFLAG:TARGET:1088
别名 上次见面日 = TCVAR:TARGET:20
别名 心情       = CFLAG:TARGET:1090
别名 朋友       = 角色 15
别名 平静       = 0                    ; 字面量别名（只读）
别名 亲近       = 1                    ; 字面量别名（只读）
别名 热情       = 2                    ; 字面量别名（只读）

时机 指令 310：
    如果 今天已触发：
        「……今天已经够了。」
    否则：
        今天已触发 = 1
        上次见面日 = DAY
        「……好吧。」
        心情 = 当 她的好感度：
            是 0 到 99 -> 平静
            是 100 到 499 -> 亲近
            否则 -> 热情
        「{朋友}最近怎么样？」
```

**编译产物（摘录）**

```
	IF LOCAL
		IF CFLAG:TARGET:1088
			PRINTFORMW 「……今天已经够了。」
		ELSE
			CFLAG:TARGET:1088 = 1
			TCVAR:TARGET:20 = DAY
			PRINTFORMW 「……好吧。」
			SELECTCASE CFLAG:TARGET:好感度
				CASE 0 TO 99
					CFLAG:TARGET:1090 = 0
				CASE 100 TO 499
					CFLAG:TARGET:1090 = 1
				CASEELSE
					CFLAG:TARGET:1090 = 2
			ENDSELECT
			PRINTFORMW 「%CALLNAME:15%最近怎么样？」
		ENDIF
	ENDIF
```

- 变量别名 `今天已触发` / `上次见面日` / `心情` 的**读**（`如果 今天已触发：`）与**写**（`今天已触发 = 1`、`心情 = 当 …`）都解析到各自目标；解析发生在 §5.0 的预处理步，先于一切降糖。
- 字面量别名 `平静` / `亲近` / `热情` 在 `当` 的分支值位置**纯文本展开**为 `0` / `1` / `2`（产物与直接把裸值写在分支里完全一致）；它们是**只读**的，写 `平静 = 1` 会报编译错误。
- `{朋友}` → `%CALLNAME:15%`（角色别名）。
- 表达式 `当` 的 `否则` 分支是**必须**的（缺则编译错误）；`否则 -> 热情` 保证 `心情` 在所有路径上被赋值。

**验收用例**：编辑器实现后，§6.1 / §6.2 的产物必须逐字节等于上表（二者是 golden 契约）；§6.3 为示意用例，演示 v1.2 的 `别名` 与表达式 `当`。

## 7. 边界与取舍

### 7.1 为什么默认"等待"，而不是默认"续"

- 语料 W:L ≈ 49:51，两种风格几乎均势，任何默认值都会错一半；
- 取"等待"为默认的三条理由：**失败模式温和**（多一次点击 vs 内容被淹没）、与视觉小说"一句一停"的直觉一致、与社区入门模板的示例写法一致；
- 代价：习惯"一口气铺完"的作者要写更多 `续`。因此 `续` 必须**极短、可一键插入**（编辑器提供"本行不等待"快捷键，把标记插入/移除）。

### 7.2 被明确排除的设计（克制清单）

| 排除项 | 理由 |
| --- | --- |
| 第一人称代词 `我` | 台词中指角色、旁白中指玩家，歧义无法消解 |
| 循环（`循环：`/`跳出`/`继续`） | 语料占比 0.02%（FOR 420 / WHILE 44 / REPEAT 36）；菜单回跳用原生 `$标签` + `GOTO` 直通即可 |
| `SIF` 糖 | `SIF` 只能管一行是历史陷阱；糖产出一律块结构 |
| 类型系统 / 泛型 / 协程 / 闭包 / lambda | 与口上场景无关，纯认知负担 |
| Elvis 操作符 `?:` | ERB **没有 null 概念**；`?:` 只能退化为"值为 0/空则取默认"，与作者"未设置"的直觉错位（他们以为在查"未设置"，实际在查"值为 0"）。需要默认值时用 `如果` 块更清晰 |
| `返回` / 提前退出 | **不增加能力**（`如果 非 条件：` 包裹整块即等价），却引入一个新的控制流关键字；口上作者认知负担已够重 |
| `直到`（排他上界） | 转译需对边界**自动减一**（`是 a 直到 b` → `CASE a TO b-1`），边界是变量/表达式时脆弱。本期只采纳无算术风险的 `不在`（§3.5）；`直到` 记入 v2 候选（条件形态转译规则：`X 是 a 直到 b` → `X >= a && X < b`） |
| 多行字符串 `"""…"""` | 大段旁白直接写多行文本行即可；`"""` 只是换一种写法，不增加能力 |
| `with` / `apply` 作用域块 | 省略重复前缀，但引入嵌套作用域概念；口上很少连续修改同一角色的多个属性 |
| `let` / `also` / `run` | 口上无对应场景 |
| 数据结构（列表、映射） | 口上没有需求；`随机` 块已覆盖文本池场景 |
| `data class` / `record` / `sealed` / `enum` | 口上不需要数据结构；具名常量用**字面量别名**（`别名 冷淡 = 0`，只读，§3.1/§3.8）即可 |
| 安全调用 `?.` | ERB 无 null，链式访问也不常见 |
| `nameof` / `yield` / `async`-`await` / LINQ | 与口上场景无关 |
| 手写按钮返回值 | 自动编号正是消灭参数顺序陷阱的手段 |
| "不换行不等待"（`N` 系 / 无 `L/W` 后缀）的糖标记 | 拼句场景应写成一行 + 行内条件；逐格排版等改不动的走原生直通（§3.3 能力边界，覆盖率见 §9） |
| 每时机多个 `选项` 块 / 嵌套 `选项` | 两个 `INPUTS` 争用同一 `RESULTS`，嵌套无解；多轮选择走原生 `$标签` + `GOTO`（§3.7） |
| 包管理 / 依赖声明 | 口上以"文件夹丢进 個人口上"分发；生态现状即最优解 |

### 7.3 逃生舱（保证不漏水）

1. **原生行直通**（§3.10）：任何 ERB 指令、`$标签`、宏调用原样保留；
2. **原生函数块**（§3.10）：行首 `@` 起整块透传，用于手写附录 C 中 v1 未覆盖的 25 个入口、或自定义工具函数；
3. **正文本地原生块**：连续多行原生 ERB 直接写在时机正文里，缩进按产物归一；
4. **`CALL`/`TRYCALLFORM`** 等调用保持原生写法可用；
5. 产物是普通 `.erb`：作者随时可以脱离编辑器，用任何文本编辑器继续维护（回到原生 ERB 也没有"回不去"的锁定）。

4. **"不换行"替代方案的覆盖率**（对应 §3.3 的能力边界）：抽 10 处真实 `PRINTFORMD`（1,754 行）与 10 处 `PRINTFORM`（5,997 行）用法，逐条尝试用"整行 + 行内条件"重写，要求**产物逐字节等价**；对无法重写的（表格/状态面板逐格排版、一行内逐段 `SETCOLOR`）统计比例，确认"走原生直通"的比例可接受。**注意语义**：`D` = 忽略 `SETCOLOR`，"不换行不等待"来自**不写 `L/W/N` 后缀**——抽样时不要把两者混为一谈。
5. **分发器 `RESETCOLOR` 的覆盖性**（对应 §3.3 与 §1.5 的结论）：`KOJO_MESSAGE.ERB` 有 37 处 `RESETCOLOR`（与 37 种调用面一一对应），但 `RETURN` 有 80 处；需确认不存在"提前 `RETURN` 且跳过 `RESETCOLOR`"的路径会在实机上把颜色泄漏到下一段文本。若有，糖需在时机末尾补 `RESETCOLOR`。

已由源码直接解决、不需实测的一项：**`成否:` 默认值**——引擎兜底即 `TFLAG:192 = 0`（`KOJO_MESSAGE.ERB:640-646`），与糖的默认产物一致（见 §3.2）。
