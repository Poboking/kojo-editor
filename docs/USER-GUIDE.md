# kojo-editor 用户指南

> 面向 **eraTW（及后续 era 系游戏）口上作者**。本指南只讲「怎么用」，不讲内部实现；
> 架构与设计见 [ARCHITECTURE.md](ARCHITECTURE.md)，`.kojo` 语言完整语法见
> [SYNTAX-SUGAR-SURFACE-SPEC.md](SYNTAX-SUGAR-SURFACE-SPEC.md)。
>
> 当前处于 **0.1.0 迭代期**：功能可用，界面会随批次调整。本指南刻意只描述
> **面板名称与操作流程**（不绑定具体按钮位置），以免界面改版后失效。

---

## 1. 它能帮你做什么

eraTW 口上库里有两千多个文件、近十万个函数，传统做法靠「记事本 + 全文 Grep」，
写错函数名会**静默失效**，改一行台词要「开游戏玩到对应状态肉眼验收」。kojo-editor
把这件事变成几件事：

- **看得见结构**：按 角色 → 家族 → 面 → 函数 浏览全部口上，点一下跳到定义；
- **读得懂别人的口上**：打开游戏目录里的 `.ERB`，直接显示成中文表层写法（台词像剧本、
  条件变成「如果 …：」），没学过这套语法也能读懂；
- **先查后改**：约定校验列出全部问题（函数名拼错、家族不完整、条件写法可疑…），
  点击即定位；
- **自己的作品单独管**：有一个属于你的**口上项目**工作区，写完一键**导出**成发布包、
  或**部署**进游戏目录；
- **改完能验**：状态回放告诉你「这条口上在当前存档下会不会触发」；状态注入器能
  把变量改成目标状态，直接进游戏验收。

外加一层 **`.kojo` 语言**：用更易读的中文表层语法书写，需要 `.ERB` 的时候由工具生成。

## 2. 安装

### 方式 A：安装包（推荐）

构建产物位于：

```
packages/app/src-tauri/target/release/bundle/nsis/
```

双击 `*-setup.exe` 安装、启动即可（无需开发环境）。若你没有安装包，请用方式 B，
或向项目维护者索取。

### 方式 B：从源码构建

需要 Node.js（含 pnpm）与 Rust 工具链。在仓库根目录：

```bash
pnpm install
pnpm --filter @kojo/app tauri dev     # 开发运行（首次需编译 Tauri 依赖树，约 20–30 分钟）
```

要产出安装包：

```bash
pnpm --filter @kojo/app tauri build
```

> 首次 `tauri dev` 可能出现一次 vite「Re-optimizing dependencies」导致的页面重载
> （会回到欢迎页），属已知抖动，再开一次工程即可稳定。
>
> ⚠ 开发机上若 `localhost:1420` 被上一次未退干净的 vite 占着，`tauri dev` 会直接失败退出，
> 并把**已经在跑的编辑器窗口一起带走**。启动前先确认该端口空闲。

## 3. 第一次使用：选择游戏目录

1. 启动后进入**欢迎页**，点「选择游戏目录」，选中你的 eraTW 游戏根目录；
   下次可以直接从欢迎页的「最近打开」进入。
2. 工具会自动**识别并索引**该目录里的口上库（首次索引约一两秒，之后更快）。
   底部状态栏会显示进度与「索引中…」。
3. 随后弹出**写权限**询问。

**关于写权限（重要）**：你可以**拒绝**。拒绝后工具进入**只读浏览模式**——浏览、
校验、导航、回放全部照常可用，只是无法写入游戏目录。而且**这不影响你创作**：
你自己的作品住在独立的工作区里，始终可写（见 §4）。

## 4. 两个真相源：工作区 vs 游戏目录

这是本工具最重要的一张图。**你自己的作品**和**游戏里的东西**是两回事，分开存放：

| | **口上项目（工作区）** | **游戏目录** |
|---|---|---|
| 是什么 | 你写东西的地方 | 别人装好的游戏内容，只作为**参照与部署目标** |
| 在哪 | 应用数据目录下（`%APPDATA%\dev.kojo.editor\workspaces\`） | 你选择的那个游戏文件夹 |
| 能不能写 | **始终可写**，不需要授权 | **默认只读**，需你显式批准 |
| 谁是权威 | **是。**改东西请改这里 | 不是。它是工作内容的**投放目标** |

左侧「**我的口上项目**」面板顶部有一条常驻提示：
**「工作区为权威 · 游戏目录仅部署目标」**，就是在提醒这件事。

> **为什么会话里会提到"改了没生效"**：如果你直接改游戏目录里的文件，工作区不会感知；
> 反过来，你在「我的口上项目」里改的东西，要经过**导出**或**部署**才会进到游戏里。
> 见 §10。

## 5. 安全模型（为什么可以放心让它写文件）

工具把「写坏文件」当成头号敌人，设计上有多重保护：

| 保护 | 说明 |
|---|---|
| **游戏目录默认只读** | 只有你**显式批准**的路径可写，越权写入会被拒绝并报错。你的工作区不受此限制。 |
| **双闸校验** | 内核白名单（第一道）+ 宿主写允许域（第二道），**以更严者为准**。 |
| **自动备份** | 每次写前把原文件备份到应用数据目录的 `backup/`（按文件分目录，保留最近 20 版）。 |
| **原样编码** | **读时探测、写时保持**编码（UTF-8-BOM / UTF-8 / Shift-JIS / UTF-16）与换行风格——不会把你的 Shift-JIS 文件改成 UTF-8。 |
| **原子写** | 先写临时文件再改名，中途断电不会留下半个文件。 |
| **不覆盖已有内容** | 部署时若目标位置已有同名文件夹，**直接报错不动手**——那可能是别人已经装好的包。 |

### 游戏目录里的 `.ERB`，我到底能不能改？

分两种情况，判据很简单：**文件在哪个区**。

- **工作区里的 `.ERB`** —— 正常可编辑，跟编辑任何文件一样。
- **游戏目录里的 `.ERB`** —— 打开时编辑器顶部有一颗 **「只读」** 胶囊。
  你直接开始打字，它会问你一次：

  - **保持只读**（推荐）：什么都不改，回去读；
  - **仍要直接编辑**：这一次、这一个文件允许你改，那颗胶囊变成 **「✏ 已解锁编辑」**
    （再点它一次就是收回这次破例，`.kojo` 预览随即回来）。
    关掉编辑器就恢复只读，**不会记住**——否则"默认只读"就形同虚设了。

  更稳妥的做法通常不是解锁，而是**回到工作区新建一份口上文件**来写自己的内容。

## 6. 日常使用

### 6.1 界面布局（VSCode 式五区）

界面分五个区域，面板按用途归位（下表只描述**区域与视图名**，不绑定具体按钮位置，
以便界面微调后仍成立）：

| 区域 | 位置 | 放什么 |
|---|---|---|
| **工具栏** | 顶部 | 常用动作（「新建口上文件」等） |
| **活动栏 + 主侧栏** | 左侧 | 创作与浏览类：**口上文件**、**函数树**（同属「资源管理器」视图，组内切换）、**我的口上项目**；低频面板收在活动栏**底部**入口 |
| **编辑器区** | 中央 | 多标签编辑；`.kojo` / `.ERB` / 文本文件均在此打开 |
| **副侧栏** | 右侧 | 分析类：**`.kojo 转译检查`**、**状态回放**、**状态注入器**、**归档浏览器** |
| **底部区** | 下方 | 问题类：**约定校验**、**`.kojo 校验`** |
| **状态栏** | 最底部 | 可写/只读徽章、诊断计数、编码/换行、行号、脏态等 |

- 容器边界**可拖拽**调整大小；关掉重开会**保持**你的布局；用「重置布局」可恢复默认
  （只影响界面，不动任何文件）。
- **面板也能拖到别的区**：把活动栏图标拖到副侧栏或底部区，它就搬过去；只拖单个面板的
  标题行也搬得动（同一视图里的另一块留在原处）。落点容器会先高亮，拖自家以外的东西
  （文本、文件）不接落。
- 找不到某面板时，用命令面板（`Ctrl+Shift+P`）直接搜索打开。

### 6.2 常用快捷键

| 快捷键 | 作用 |
|---|---|
| `Ctrl+Shift+P` / `F1` | **命令面板**（搜索并执行一切命令） |
| `Ctrl+P` | **快速打开**（按文件名跳转，文件名命中优先于路径命中） |
| `Ctrl+N` | 新建口上文件（`.kojo` 向导，见 §8.5） |
| `Ctrl+S` | 保存（`.kojo` 自动编译，见 §8.2） |
| `Ctrl+Shift+S` | 全部保存 |
| `Ctrl+W` | 关闭当前标签 |
| `Ctrl+B` / `Ctrl+J` / `Ctrl+Alt+B` | 切换 主侧栏 / 底部区 / 副侧栏 |
| `Ctrl+Alt+T` | 切换 **`.kojo` 预览**（见 §9） |
| `Ctrl+K Z` | 进入**写作模式**（`Esc` 退出） |
| `Esc` | **逐层**关最上面的东西：弹出的对话框 → 向导/选择器 → 写作模式。一次只退一层，不会把整屏关掉 |

> 编辑多文件时用**标签栏**切换：标签上出现 `●` 表示未保存；关闭未保存的标签会先询问。
> 切换标签不会丢内容，未保存确认**只在关闭时**出现。
>
> 用中文输入法时：候选窗开着按 `Esc` 只是**撤销候选**，不会顺手关掉对话框或退出写作模式。

### 6.3 各面板做什么

- **口上文件**（左侧）：按 **角色 → 作者包 → 口上文件** 列出游戏里的口上文件，点开即读。
  这是**看别人的东西**。层级太深不想一层层点时，用「**展开全部 / 折叠全部**」（视图里与根节点
  右键两处都有，双向可逆，展开态会有行数反馈）。
- **函数树**（左侧）：按 `角色 → 家族 → 面 → 函数` 浏览全库函数，点击定位定义。
  **把鼠标停在某个函数上**，会显示这位作者写在该函数上方的注释块
  （约一半函数有，常含中文函数名与说明）——比只有大写函数名好认得多。
- **我的口上项目**（左侧）：**你自己作品的管理面板**，见 §7。
- **约定校验**（底部）：列出全部问题，**点击某条即跳转到对应文件的对应行**。
- **`.kojo 校验`**（底部）：当前 `.kojo` 文件的转译问题汇总（错误 / 警告 / 提示），点击可定位。
- **状态回放**（右侧）：选中某个**存档**与**角色**，查看每条触发条件的真假与分支走向，
  判断口上会不会触发。
- **状态注入器**（右侧）：把变量改成目标状态并写入**测试档**（见 §11）。
- **归档浏览器**（右侧）：浏览压缩包等资源文件（不在编辑器内打开）。

## 7. 我的口上项目：写自己的作品

这是你放自己东西的地方，**永远可写**，不需要给游戏目录授权也能用。

### 7.1 新建口上项目

面板顶部点「＋ 新建」，填几项：

| 字段 | 说明 |
|---|---|
| 作品名 / 版本 / 作者名 | 作者名会用于署名与许可条款里的版权人；导入别人的包时不会被覆盖 |
| 目标角色 | 从当前游戏项目的角色表里选。**没有个人口上目录的角色会被标明**（eraTW 的 `#0 你` 就是 master）：这样的包照样能写、能导出，只有「部署到游戏目录」那一步走不通，向导在你就选它的那一刻说明白 |
| 剧本号 | 1–10；多剧本作品按剧本号分开 |
| **许可协议** | 见 §7.2；默认「不生成 LICENSE 文件」 |

面板下方会**实时预览**将要生成的包目录名与文件数。创建后得到：

- 一份**中文 README**（作品信息、面清单、部署说明、许可说明）；
- **8 个核心面空壳文件**，扩展名是 **`.kojo`**：
  事件 / 日常指令 / 性交指令 / 奉仕指令 / 爱抚指令 / 绝顶 / 刻印取得 / 性骚扰指令；
- 若选了协议，多一份 `LICENSE`。

> 空壳里**只有注释，不含任何活函数**——工具不替作者做创作决定，从 README 里
> 标注的位置开始写即可。

### 7.2 许可协议怎么选

「不生成」是缺省项：**工具不替你决定别人能不能用你的东西**。可选项：

| 选项 | 选了它意味着 |
|---|---|
| **LTOL · 时限开放许可**（era 社区） | 标注之日起**一年**有效，版本升级再续一年；到期或作者失联半年后转为免费许可 |
| **CC BY-NC 4.0** 署名-非商业性使用 | 别人可转载和改编，但必须署名、且不得用于商业目的 |
| **MIT** | 几乎不设限：随便用、随便改，保留你的版权声明即可 |
| **BSD-2-Clause** | 与 MIT 接近：再分发时要保留版权声明和免责条款 |
| **ISC** | 与 MIT 实质等价的更短写法 |
| **占位模板** | 只落署名与年份，条款留给你自己写 |

> **LTOL 有期限**，发布时留意 `LICENSE` 里记的年份。
> **CC BY-NC 4.0** 生成的文件是**要点速览 + 官方链接**，不是条款全文——
> 具有法律效力的完整条款以文件里的官方链接为准。

### 7.3 展开一个包 = 真实文件夹

点开包名，看到的是这个包**在磁盘上的真实内容**：`.kojo`、`.ERB`、`.txt` 说明、
图片等一律如实显示，不是筛选过的虚拟列表。压缩包/资源类文件会标注"不在编辑器内打开"。

包名下方的一行小字是**署名与授权摘要**：目标角色 · 剧本号 · 原作者 · 最后更新 ·
授权文件的形态。鼠标悬停可以看到这些信息抽自哪个文件的哪一行——
**工具只报证据，不替你判断"能不能转载"**（授权条款的含义因人而异）。

### 7.4 右键新建

在包名、子目录或项目名上**点鼠标右键**，可以新建：

- **新建口上文件（.kojo）** ← 默认推荐，中文表层写法与原生 ERB 写法都能写在同一个文件里
- 新建 ERB 文件（.ERB）
- 新建文本文件（.txt）
- 新建文件夹

选中后名字输入框**直接长在树里**：输入时右侧实时显示最终会建成什么名字
（例如打 `事件` → 显示 `→ 事件.kojo`），**回车创建**、**Esc 取消**。
新建的是文件的话，会顺手在编辑器里打开。

> 名字不合法时不会偷偷帮你改，而是把原因写在下面告诉你（例如 Windows 不允许的字符、
> 名字以点号结尾会被裁掉等）。

### 7.5 导入别人的包

在「口上文件」树里对某个作者包右键 →「**导入为我的口上项目**」，
把它复制进你的工作区再改。原文件不动。

## 8. `.kojo` 语言：编辑 → 保存 → 编译

### 8.1 基本规则

- `.kojo` 是**超集**：中文表层语法与原始 ERB 写法可以写在同一个文件里。
- `.kojo` 源文件编译后，产物是**同目录、同基名**的 `.ERB`。例如
  `M_KOJO_K1_日常.kojo` → 同目录 `M_KOJO_K1_日常.ERB`。
- 打开 `.kojo` 时编辑器会给出**中文高亮与补全**（关键字、保留代词、别名）。
- 编辑过程中，有问题的行会出现**波浪线**；底部「`.kojo 校验`」面板汇总问题，点击可定位。

### 8.2 保存时会发生什么

按 **Ctrl+S** 时：

1. **源文件 `.kojo` 一定保存**（你的成果永不丢失）；
2. 若转译通过 → **同时编译产物 `.ERB` 落盘**（写前自动备份旧产物），状态栏提示
   `已保存并编译 → xxx.ERB（N B）`；
3. 若转译**有错误** → 源文件照常保存，但**不生成产物**（避免半成品 ERB），状态栏
   提示 `产物未生成：转译含 N 项错误（见「.kojo 校验」）`——按提示修好再存。

产物一律是 **UTF-8-BOM + LF + 末尾换行**（与真实语料的通行形态一致）。

### 8.3 全角空格告警（保存时的确认框）

若源文件里含**全角空格（U+3000）**——它和半角空格肉眼难分，是口上编辑的高频坑
——保存时会弹出确认框，让你三选：

- **取消**：本次不保存（磁盘不变，可继续修改）；
- **仍然保存**：按原样保存（全角空格保留）；
- **替换为半角空格并保存**：编辑器内把全角空格换成半角（**可 Ctrl+Z 撤回**）后保存。

> 为什么只告警不强制拦截：真实口上语料中约 1.54% 的行含全角空格，且**多为有意
> 的行中用法**，一刀切拦截会误伤。故以「提示 + 一键修复」交给你决定。

### 8.4 最小示例

```
角色: 1
时机 初见：
    「你好。」
    她笑了。 续
```

> 完整的表层语法（关键字、别名、条件/分支写法等）见
> [SYNTAX-SUGAR-SURFACE-SPEC.md](SYNTAX-SUGAR-SURFACE-SPEC.md)（当前 v1.6）。

### 8.5 新建口上文件（向导）

用命令面板搜「新建口上文件」，或按 `Ctrl+N`，或点工具栏按钮。要填的就四项：

| 字段 | 说明 |
|---|---|
| **角色** | 必选，从当前游戏项目的角色表里取 |
| 家族名 | 可选，留空 = 初始家族；写进文件名尾段 |
| 起始时机 / 时机编号 | 可选，选了就预置一个时机块 |
| 文件名 / 写入位置 | 不用填，**实时预览**（如 `M_KOJO_K49_日常.kojo`） |

**新文件落在你自己的口上项目里**（作者包目录），不写游戏目录——工作区恒可写，
所以这一步**不需要先批准写权限**，也不会中途让你去点状态栏徽章。
前提是**已打开一个游戏项目**（角色表和文件名模板都从那儿来）；没打开时向导会直接
说明原因而不是让你填完再失败。

还没有口上项目时，向导不会把你堵在门外，而是给两条路：

- 「**新建口上项目并创建**」：先走一遍新建项目向导，建好后**自动**把手上这份
  `.kojo` 落进新项目的包里（若这一步失败，会把原因原样带回向导，不会静默）；
- 「**选择文件夹另存…**」：用系统保存对话框自己挑位置，建单文件。
  代价要说清：这样的文件**不在口上项目里，因此不参与导出与部署**。

创建成功后文件自动在编辑器打开；同名文件**不覆盖**，直接把原因写给你。

### 8.6 把原生写法改成 `.kojo` 写法（💡）

在 `.kojo` 文件里，把光标停在一行**原生 ERB 写法**上，会出现 **💡**：
点它即把该行转成对应的 `.kojo` 写法，**可 `Ctrl+Z` 撤回**。

> 💡 只出现在 `.kojo` 里。要读**别人的** `.ERB`，用下一节的 `.kojo` 预览。

## 9. 读别人的口上：`.kojo` 预览

打开游戏目录里的 `.ERB`（工作区里自己写的 `.ERB` 不在其列——自己正在写的东西直接看原文），
**第一次**会先问你要不要开启「`.kojo` 预览」。开启后，整份文件会**就地**显示成中文表层写法：

| 你会看到 | 对应原来的写法 |
|---|---|
| 一行行台词、旁白 | `PRINTFORMW 「…」` / `PRINTFORMDL …` 等输出指令 |
| `如果 X：` / `否则：` / `否则如果 X：` | `IF X` / `ELSE` / `ELSEIF X` |
| `当 X：` / `是 v：` | `SELECTCASE X` / `CASE v` |
| `{她}` `{你}` | `%CALLNAME:TARGET%` / `%CALLNAME:MASTER%` |
| 缩进收束（不显示结束行） | `ENDIF` / `ENDSELECT` |
| 注释与空行 | 原样 |

暂时还不支持的行（循环、`TRY`、`SIF` 分支、数据表、赋值与调用等）**保持原样显示**，不会被藏起来。

三条要知道的：

- **只改显示，一个字节都不动文件**。开启后工具条上会给出「`.kojo` 显示 N 行」，鼠标悬停
  说明其余行为什么还是原样（还没覆盖到的控制流、赋值与调用，以及注释和空行）。
- **随时可切**：点工具条的「**`.kojo` 预览**」按钮，或按 **`Ctrl+Alt+T`**，也可以在
  「设置」里改。**默认关**，开了会被记住。
- **第一次打开 `.ERB` 时会问你一次**要不要开（一个会改变文件显示方式的功能，
  至少该先告诉你它存在）。问过之后不再问。

> `.kojo` 预览与"可编辑"是互斥的：一旦你解锁编辑某份游戏目录的 `.ERB`，
> 该文件的预览会自动让位（要改的东西必须看得见）。想收回这次破例，
> **再点一次那颗「✏ 已解锁编辑」胶囊**即可——回到只读，预览也跟着回来。

## 10. 发布：导出与部署

写完要让它进游戏、或发给别人，有两条路。**两条都会自动把 `.kojo` 转成游戏认得的
`.ERB`**——直接把 `.kojo` 放进游戏目录是**不生效**的（引擎只读 `.ERB`），
这是最常见的"装了没反应"原因。

在「我的口上项目」里，鼠标悬停到某个包上会出现两个动作。

### 10.1 导出（发给别人 / 存档）

点「**导出**」→ 选一个保存位置 → 得到一个 **ZIP 压缩包**。

- 包内是一个以你的包目录名命名的文件夹，解压出来就是可发布形态；
- `.kojo` 已转成同名 `.ERB`；README、说明、图片等**原样带上，一个字节不改**；
- **压缩包里不会有 `.kojo`**——游戏读不到它，留着只会让人以为装好了；
- 若某个 `.kojo` 转译失败，**整个导出会被拒绝并告诉你哪个文件、哪一行**，
  不会给你一个缺文件的半成品包；
- 你的工作区原件不动。

### 10.2 部署（装进自己的游戏）

点「**部署**」→ 选目标角色 → 窗口里会**先显示落点**给你确认 → 点「部署到游戏目录」。

- 落点是 `<角色口上目录>/<你的包名>/`；
- **目标已存在会直接报错，不覆盖**（那可能是别人已经装好的包）；
- 游戏目录默认只读，所以**需要先批准写权限**；没批准时窗口会当场写明，
  并且**不会先建一个空目录**再失败；
- 角色在游戏里没有个人口上目录时，同样直接说明，按钮不可点。

### 10.3 手工放置也可以

先把 `.kojo` 全部转译成同名 `.ERB`（在 `.kojo` 上按 `Ctrl+S` 即可），
再把 `.ERB` 连同辅助文件复制进游戏目录对应位置。

## 11. 状态注入器：安全提示（务必先读）

「状态注入器」用于把变量改成目标状态，**只对测试档生效**，并有四重保护：

1. **只改测试档**：绝不会写你的正式存档——请始终在**副本/测试档**上操作；
2. **两步确认**：改动前需要你二次确认；
3. **自动备份**：写入前备份被改的文件，可回退；
4. **回读验证**：写完立即回读比对，确认落盘内容与预期一致。

> 建议：动手前先把存档目录**整体复制一份**作为保险。注入器只保证「它改了哪些
> 字节」，不替你对「该不该改」负责——游戏内的存档兼容性请自行评估。

## 12. 故障排查

| 现象 | 原因 / 对策 |
|---|---|
| 装进游戏的口上没反应 | **十有八九是把 `.kojo` 直接放进游戏目录了**——引擎只读 `.ERB`。请用 §10 的「导出」或「部署」。 |
| 保存时报「Write not allowed / 越权」 | 该路径不在授权范围内。游戏目录需重新授予写权限；自己的作品请放进**工作区**（§4），工作区不需要授权。 |
| 保存后游戏读不到新内容 | 检查是否生成了**同目录同名 `.ERB`**；若状态栏提示「产物未生成」，先修掉「`.kojo 校验`」里的错误。 |
| 提示「产物未生成：转译含 N 项错误」 | 这是**保护**：有错误时不产半成品。按「`.kojo 校验`」面板定位修改后重存。 |
| 导出/部署报「产物名冲突」 | 同一目录下同时有 `事件.kojo` 和 `事件.ERB`——两者都会落成 `事件.ERB`，工具不替你选。删掉或改名其中一个。 |
| 中文乱码 | 保存会保持原编码；若源文件本身编码异常，请在外部工具确认其编码后再编辑。 |
| 误改了文件想回退 | 备份在应用数据目录 `backup/<文件哈希>/` 下（保留最近 20 版），手动还原即可。 |
| 游戏目录里的 `.ERB` 只能看不能改 | 这是**刻意设计**。要改：直接开始输入会问你一次（§5）；更好的做法是回工作区新建一份 `.kojo` 写自己的内容。 |
| 打开 `.ERB` 后"内容变了"很慌 | 那是 **`.kojo` 预览**（§9），只改显示、没动文件。按 `Ctrl+Alt+T` 切回原样。 |
| 看不到 💡 | 💡 只在 **`.kojo`** 文件里的原生写法行上出现。读 `.ERB` 请用 `.kojo` 预览。 |
| 在别的程序里改了文件，编辑器里也跟着变了 | 这是**正常**的（文件监视 + 自动重载），不是幽灵改动。反过来若你有未保存的改动、文件在磁盘上被别人改了，编辑器**不会**覆盖你的内容，而是发一条常驻通知让你选。 |
| 在别处新建/删除的文件没进树 | 正常情况下**几秒内会自动上树**（目录缓存有失效通道，§5.91/§5.93）。真没出现时点工具栏项目标签旁的「**重载项目**」兜底；已展开节点的折叠状态不会被打乱。 |
| 函数树/索引没跟着新文件更新 | 这是**已知边界**：监视器管的是**文件与目录**，全项目函数索引重建约 2 秒，不做增量之前不自动触发（属性能线）。需要立即反映新函数时用「重载项目」。 |
| 首次打开工程出现控件闪烁 / 回到欢迎页 | `tauri dev` 首次 vite 重优化的已知抖动，重开工程即可。 |
| 界面上找不到某个面板 | 用 `Ctrl+Shift+P` 搜命令打开；低频面板收在活动栏底部入口。 |
| 面板位置 / 大小乱了，想恢复默认 | 命令面板搜「重置布局」，或「设置」→ 布局 → 重置布局（不影响任何文件内容）。 |
| 顶部工具栏 / 底部区 / 副侧栏不见了 | 分别用 `Ctrl+B` / `Ctrl+J` / `Ctrl+Alt+B` 切换；或重置布局。 |
| 快捷键没反应 | 焦点在输入框或弹出的选择器里时快捷键会**让行**（`Esc` 先关面板）。先按 `Esc` 关闭再试。 |
| 打开工程后函数树/文件树空空 | 状态栏会显示「索引构建中…」或红色「索引失败：原因」。若为失败，用**项目头部**的「重载项目」或「重新授权」自救。 |

## 13. 常见问题

**Q：会不会改坏我的游戏目录？**
默认只读；只有你显式批准的路径可写，且写前自动备份、写时保持原编码、原子落盘。
未授权时浏览类功能完全可用，你自己的作品也不受影响——它住在工作区，那里始终可写。

**Q：我改的到底哪一份算数？**
**工作区那份算数。** 游戏目录是部署目标：在工作区改完，用「导出」或「部署」投进去。
直接改游戏目录里的文件，工作区不会感知。

**Q：和直接编辑 `.ERB` 冲突吗？**
不冲突。原生 `.ERB` 仍可直接编辑（游戏目录里的那份需按 §5 解锁）；`.kojo` 只是可选的、
更易读的表层语法，两者共存，且可以写在同一个 `.kojo` 文件里。

**Q：`.kojo` 编译出错，我的源文件会丢吗？**
不会。源文件永远保存；出错时只是**不生成** `.ERB` 产物，导出/部署则会整体拒绝而不是
给你一个缺文件的半成品包。

**Q：为什么新建的文件都是 `.kojo` 而不是 `.ERB`？**
因为 `.kojo` 是超集：中文表层写法与原生 ERB 写法都能写。反过来（先给你 `.ERB`）就限制了你的表达，
而工具不该在你还没决定之前替你做这个决定。

**Q：能编辑非 eraTW 的游戏吗？**
当前适配器面向 eraTW；架构支持新增适配器插件来扩展其他 era 系游戏（内核无需改动）。
