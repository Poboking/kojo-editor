> 审查基线：`dev` @ `4b192824`（拉取后工作区干净）。

> （`.settings-host` 920px），四种状态 × 暗/浅两主题，逐屏读图；再用源码定位每个观感的成因。

## 结论先行

1. **它不像「设置页」，像一个塞进设置页的独立后台。** 全站其余节是「`.settings-group` 平铺 + 分组标题 + 行」，
   本页是「卡片套卡片套卡片」+ 自带的 `h2`，左轴也比别人多缩进 16px。
2. **同一件事说了三遍。** 徽标「运行中」+ 状态条「状态：运行中 · 端口 · 并发 · 握手」+ 三张读数卡，
   全在讲同一组事实；真正该被看见的「下一步做什么」被压到第四屏。
3. **它会对用户说假话。** 服务没启动时先弹一条黄色「接入台账读取失败」；读取失败时把「不知道」画成 `0`。
   这两条违反项目自己的铁律 4（不静默、不编造），但方向反过来——**静默地编造了坏消息**。

## 附：可复现的审查方式

组件本身完全可注入，不需要 Tauri：

```tsx
<AiAccessSection
  runner={async (cmd) => mockByCommand[cmd]}  // mcp_status / mcp_scope_query / …
  pollMs={0}
/>
```

套 `.settings-host > .settings-nav-panel > .settings-body` 即可得到与真机同宽的页面。
四种状态各截一张，比读源码快得多——本次审查的每条结论都能在图上指出来。
