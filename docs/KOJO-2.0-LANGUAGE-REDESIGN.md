# Kojo 2.0 语言设计重构总案（工作稿 · 2026-11-04）

> 状态：设计已拍板，分波实施中。最终会合并进 `KOJO-2.0-LANGUAGE-SPEC.md` 成为正式规范。
> 冻结边界：`【剧场：…】` Theater 语法 / Theater AST / M2/M3 / Target Registry / Project IR /
> Linker / Runtime Matcher / Editor Integration Application Service / ERB wrapper 协议 /
> 项目级编译与产物组装接口。旧 `# 机` 只保留既定兼容语义，不再作为主要作者语法。

## 0. 一句话结论

现行 kojo2 已经有中文骨架，但表面语言仍像「Markdown 注解 + 英文脚本符号」：
五个半角锚点互不成族、叙事必须逐行 `>`、声明像注解、调用 `!` 读起来像否定、
随机叫「随机」其实只是等概率择一、非叙事区 `{名字}` 与裸名字两套写法。

重构方向：**方寸标题 · 冒号动作用 · 裸行叙事**——
让源码第一眼像一份中文剧本，程序结构退到第二层视觉。

## 1. 三个视觉族（新正典）

| 族 | 形态 | 读法 | 承担 |
|---|---|---|---|
| **方寸** | `【…】` 独占一行 | 标题 / 场记板 | 文件级声明与场景头（Theater 头本来就是这一族） |
| **动作** | `词 …：` 块头 / `词` 单词指令 | 舞台指示 | 可执行块、分支头、控制转移、调用 |
| **叙事** | 裸行 = 旁白；`角色：「…」` = 台词 | 剧本正文 | 作者 90% 时间写的东西 |

辅助记号：

- 行尾 `续` = 不等待（保留，语义不变）。
- 整行 `※ …` = 注释（`//` 兼容）。
- 行尾半角 `(提示)` = 导演批注（不打印）；全角 `（…）` = 正文（打印）——保留现行分工。
- 数字/运算符/参数列表仍用半角：输入成本低、无歧义；中文词别名保留但不作正典。

## 2. 新正典语法表

### 2.1 文件骨架

```kojo
【剧场：初见｜神社】

【幕 神社清晨】
【视角 灵梦】
【挂 指令 310】

【设 亲近线 整数 = 500】
【设 今天已触发 整数 = 0 存档】

【对照表 心情 依据 恋慕】
    0..99 → 疏远
    100..499 → 平常
    亲近线.. → 亲近
    否 → 未知

晨光透过鸟居，斑驳地洒在石阶上。
灵梦：「{你}今天来得挺早嘛。」(微笑)

若 恋慕 >= 亲近线：
    灵梦：「其实……{我}一直在等你。」(心形)
再若 恋慕 >= 100：
    灵梦：「早上好，今天天气不错呢。」
否则：
    灵梦：「……早。」

【池 早安问候】
    若 恋慕 < 100：
        「……早。」
    否则：
        「早上好。」

演：早安问候
```

### 2.2 声明（方寸族）

| 新正典 | 旧写法（兼容） | 说明 |
|---|---|---|
| `【幕 神社清晨】` | `# 幕 神社清晨` | 场景，不提升、按序演出 |
| `【视角 灵梦】` | `# 视角 灵梦` | 代词表不变 |
| `【挂 指令 310】` | `# 机 指令 310` | **新作者语法**；`# 机` 只作旧文件兼容 |
| `【设 亲近线 整数 = 500】` | `# 设 …` | 单行声明；类型/初值/存储期规则不变（类型自然化见 §6 波 2） |
| `【对照表 心情 依据 恋慕】` | `# 对照表 …` | 表体 `→` 为正典，`->` 兼容 |
| `【池 早安问候】` | `# 池 …` | 条件台词池 |
| `【模 娇羞退场(原因)】` | `# 模 …` | 编译期模板 |
| `【函 增加羁绊(目标, 数值 = 10)】` | `@函 …` | 运行期函数 |
| `【织 回合末 之后】` | `@织 …` | 监听；修饰词 `之前/之后/接管` 不变 |
| `【方言 …】` | `# 方言 …` | 方言断言不变 |

### 2.3 动作（冒号族）

| 新正典 | 旧写法（兼容） | 语义 |
|---|---|---|
| `算：` | `@算` | 状态更新块 |
| `色：0xFF8080` | `@着色 0xFF8080` | 演出着色块 |
| `颜绘：笑顔` | `@颜绘 笑顔` | 单行演出指令 |
| `择一：` | `@随机` | 等概率择一（名字改准：不是概率分布） |
| `组：` | `@组` | 择一候选组 |
| `循环：条件` | `@循 条件` | 条件循环 |
| `重复：3` | `@复 3` | 固定次数 |
| `遍历：队伍` | `@巡 队伍` | 遍历集合 |
| `标：名字` / `跳：名字` | `@标` / `@跳` | 同单元跳转 |
| `断` / `续` | `@断` / `@续` | 循环内跳出/继续（独立成行） |
| `演：名字` / `演：名字(实参)` | `! 名字` | 统一调用池/模板/函数 |
| `若 条件：` | `? 条件` | 条件链头 |
| `再若 条件：` | `? 条件`（链中） | 条件链中段 |
| `否则：` | `? 否` | 条件链默认分支，必须最后 |

`@原生{ … }` 暂保留旧形态（新方寸形态在波 3 设计，先不动逃生舱语义）。

### 2.4 叙事（裸行族）

- **裸行 = 旁白**（叙事区），不再需要 `>`。
- `角色：「台词」` 台词；说话人规则不变。
- `# 池` 内裸引号仍 = 省略说话人的台词（局部例外保留）。
- 行尾半角 `(提示)` = 导演批注；全角 `（…）` 是正文；`续` = 不等待；`空行` 三态保留。
- 叙事区里出现**赋值/调用/控制结构**仍然报错：裸行只在"看起来是正文"时才当旁白；
  语句形态（含顶层赋值运算符、`名字(` 调用形态）仍按"叙事区裸表达式"报错，不静默变文本。
- 计算区（`算：`/函数体/循环体）裸行仍是代码；要演出写 `>` 或 `角色：`（保留现行边界）。

### 2.5 表达式（本波不变，波 2 处理）

- 条件运算符、`{}` 插值、数组/长度、函数调用、`{角色}的属性` 全部保持语义；
  波 2 再决定「非叙事区去 `{名字}`」「插值记号」「中文比较词」等表面统一。

## 3. 语义不变量（任何审美改动不得破坏）

1. 确定性解析：同一源码只有一种 AST；新表面在词法层归一化到既有节点，不引入歧义分支。
2. 块结构：缩进 4 空格、去缩进收口、块内规则不变。
3. 语句/表达式边界：叙事区的裸表达式仍报错；计算区裸行仍是代码。
4. 诊断：新增写法复用既有诊断码前缀；错误位置仍指向原始源码列。
5. SourceMap：新表面记录原始 span，不因归一化偏移。
6. 编译语义：新表面与旧写法必须产出**逐字相同**的 ERB（同 AST 同 lower）。
7. M1 golden 字节零变化；M2/M3/Theater/Application Service 零改动。
8. 旧写法在过渡期继续被接受，不强制一次性迁移；迁移由编辑器快速修复/格式化提供。

## 4. 兼容与迁移策略

- 旧 `#` / `@` / `>` / `?` / `!` 五种写法在过渡期**全部继续可用**，语义逐字不变。
- 编辑器提供「转为新写法」格式化/快速修复（波 5 落地），批量迁移不破坏既有项目。
- 旧 `# 机` 不再出现在教程/模板/补全里；新文件只教 `【挂 …】`。
- 迁移诊断不 downgrade 语义约束：旧写法仍是合法 2.0，只是"非正典表面"。

## 8. 语料证据（2026-11-04 盘点）与设计修订

盘点报告：`C:\tmp\kojo-lang\corpus.md`（113 个仓内 `.kojo2` / 1430 行；真实语料不在位，用
kojo-sugar goldens 8154 行 + migrate-corpus 88 文件做代理样本）。关键事实：

1. **仓内 2.0 语料是夹具形状，不是作品形状**：没有一份作者级完整样例；`examples/m2-project`
   每份只有 3 行。→ W5 必须补"作者级可编译示例项目"，否则语言设计没有真实读者。
2. **真实稿子重心 ≠ 2.0 正典**：代理样本 33.1% 原生 ERB 直通行、28.4% `;` 注释、14.4% 裸 `「」`；
   2.0 夹具重心却是 `>` 旁白 + 台词。→ 迁移首屏必须能机械处理这三类，否则"叙事优先"只是纸面。
3. **一号负担是 `设` 一词两义**：`# 设 名 整数 = 0` 是常量（赋值即错），要变量必须补存储期词。
   → **W2 决策：正典拆成两个字**
   - `【定 名 类型 = 值】`：编译期常量（不可赋值，必须初值）；
   - `【设 名 类型 [= 值] [存储期]】`：运行期变量（缺省 `场景`，可赋值）。
   - 旧 `# 设` 保持自动推断（兼容），迁移工具按"是否被赋值"判定改写成 `定/设`；判不准时：
     写 `设`（变量语义更宽，避免静默变常量）。
4. **二号负担是 `续` 一词两义**（行尾等待 vs `@续` 循环继续）。→ **W2 决策**：
   - 行尾 `续` 保留（等待三态）；
   - 循环继续正典改 `下一轮`，循环跳出正典改 `跳出循环`（独立成行）；
   - `断`/`续` 继续兼容为旧 program 写法；编辑器把 `断/续` 标成"旧写法"，补全只教新词。
5. **编辑器/编译器/规范三处硬不一致**：中文运算符被高亮但表达式层只收符号；`# 对照表` 的
   code action 块头正则写成 `表`（永不命中）；全角冒号仍触发自动缩进（与 2.0 旧"不写冒号"冲突，
   但与 W1 冒号块头正好一致——W1 起保留，更新规范说明）。→ W2 起以编译器为准修编辑器：
   中文运算符**补进表达式语法**（`等于/不等于/且/或/非` 作 `==/!=/&&/||/!` 的别名），
   高亮与解析同一张表；其余逐条修。
6. **`@原生` 必须换新形态**：W3 决策 `【原生】 … 【/原生】`（raw 行直到独立收口行，不要求缩进，
   也不解析任何 2.0 语法）；旧 `@原生{}` 兼容。理由：33% 的迁移稿是原生直通行，旧形态的
   `{`/`}` 与 ERB 大括号互相干扰，作者最容易被它卡住。
7. **`;` 注释与裸 `「」`**：W5 迁移把 `;` 行注释机械换成 `※`；裸 `「…」` 一律包成
   `> 「…」`（旁白引语）或补说话人，不新增"无说话人的台词"语义（避免池/场景两套裸引号语义冲突）。
8. **W1 落地状态（2026-11-04）**：core 词法归一化 + 裸行旁白已实现，
   `packages/kojo-core/tests/language-redesign-w1.test.ts` 16 例绿；编辑器作者面与
   conformance/eraTW 真实 ERB 对拍并行落地中。旧写法零改动继续可用。

## 9. 实现约束（盘点车 2026-11-04 报告，`C:\tmp\kojo-lang\inventory.md`）

1. **作者链路没有可用的表达式解析器**：`expr/parse.ts` 的 `parseExpr` 无生产消费；parser 只存
   表达式文本切片，sema 用正则猜类型。⇒ 任何"新表达式表面"（中文运算符、别名）在 phi 层
   都必须先有真正的表达式解析/诊断，否则只是把非法文本喂给 adapter。**W2 决定：中文运算符
   不升正典**；编辑器停止把它当语法高亮（W5 修），避免"高亮但不认"。
2. **词表位序是跨包公开契约**：`KOJO_DECL_WORDS` / `KOJO_DISPATCH_WORDS` 的索引被
   `kojo-lang` 14 个文件按位置消费。**任何插词/改序前**必须先把消费方改成按名查表，
   或另立新表面词表（W1 已另立 `KOJO_HEADER_*` / `KOJO_ACTION_WORD_ALIAS`）。
3. **lower 三张 switch 无 default 兜底**（`lower/narrative.ts`、`lower/program.ts`、
   `lower/expand/walk.ts`）：加 AST 节点会静默不产字节。⇒ 语言表面改动优先在词法层归一化，
   直到这些 switch 补上 never 兜底（W3 前置）。
4. **conformance 逐字节闸**：27 份 `.golden.erb` + 20 份 `.diagnostics.json` + 11 份
   三方言 `.body.erb`；新表面 fixture 允许新增，**不许改既有 golden**（除非语义确实变更并
   逐条审阅）。
5. **旧语法/新语法三份真源**：core lexer/parser、`kojo-lang` Monarch、`kojo-syntax-tree/
   grammar.v2.js`；W1 表面必须在三处同步，否则编辑器与编译器分叉。
6. **冻结区已确认解耦**：Theater / M2/M3 / ERB wrapper / Project IR / Linker / Runtime Matcher /
   Application Service 不 import lexer/parser/ast，语言重构碰不到它们。
