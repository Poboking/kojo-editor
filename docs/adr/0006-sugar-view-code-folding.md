# ADR-0006: 糖视图可以折叠代码，但必须「默认收起 + 可展开原文」

- **日期**：2026-10-12
- **状态**：已接受（用户拍板）；**实施未开工**（下一批之后的独立批）
- **相关**：`docs/SYNTAX-SUGAR-SURFACE-SPEC.md` §3.10 原生直通 / §1.2 愿景；
  IMPLEMENTATION-LOG §5.66–§5.68（批 I/J/K）；`docs/LIFT-REMEASURE-2026-10-12.md` 十一（续五）；
  ADR-0005（写权限与糖视图互斥，同属"糖视图边界"这一族决策）

## 背景

糖视图的愿景是「让不熟悉 EraBasic 的人打开别人写的 ERB 口上，能像看剧本一样读懂」。
批 I/J/K 之后，**读者要读的行**已经基本到位（台词 99.2%｜输出 99.2%｜演出 98.0%｜函数头 81.2%），
而未投影行的榜首变成了**函数骨架**：

| token | 未投影行数 | 性质 |
|---|---|---|
| `RETURN` | 167,441 | 函数返回（几乎无阅读价值，但**是结构事实**） |
| `CALL`（非 HPH_PRINT 部分） | ≈ 60,000 | **有副作用**：跳转进别的函数 |
| `LOCAL` | 54,268 | 临时量（读者的噪声底） |
| `SETCOLOR` / `DATAFORM` 等 | 17,713 / 17,734 | 演出与数据表 |

也就是说：**再翻译"语言"已经不能显著改善读感，剩下的障碍是"代码量本身"**。
一条 300 行的口上里可能有 120 行是骨架——读者要的是剧本，看见的是剧本 + 一半汇编。

于是必须回答一个原则层面的冲突：

- **愿景**要求把噪声从视野里移开；
- **铁律「绝不静默」**（ARCHITECTURE）要求能力缺席必须**可见**，
  而且糖视图过去的口径是"只翻译、不删行"（§3.10 原生直通连灰字都保留）。

把 `CALL MOPIGU(RESULT)` 直接从读者眼前拿走，是**第一次由编辑器主动隐去游戏代码**——
一旦做过头，就从"帮读者读懂"滑向"替读者决定他该看什么"，并且会让核对语义的人看不到副作用。

## 决策

1. **允许折叠**：糖视图不必再承诺"所有未投影行都逐行可见"。骨架类行**默认收起**。
2. **收起 ≠ 删除**：折叠必须以**可展开**为前提——折叠处留一行可读的占位（例如
   `… 3 行状态计算`），点击/快捷键即还原原文逐行显示。**原文永远一字符不差地在那里**
   （折叠只是视图状态，绝不改文档、绝不改盘）。
3. **默认折叠的白名单必须封闭且可证**：只有**无外部副作用**的行型可以进默认折叠
   （候选：`LOCAL` 赋值、`RETURN`、纯 `;` 注释分组内的空行）。
   **有副作用的一律不折**：`CALL` / `TRYCALL*` / 任何角色状态赋值（`CFLAG` 等九族）/
   `PRINTDATA` 数据体 / `SETCOLOR` 系 / `#DIM` `@` `#` `$` 结构行。
   白名单是**判据**而不是启发式——按批 J 的教训，**"看起来是骨架"不构成折叠理由**。
4. **不静默的落点**：折叠状态必须在**状态栏/工具条**给出可读计数（"已收起 N 行，点此展开"），
   并且糖视图摘要口径要跟着改（现在只报"已映射多少行"，折叠后必须同时报"收起多少行"）。
5. **关闭开关**：折叠必须能被整体关掉（用户偏好），关掉后回到批 K 的形态（逐行可见）。

## 后果与验收含义（为什么这不是一行开关）

- **契约层**：`SugarProjectSegment` 目前只有 `fromLine/toLine/sugarText/lineCount`，
  **承载不了"这一段里哪些源行被收起、收起后显示什么"**。要新增字段（additive）而不是塞进
  `sugarText` 字符串——宿主按字符串猜结构就是第二个真相源。
- **宿主层**：ViewZone 需要一个可交互的折叠柄（展开/收起是视图状态，不进 Monaco 文档、不进撤销栈），
  且与 `setHiddenAreas` 的现有分工要先定清楚（隐藏区间由投影给，折叠柄由宿主给）。
- **守门**：第七把尺子 = **折叠率**（默认折叠的占未投影行的比例）+ 一条硬不变量
  **「折叠行的副作用数为 0」**（可由 `condition-extractor` / `erb-parser` 的结构信息判定，
  不许投影层自己猜）。缺了后者，这把尺子只会奖励过度折叠。
- **性能**：折叠减少的是**读者要读的行**，不是 ViewZone 数（批 K 已把段数降到 289,542）；
  所以不要拿"性能提升"当这条决策的理由——它是纯读感决策。

## 备选方案（为何不选）

| 方案 | 为何不选 |
|---|---|
| 只降灰、一律不隐藏 | 与愿景正面冲突：读者仍要扫过 20 万行代码；行覆盖天花板永远停在 60.8% |
| 默认隐藏且不可展开 | 直接违反「绝不静默」，且核对语义的人无从看副作用——这是本项目明令禁止的那种"看着像懂了其实被误导" |
| 启发式按"短行/大写"折叠 | 与"判据封闭可证"冲突；批 J 的假阳性正是"看起来像"造成的 |

## 实施前的核对清单（下一批开工时逐条打勾）

1. 契约：`SugarProjectSegment` 增 additive 字段（收起的源行区间 + 占位文本），**不塞进 `sugarText` 字符串**。
2. 事件/偏好：糖视图偏好里加"折叠开关"，关掉即回到批 K 形态；偏好持久化沿用现有 overlay 设置通道。
3. 宿主：折叠柄走 ViewZone 交互，状态不进 Monaco 文档、不进撤销栈；与 `setHiddenAreas` 的分工写进注释。
4. 白名单封闭：默认折叠只允许 `LOCAL` 赋值 / `RETURN` / 空行三类，**其余一律不折**；
   判据来自 `erb-parser` 结构信息与 `condition-extractor` 的副作用数据，不由投影层自行猜。
5. 守门：新增第七把尺子「折叠率」，并加硬不变量**「被折叠行的副作用数恒为 0」**——
   缺这条，尺子只会奖励过度折叠。
6. 不静默：工具条摘要同时报「已映射 N 行｜已收起 M 行（可展开）」，M=0 时不提后半句。
7. 文档：`docs/MANUAL-CHECKLIST-*` 加目视项（展开/收起/关偏好三条），并在糖视图首次询问文案里说明可关。
