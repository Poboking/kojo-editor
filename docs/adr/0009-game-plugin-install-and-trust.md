# ADR-0009: 游戏插件安装、函数覆盖与信任链 —— 改的是盘上文件，不是运行中的进程

- **日期**：2026-10-26
- **状态**：**已接受（设计口径定稿；实现未开工）**——本文不含「已实现」的任何断言
- **相关**：[`LAUNCHER-ARCHITECTURE.md`](../LAUNCHER-ARCHITECTURE.md) v0.4 §5.4（清单）、§6.7（`PluginManager`）、
  §10.1–§10.4（安装 / 冲突 / 启停 / 门禁）、§13.1、§16 风险 5/14/15/17；ADR-0007（代码插件轨）、
  ADR-0008（进程特权面与写授权表）、ADR-0010（插件项目的构建与源/产物分离）

## 背景

启动器把「游戏插件」升为一等能力：插件可以**修改 / 替换**游戏逻辑（ERB 脚本、CSV 数据、资源），
而不只是追加内容。这与 `ARCHITECTURE.md` §1.2 的「不直接修改游戏逻辑代码」正面相撞，
必须先把三件事说清，否则实现会在三种误读之间摇摆：

1. **它和 ADR-0007 的代码插件是不是一回事？** 名字都叫「插件」，能力面完全不同。
   把 ADR-0007 的禁令套过来，会把一个正当产品能力判成违规；反过来，把它的前置三件套
   （权限模型 / 沙箱 / 签名）当成游戏插件的开工条件，会把这条线无限期卡死。
2. **函数重名到底算不算冲突？** 真盘事实：eraSQC 有 **190 处**逐角色同名函数重复
   （EVENTTRAIN 91 + EVENTEND 90 + 1），eratohoK 仅 **2 处**。在这个生态里，
   「同名函数多处定义」既可能是引擎语义的一部分，也可能是插件真把别人的函数盖掉了。
   一律拒 = 把正常包判死；一律放 = 静默覆盖。
3. **存档怎么办？** 插件改的是逻辑，玩家在旧存档上的进度可能因此读不出；装与卸都不该
   在不告知的情况下动存档。

## 决策

### 1. 与 ADR-0007 的边界（先划线，再谈门禁）

| 维度 | **游戏插件**（本 ADR） | **代码插件**（ADR-0007） |
|---|---|---|
| 载体 | 磁盘上的游戏脚本 / 数据 / 资源（ZIP 包） | 会执行 JS 的插件代码 |
| 生效方式 | **经游戏自身的加载机制**（引擎按目录/文件名扫描） | 装载进编辑器进程，与宿主同运行时 |
| 能力面 | 读不到编辑器上下文；不注入进程、不 hook、不热替换 | 全权 `PluginContext`（`kernel.io` / `bus` / `storage` / 槽位） |
| 分发 | 本地 ZIP 由用户显式选择（首版） | 市场 v1 **不**分发；只立项不排期 |
| 可逆性 | 文件级：先备份、可卸载、可回滚到装前哈希 | 卸下即可，无盘上残留 |
| ADR-0007 前置三件套 | **不适用**：不执行代码 ⇒ 不需要代码沙箱与执行权限模型；签名属 P2 | 缺一不可 |

一句话：**游戏插件改的是「游戏下次启动时读到的文件」，不是「正在运行的进程」**。
这也正是它可回滚的前提——没有运行期状态需要收拾。

### 2. 安装 = 两阶段（plan / apply）+ 每实例单飞 + 计划过期 + 逐文件对账 + 逆序回滚

- `planInstall` **只读**：解到 `instances/{id}/tmp/{planId}/`、读清单、算文件与函数冲突、
  兼容性、存档影响、风险分级，**不碰 `game/`**；返回 planId。
- `applyInstall` 开始前重新校验：plan 未过期、实例未变、文件哈希未变、同 id 已装版本未变。
  任一变化 ⇒ 计划失效，重走预检。
- `applyInstall` **每实例单飞**：同一实例同时只允许一个内容/插件变更任务（`LAUNCHER_TASK_BUSY`）。
- **逐文件哈希对账**：计划里展示的「将覆盖 N 个基础文件 / 将覆盖 M 个函数」与实际应用必须逐条对得上；
  数量变了即视为计划失效。
- **逆序回滚，不整目录删**：失败时逐文件核对哈希后再删/恢复。整目录删会连带删掉用户后来放进去的文件
  ——那是不可逆伤害，比安装失败本身更糟。
- 首次安装写 `backups/packs/{packId}/original/`（已存在则**不动**，保证卸载能回到最初）；
  本次操作写 `{timestamp}/` 供回滚。升级不得覆盖 `original/`。

### 3. 函数级冲突：比对键是归一化名，「有意重复」走 adapter 的 `conventionPolicy`

- **比对键 = `ErbFunction.normalizedName`**（`plugin-api/src/erb.ts`；Emuera 系函数名大小写不敏感）。
  拿原样名比会漏掉 `M_KOJO_K1` vs `m_kojo_k1` 这类撞车——漏报比误报更危险。
- **「有意重复」不另立名单**：判据与 `convention-linter` 的 `erb.duplicate-function` **同源**，
  由当前 adapter 的 `GameAdapter.conventionPolicy`（`ConventionSuppression[]`：`ruleId` +
  `names` / `namePattern` + **必填** `reason`）收敛。启动器只消费，不新增宽容表。
  真盘证据：eraSQC **190 处**（EVENTTRAIN 91 + EVENTEND 90 + 1）、eratohoK **2 处**。
  若启动器自建一份白名单，两份判据迟早分叉：linter 说「有意重复」，安装说「冲突」。
- **文件冲突与函数冲突不重复计**：插件整体覆盖了定义该函数的基础文件时，按文件冲突处理
  （用户已决定替换整份文件），不再重复报函数冲突；函数级冲突只针对「新增/叠加文件里重新定义了已有函数」。
- 默认 `abort`；`skip`（保留既有定义）/ `replace`（先备份旧定义所在文件再覆盖）必须**逐条**选择，
  不提供「全部同意」。
- 启用 / 调序前**重跑**冲突检查：装的时候不冲突，不代表同时启用不冲突（`LAUNCHER_PLUGIN_CONFLICT`）。

### 4. 存档影响门禁

- 清单 `saveImpact`（`none` / `possible` / `unknown`）缺省 **`unknown`**——按最坏情况处理。
- `saveImpact != 'none'` ⇒ `applyInstall` **先备份存档**（`reason='pre-plugin'`）；
  **备份失败即中止**（`LAUNCHER_PLUGIN_SAVE_RISK`），不「先装上再说」。
- 卸载**不删存档**：插件写入的数据可能仍被旧存档引用。卸载结果必须给出
  「该插件声明过存档影响，旧存档可能无法在无插件环境读取」的提示，并保留 `pre-plugin` 备份。
- 用户未确认存档影响 ⇒ `abort`；`acknowledgeSaveImpact` 缺省 `false`（宁可拒绝，不可默认放行）。

### 5. 风险分级只由「清单能力 + 实际落点」推导

| 级别 | 判据 |
|---|---|
| `content-only` | 只追加、不覆盖任何既有文件 |
| `extends-logic` | 新增函数/命令/数据，或覆盖但不删除既有定义 |
| `overrides-logic` | 覆盖/替换既有脚本函数或资源 |
| `unknown` | 清单缺字段或无法判定；按**最高**风险展示，装前必须逐项确认 |

- 声明与实际不符（例如只声明 `add-content` 却覆盖基础文件）⇒ **按实际升风险**并记 warning；
  **不信任声明**。core 不读脚本内容（那会变成第二套语义解析），只看清单与落点。

### 6. 信任链分级

- **首版只接受本地 ZIP**（原生文件对话框选择），不做静默下载安装；
  展示发布者、来源、文件清单与风险，`trust.state='unverified'` **如实显示**。
- **P2**：包签名 + 发布者公钥信任库；验签通过才允许「自动更新」，否则每次更新重新确认。
- **「来源像官方」不是授权**：来源域名与签名是证据，不能替代「装之前看清楚」。
- `LAUNCHER_PLUGIN_UNTRUSTED` 是 P2 的码；首版不拿它假装已有验签。

### 7. 明确不做

进程注入、DLL hook、内存修改、运行中热替换；静默安装；自动下载并安装任意 URL 的包。
**游戏如何发现插件（首版诚实边界）**：只支持「游戏自己按目录/文件名扫描」的加载方式，
由 adapter 的 `orderSource` + `entrypoints` 表达。若某游戏必须改注册表 / 配置行才能启用插件，
adapter 不提供 `pluginRules`（或显式声明不支持），启动器显示「该游戏暂不支持插件安装」。
**不支持就说不支持**，不假装装完能用。

## 备选方案（为何不选）

| 方案 | 为何不选 |
|---|---|
| 插件一律不得覆盖基础文件（只允许 `add-content`） | 堵死主场景（插件的用途就是改逻辑），用户会退回手工复制——没有清单、没有备份、没有回滚，更危险；否 |
| 把游戏插件纳入 ADR-0007 的前置三件套 | 游戏插件不执行于编辑器或游戏进程，代码沙箱对它无对象；套上去只会把这条线无限期卡死；否 |
| 用原样函数名比对 | 大小写不敏感引擎会漏报真实冲突；否 |
| 启动器自建「有意重复」宽容名单 | 与 `erb.duplicate-function` 判据分叉，真盘上 190 处会刷屏或反被吞；否 |
| 安装确认页「全部同意」一把梭 | 逐条决议是唯一能让用户看见「改哪几个函数/文件」的形式；否 |
| 装前不备份存档（提示用户自负） | 一次不可逆的存档污染就可能让玩家丢进度；备份成本远低于代价；否 |
| 首版就上包签名 | 没有公钥分发与吊销机制时只是**假安全**（与 ADR-0007 对 `permissions` 字段的判断同源）；P2 |
| 卸载时顺带删除插件写入的存档 | 删的是玩家的进度，不是插件的数据；否 |

## 后果与前置

**后果**：

- 「安装」是与「启动」同级的一等特权动作：必须停游戏（`LAUNCHER_INSTANCE_BUSY`）、必须有计划、
  必须可回滚。任何「装完再提示」的路径都不合法。
- `shared` 实例安装需要对应根的写授权（ADR-0008 的第三张表）；`copy` 实例写在实例根内。
- 构建产物（ADR-0010）**不是免检理由**：同样过 ZIP 四重守卫、`pack.json` 哈希核对与本节全部门禁。

**前置**（未满足前不得宣称已落地）：

1. **安装前脏缓冲检查（P1 硬闸）**：编辑器正打开同一根时，watcher 只能告知「盘上变了」，
   拦不住用户拿旧缓冲把插件改动写回去；命中脏缓冲必须阻止安装并提示保存/放弃。
2. `analyzeFunctions` 必须由 adapter 经 `erb.parser` 服务键或库包（`@kojo/kojo-core` /
   `packages/erb-syntax-tree`）取函数索引；**壳层 `monaco/tree-sitter` 不可 import**（那是应用壳）。
   解析失败必须抛错，不许返回空数组假装「没有函数」。
3. ZIP 限额尚无真实 P95（§16 风险 6）：未定值前不做下载安装，本地 ZIP 也走共享判据表。
4. `shared` 授权链与 `approvals.json` 落地（ADR-0008）。

**未解缺口（按问题记，不按计划记）**：跨包函数依赖图（P2）、存档兼容检查（P2）、
签名与公钥吊销（P2）、多插件同名函数的「谁生效」诊断页（P1 诊断，P2 依赖图）。

**验收含义**：计划展示与落盘逐条对账；卸载后文件哈希回到装前；`saveImpact != 'none'` 时
备份存在性与「备份失败即中止」；同名函数 fixture 默认 `abort`，`replace` 前有旧文件备份；
`conventionPolicy` 命中的真盘重复不计入冲突（eraSQC / eratohoK 两例为金样本）。
