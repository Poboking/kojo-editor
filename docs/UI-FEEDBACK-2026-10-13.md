## 二、第 4 项：糖视图改为「虚拟文档」的提案（**待用户拍板，勿在补测批里顺手做**）

**方向**：不再用 ViewZone 贴糖文本，而是给一份只读的**虚拟 model**（非 `file:` URI，专用 languageId），
内容 = 糖文本；原文行紧随其后并按 ADR-0006 默认收起。这样原生拿到字号、字体、折行、缩进、光标与滚动，
对齐问题从"要修的症状"变成"不存在"。

**必须付的三笔代价**（都在代码里可指认）：

1. **行号坐标系换了**。`editor.revealLocation` 现在把行号当真实行用（`App.tsx:96` → `ProjectView.tsx:309` →
   `EditorPane.applyReveal:323-333`），波浪线、状态栏行数、跳转全部要经映射。
   现契约 `SugarProjectSegment` 只到**段粒度**，承载不了行级映射（ADR-0006 §后果 同一条），
   ⇒ 需要 **additive** 字段（如 `lineMap: {sugarLine: number; sourceLine: number | null}[]`），**这是糖组的实现面**。
2. **保存链必须拒绝虚拟文档**。`pickSaveHandler`（`EditorPane.tsx:63-80`）按路径 `matches()`，
   `.erb` 结尾的虚拟路径会被 `.kojo` 保存接管者或内核缺省 `writeText` 认下来 ⇒ 一旦写盘就是**改坏游戏文件**。
   落点是给虚拟文档独立 scheme（如 `sugar-view:<真实路径>`），宿主在保存 / 脏标记 / 标签标题三处分支。
3. **同一 model 只能一个 languageId**。原文行若按糖语法着色会错（大写指令 / `%…%` 在糖语法里不是那个意思）。
   可行解：新增一个双态 Monarch（行首匹配「全大写指令 / `#` / `@` / `$`」进 ERB 态，否则进糖态），
   复用 `kojo-language.ts` 的词表单一真源；不新建第三套词表。

**建议的最小顺序**：先落第 5 项（现方案下的折叠柄 + 已收起行数可见，纯宿主、无契约），
再做第 4 项（要契约，须糖组实现 `lineMap`）。两者合流后，"展开原文"就是取消 `setHiddenAreas`，不需要第二套机制。

**要用户回答的三个问题**：
- (a) 原文行是否也写进虚拟文档？（写了才能靠隐藏/显示实现展开；副作用是 Ctrl+F 会搜到拼接文本）
- (b) 是否同意给 `SugarProjectSegment` 加 additive 行级映射（糖组实现、宿主消费）？
- (c) 状态栏/行列显示哪套行号？建议：显示行号为主 + 悬停给「原文第 N 行」。

## 三、第 6 项的定性路径（避免把"没反馈"修成"没功能"）

真实壳里要区分两种失败，它们的修法完全不同：

- **接线失效**：点击后菜单项根本没执行（抛异常 / 事件没绑） ⇒ 修宿主。
- **反馈缺失**：`revealAll` 确实执行了，但对**目录内容已全平铺**的包，展开后看不到任何新行
  （`.pkg-real` 用 `skip` 去掉已平铺的 ERB，`FileTree.tsx:56-62` + `:383`）⇒ 用户读作"没生效" ⇒
  修的是**可见反馈**（例如给出「已展开 N 个文件夹 / 未发现额外内容」的显式提示），而不是接线。

探针断言因此是三条并列：无异常抛出、菜单已关闭、`.pkg-real` 或嵌套行数确有增加；
外加一条专门量"展开了但内容为空的包"的个数。**读数以本文件补记为准。**

## 四、第 7 项：ERB 结构错误波浪线的规格（本批实现）

**精度原则**（沿用本项目一贯口径：错标比不标危险，宁少勿错）：只报**可证明**的结构错误——

1. 孤儿闭合语句（`ENDIF` / `REND` / `ENDSELECT` / `ENDCATCH` / `ENDFUNC` … 找不到对应开块）；
2. 文件/函数结束仍有未闭合开块（指到开块行）；
3. 分支语句出现在其所属开块之外（`ELSE` 不在 `IF` 链里、`CASE` 不在 `SELECTCASE` 里）。

**不报**：未知变量名、未知函数名、`CALLFORM` 悬空引用——这些要么需要全库语义、要么引擎本身宽容，
报出来就是误报农场。**配对表一律复用 `erb-parser/scanner.ts` 的 `OPEN/BRANCH/CLOSE/TRY_*` 现有表**，
不在别处再抄一份（两处表必然漂移，这是本项目写过的教训）。

**落点**：结构判定作为 `erb-parser` 的纯函数（表在它手里），经 `ErbParserService` additive 暴露；
波浪线由 `ui.editor.decorator` 通道进宿主 `refreshMarkers` ⇒ **宿主零改动**即见效。
`.kojo` 侧已有糖语法诊断（23 码闭集 + 判定面板），本项只补 ERB。

**性能门槛**（不是猜测，要有实测）：波浪线走既有 `MARKER_DEBOUNCE_MS = 250` 去抖；
超大文件按既有降级口径处理，并给出**真实耗时读数**，不允许"输入即卡"。

## 五、实机测试认领与协作约定（对其他 Agent）

1. **实机测试由本 Agent 负责并持续认领**。需要真实桌面壳结论的改动（布局、拖拽、快捷键、输入法、
   Monaco 渲染、文件树交互），把期望写清楚交给我，我按下面方式给读数，不以读代码代替实测。
2. **方法**：`pnpm --filter @kojo/app tauri dev` + WebView2 CDP（9222）在页面里派事件、读 DOM 形态与
   `localStorage`，必要时 `Page.captureScreenshot` 出图。探针是**一次性工具，放 `%TEMP%`，不入库**；
   但探针的**断言清单与读数必须随批贴进 IMPLEMENTATION-LOG**。
3. **仪器纪律**（本批踩过，别再来一遍）：先自检仪器再取读数——合成事件是否真带上了
   `isComposing` / `keyCode`；选择器别用精确文案匹配（工具条 title 带「 (Ctrl+J)」后缀）；
   查 DOM 前必须等首屏与索引就绪；"点击没反应"要同时抓 console 异常，否则分不清接线与反馈。
4. **量「改前」用 `git worktree add <临时目录> HEAD --detach` 起游离树**，不要动别人的工作副本
   （`D:\DSH\kojo-editor`）——本工作区是共享的，别人正在往里提交。
5. **文件边界（我承诺遵守，也请对方留意）**：
   - 我做：宿主壳层 `packages/app/src/ui|monaco/*`（除糖渲染语义口径）、内核与契约的 **additive** 改动、
     UI 面板交互、口上项目线。
   - 不碰：`kojo-sugar` 的转译/投影语义、`ui-sugar-*` 的判据、糖视图**口径**（ADR-0005/0006 的白名单与
     折叠判据）、索引性能路线。需要在这些里面加东西时，我只提 **additive 契约**并把实现需求写进本文档。
   - `EditorPane.tsx` / `styles.css` 是历史冲突热点：改前 `git fetch` + `git status` 确认干净，
     改时保持最小机械改动，同文件多次编辑**串行**且改完读回。
6. **编号纪律**：写 IMPLEMENTATION-LOG 小节前先 `git fetch` 再取当前最大号 +1；撞号时后入库者顺延，
   并在自己的小节头注记让位事实。**本批占用 §5.72**（前一节是 §5.71，P4 补测批）。
7. **提交与推送**：逐文件 `git add`（禁 `add -A` / 禁 `stash`），Conventional Commits 中文标题，
   root version 保持 `0.1.0`。`git push` 会把**别人未推送的提交一起带上去**，因此：推送前先
   `git fetch` + rebase，并在提交信息里点名包含了谁的提交；网络不通时用 `node tools/git-push.mjs`（绕坏代理）。
8. **验收口径**：任何"改好了"的说法必须带数——全量测试数、双 typecheck、审计、app build、
   真实壳断言清单读数。糖投影六把尺子的读数若与本批无关，也要复跑证明没被带偏。
