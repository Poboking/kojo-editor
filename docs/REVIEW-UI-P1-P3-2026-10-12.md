## 三、值得肯定的设计

1. **契约全部 additive，缺省即现状**：`ui.panel` 新增 `location`/`defaultActive`/`group` 全 optional；未声明 `location` 回落 `sidebar`——第三方插件**零改动仍可用**，无「必须同步改所有插件」的窗口期。这是本线最重要的工程纪律。
2. **宿主零业务知识**：快速打开候选是**泛型路径列表**，壳层不认识「口上」；「新建口上文件」的命名知识全住 `ui-sugar-editor`，并经 adapter `kojoFaceTemplates.registration.declare` 推导、**fail-closed**（缺表即显式不可用，不猜）。对照 DSH「一切皆插件」，边界干净。
3. **布局状态不进内核存储域**：`kojo.ui.layout.v1` 住壳层私有 `localStorage`——布局是宿主形态而非业务数据，归属正确。
4. **命令单一真源**：快捷键 / 命令面板 / 工具栏按钮同指一份注册表，工具栏**只引用命令 id**，杜绝「按钮能用、快捷键失效」的漂移。
5. **多标签的稳定性设计**：model 常驻内存 + `saveViewState`/`restoreViewState` + 逐 model `getAlternativeVersionId()` **O(1)** 脏判定——切换零丢失、判定零 diff 开销（BUG-4 方案的纵深延伸）。
6. **供给与执行分离**：codeAction 的 `run` 以 id 反查最新动作并**重读盘**再应用（供给与执行之间用户可能编辑）——沿用 §5.37 的「执行前重读」纪律，是防闭包过时的正确姿势。
7. **不假装可点**：诊断计数点击暂只给 `Ctrl+J` 提示而非静默无反应——**宁可显式提示，不做假交互**。
8. **迁移不丢功能**：💡 升糖上线后，aux 兜底面板**保留**（`defaultActive:false`），避免「面板迁移即能力消失」。
9. **事件白名单教训已被吸收**（`0bf2eb9`）：新增内核事件 `ui.overlay.open`/`ui.overlay.close`/`editor.activeFileChanged` 未同步进 `KERNEL_EVENT_NAMES` 会导致 `scopedBus.emit` 抛错、向导链断裂——已补全并在 HANDOFF 记为纪律条目。
