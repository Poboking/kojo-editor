# 升糖重定位与实现重做 · 需求定稿

- 日期：2026-10-12
- 状态：需求已确认。补充3 自动分流**尚未实现**，且 1.4 旧设计（工具栏按钮）已删除
- 来源：用户 2026-10-12 口头需求，本文为唯一口径

---

## 背景

现版升糖功能存在两个根本问题：

1. **定位错误**：升糖会把糖写法**写回源文件**。但 ERB 是 Emuera 认识的格式，糖写法游戏根本不认——写回去除了搅乱原文件没有任何收益。
2. **识别失效**：预筛规则过度严格（块内出现注释或空行就整块跳过），对绝大多数真实口上文件识别不出任何候选。用户实测结论：「用过之后只觉得一点用都没有，废物功能一个。」

本文定稿两个改动方向：**一点是升糖的定位重做，二点是升糖识别的实现重做。**

---

## 第一点：升糖重定位 —— 升糖只用于「看」

**核心一句话：编辑器不再改写 ERB 原文件，升糖结果只是显示给你看的。**

### 1.1 原则：编辑器默认不写 ERB（补充2，立为原则）

- 编辑器**默认不写入 ERB 文件**。
- 在此前提下，ERB 的升糖就合理了——**只用来预览**。
- 真要把改动落盘写入时，**默认把原 ERB 文件转为 `.kojo` 文件**，在 `.kojo` 上写。

### 1.2 展示效果：折叠 + 打字机效果 （补充1）

打开 ERB 文件后：

- 能升糖的片段，其原始 ERB 文本被**折叠**（前端效果，参考现代编辑器里 if 代码块的折叠）；
- 折叠处**上方**就地显示升糖后的语法糖写法（ViewZone 显示糖写法（打字机效果，快速））
- **点开折叠**后，能**同时**看到：上面的语法糖写法 + 下面的原有 ERB 文本（附注视觉效果），方便逐行对照。

全程纯前端显示，**不改原文件一个字节**。

### 1.3 用户要编辑 ERB 时怎么办（补充3，重写版）

> 旧设计（工具栏放「强制编辑 ERB」按钮让用户自己点）**作废**——那是把系统的责任抛给用户。

新设计：**检测到用户要编辑 ERB 文件时，系统自动分流，用户无感**：

- **分支1（默认）**：自动把该 ERB 文件转为 `.kojo` 文件，用户的编辑在 `.kojo` 上进行，语法糖功能照常可用；
- **分支2**：用户在设置里**关闭了「自动转 `.kojo`」**，此时弹出提示：「编辑 ERB 文件将禁用语法糖」——确认后才允许编辑，编辑期间语法糖功能关闭。

### 1.4 已作废的旧设计（现有代码里的，待改）

| 旧设计 | 作废原因 |
|---|---|
| 工具栏「强制编辑 ERB」按钮 | 把选择负担丢给用户；应改为 1.3 的自动分流 |
| 升糖候选「应用」写回源文件 | 糖写法游戏不认，写回无收益且搅乱原文件 |
| 面板里的勾选三态 / diff 视图（写回路径配套） | 写回路径摘除后失去存在意义 |

## 第二点：升糖识别实现重做 —— 换 tree-sitter

**核心一句话：不再在手写解析器上修修补补，预筛和解析直接换 tree-sitter + C 语言解析器（外部扫描器）。**

### 2.1 问题

- 现有 `erb-parser` 的手写扫描器预筛过度严格：块内出现注释或空行即整块跳过并标记已消费，导致真实口上文件大量 PRINT 行无法被行级扫描单独提升；
- `@` 函数边界深度栈不重置；结构预筛在注释密集、深嵌套、多函数的真实文件上过度拒绝候选，实际命中率极低。

### 2.2 方案

- 预筛策略直接上 **tree-sitter + C 语言解析器（external scanner）**；
- 没有现成的 Emuera ERB grammar，需要自研 grammar + C external scanner；
- 运行时用 `web-tree-sitter`（wasm），需验证 Windows 下构建链可行性（`tree-sitter build --wasm`，可能涉及 emscripten/docker）。（批注：一定需要wasm吗？）

### 2.3 实施前置

1. 先做**构建链最小验证**（探针）：一个最小 grammar + 最小 external scanner 能否在 Windows 构建出 wasm 并在应用内跑通；
2. 探针通过后再写 ERA/ERB grammar，替换 `erb-parser` 的预筛实现。

## 已知设计缺口（实现 1.3 分支1 前必须解决）

**ERB → `.kojo` 全量转换器目前不存在。**

- `.kojo` 表层语法支持 `@` 原生函数块与顶层原生行**透传**，所以装下完整 ERB 内容没问题；
- 但**糖写在 `@` 原生块内不会被编译**——要转换后的 `.kojo` 真正可用，必须把时机体内的可升糖片段还原成真正的 `时机` 块糖语法；
- 这需要一个**反编译器/适配器**（ERB AST → `.kojo` 糖文档），是 1.3 分支1 的核心工作量，不是简单改个扩展名。

## 验收口径（两点共同的底线）

1. 升糖预览全程**零写盘**（源文件逐字节不变）；
2. 升糖候选只展示 round-trip 逐字节自证通过的片段，未建议区间显式列出、不静默；
3. 1.3 的分流对用户无感：默认路径下用户不需要做任何选择就能编辑并保留语法糖能力；
4. tree-sitter 替换后，预筛对真实口上语料的候选命中率必须有**量化提升**（对比改造前后在同一批文件上的候选数/跳过数），不接受「跑通就行」。
