## 1. 生态事实底座（有语料背书，实测）

- 配布单位 = **一个文件夹 = 一个作品包**；上游以压缩包发布（README + ERB，有时带资源）。
- 实测规模：**155 角色目录 / 193 作者包 / 2,285 ERB / 554 非 ERB**；**85.5% 的包含 README 类文档**。
- 包名三形态：①作品/作者名 ②角色名 ③角色名+版本日期。
- **署名在 README 正文**（`作者 holy / 最終更新 2023/10/07`），**不在目录名**；`ライセンス.txt` 出现频次很高。
- 面（文件名后缀）分层：核心 8（イベント/日常系コマンド/性交系/奉仕系/愛撫系/絶頂/刻印取得/セクハラ）、常见 10（弾幕勝負/カウンター/派生/依頼/道具系/ハード/加虐系/育児/自慰系…）、长尾（IMAGE/日記/関数ライブラリ/UPDATE…）。
- 命名自由度三维度：**语种**（日语/英语/中文）、**分区编号**（`コマンド000～愛撫`）、**章回体**（`第1章[…]`）。
- 四件套 `FLAGSETTING/COLOR/ENCOUNTER/EXTRASOURCE` 是**函数级**（家族内），不是独立文件。
- 非 ERB 附件构成：`.txt` 475 · `.ERH` 31 · 无扩展名 21 · `.7z` 13 · 图片 6 · `.zip` 3 · `.rar` 2 · `.csv` 1。
- **边界/反例（解析器必须兜底）**：20 个角色仅 `HOGE` 占位；`159 先代` 无包目录直接堆 ERB；包内文件名不总合规（`NO.1M_KOJO_K97_OwO_事件系.ERB`、`KOJO_ZDHS_K43_1153.ERB`、`飞刀版COUNTER系.ERB`）；`K1[]` / `KX` 角色号占位；多剧本编号 ≤10。

## 2. 核心架构决定

**对偶 + 引用关系**

```
口上项目（作者工作区，可写）  ──引用──▶  游戏项目（eraTW 实例，只读）
  新建 · 编辑 · 组织 · 导出                家族模板 · 面定义 · 变量 schema · 状态回放
```

三条硬约束：

1. **`export.target`** **槽已存在**（[slots.ts](file:///c:/先前项目/kojo-editor/packages/plugin-api/src/slots.ts#L294-L324)），ZIP 导出直接落位，不发明新槽。
2. **新概念不进** **`eratw-adapter`**：adapter 只说"这个游戏的口上长什么样"；"作者怎么组织自己的包"是通用能力 → 新服务/新插件。
3. **内核零游戏知识**：项目模型只有 `workspace / project / artifact`，禁 `口上 / kojo / M_KOJO`；包结构模板由适配器/专用插件提供。

其他已定：

- **项目权威，游戏目录 = 部署目标**（你认可）。
- 写保护铁律不破：游戏目录默认只读，作者工作区独立。
- **左侧保留两个根节点**（`我的口上项目` / `游戏语料`）共存，而非替换——避免老用户迷失。
- 界面现状：左侧 = [ProjectView.tsx](file:///c:/先前项目/kojo-editor/packages/app/src/ui/ProjectView.tsx#L142) 内建「口上文件」树 + 函数树，`group:'explorer'` 合并、上下弹性分栏；[FileTree.tsx](file:///c:/先前项目/kojo-editor/packages/app/src/ui/FileTree.tsx#L42) **已有**「角色 → 作者包 → 文件」三级雏形。

## 3. 左侧口上树设计（你本轮的方案，已采纳为定稿方向）

- **默认态 = 现状**：角色 → **作者包节点（可折叠，默认折叠）** → 面文件。
- **避免歧义，作者包节点**示例：`<span class="tree-author-name">灵梦-少女之梦 20</span>`。
- **点击 作者包节点 → 原地展开为真实文件夹视图**：`README / ライセンス / 面文件 / 附加文件 / 资源`。
- **备用路径**：**右键** 口上树**→ "查看被隐藏的文件和文件夹"**，给需要看全貌的人一条通道，而默认界面保持清爽。

> 设计意图重申：默认折叠不是"藏信息"，而是把「借阅找思路」和「看清一个包的全貌」拆成两个动作层级。
