# 第一部分 设计规范

## 0. 定位：eraTW 先做好，SDK 同步打底

### 0.1 eraTW-first，不是 eraTW-only

1. **先把 eraTW 的语法、产物、取色、等待、事件、编码做到全绿**；
2. **同时把 core / adapter / SDK 的边界定清楚**，因为边界会反过来影响语法；
3. 再用第二个、第三个 adapter 验证"通用口上表面"；
4. 最后才谈特性包、方言、市场。

所以：

- eraTW 专属的演出、事件、文本载体，**不因为"通用"而被削掉**；
- 但它们不能写死进 core 的 AST / 诊断 / emitter；
- 它们要成为 eraTW adapter 的 `presentation`、`eventCatalog`、`profile`、`poolStyle` / `randStyle`。

### 0.2 单一模式：Kojo 2.0 就是当前语言

- **没有旧版文件模式。** 编译器没有"按旧版编译"的分支。
- **没有旧版验收。** 所有源文件、所有产物、所有测试都以 2.0 为唯一基线。
- **没有版本声明。** 编译器只认 2.0；不存在"按版本号切换语法"的路径。
- **旧文件必须迁移。** 迁移工具只改源码，不保留旧语法层；迁移后的源文件就是 2.0，旧写法不再合法。
- **旧写法一律 error + 一键迁移。** 迁移是转换，不是保留旧语法；编译器不会在运行期或编译期保留旧语法分支。

### 0.3 三层表面：叙事面、程序层、原生层

| 层 | 谁在用 | 内容 | 依赖 |
|---|---|---|---|
| **叙事面** | 口上作者 | `#` 声明、`角色：`、`>`、`?`、`!`、`# 表`、`# 池`、`# 模`、`@算`、`@随机`、`@着色`、`@颜绘`、`@织` | core |
| **程序层** | 需要循环/数组/跳转/递归的作者 | `@循`、`@断`、`@续`、`@标`、`@跳`、数组、`@巡`、`@复`、`@函`、`@返` | program extension |
| **原生层** | 需要底层 ERB 的作者 | `@原生` 缩进围栏，逐行直通 | 永远可用 |

叙事面是正文的默认路径；程序层是后台账本和复杂机制的 canonical 写法；原生层是逃生舱。三层共享同一份 source map，不互相污染。

### 0.4 完整性与替代关系

Kojo 2.0 **是替代**：

- 2.0 覆盖旧版能力：循环、标签、跳转、数据表、函数在程序层有 canonical 对应，不再只能靠 `@原生`；
- 但覆盖不等于保留：旧文件必须迁移，迁移后的产物按 2.0 规则重新生成，不以旧产物为基线；
- 旧写法在 2.0 编译器里一律 error + 迁移；没有"原样编译"模式。

图灵完备性放在**程序层**，不塞进叙事面：

- `@循` + `@断` + `@续` 提供无界循环；
- `# 变量 ... 整数[N]` + `[下标]` + `.长度` 提供数组/内存；
- `@标` + `@跳` 提供受限跳转；
- `@函` + `@返` 提供递归；
- `@原生` 作为最终逃生舱，保证任何 ERB 可表达的东西都能落地。

> **语言整体是图灵完备的；core 叙事面不要求图灵完备。**
> core 验收不需要 `@循`/`@标`/数组；program extension 验收必须覆盖它们。eraTW adapter 默认开启 program，并把它们纳入 eraTW 验收线。

### 0.5 根冲突与语料证据

旧版的叙事心智是：有 `「」` → 台词 → 作者色；无引号 → 旁白 → 默认色；行尾无 `续` → 等待。

2.0 改成：`角色：「…」` → 台词；`> …` → 旁白；`续` 控制等待。

Phase 2 读数纠正了三个过度概括（完整读数见附录 A）：

- 引号 → `FORM` 占 99.6%，但无引号行 90.1% 仍是 `FORM`、eraTW-family 只有约 50.2% 用 `D`，eraSQN/eraKoumakan 基本没有 `D` ⇒ `角色：` / `>` 显式化成立，但"旁白=默认色"不成立，必须走 profile；
- 无全局等待默认：eraSQN W/L = 13.726、eraKoumakan = 0.187；eraTW 内部 18.3% 文件 <30% W、47.0% >70% W ⇒ `续` 保留、等待默认来自 profile，独立转译器缺 profile 必须报错；
- 事件有四种架构（eraTW-family 唯一函数 / eraSQN 共享 `EVENTTRAIN` / erafl `RESULTS` 元数据 / eraKoumakan `KOJO_MESSAGE_*`，eraNTR 无口上层）⇒ `# 机` / `@织` 只定义形状，事件名走 adapter 的 `eventCatalog`，九事件只是 eraTW 参考。

**一处事实纠正（规范级）**：`PRINTDATA / DATAFORM` 是随机候选族，不是条件选择。**池 → `IF/ELSEIF/ELSE`（或可证的 `SELECTCASE`）；纯文本随机 → `PRINTDATA/DATAFORM`；有副作用随机 → `RAND + SELECTCASE`。**

## 1. 分层：core / adapter-sdk / eraTW / program extension

### 1.1 四层

| 层 | 内容 | 禁止 |
|---|---|---|
| **kojo-core** | 五个锚点、叙事/调度表面、条件、`# 变量`/`# 常量` 声明形状、`# 表`、`# 池`、`# 模`、`@算`、`@随机` 形状、`@颜绘` 形状、`@原生`、`@织` 形状、诊断、source map | 不得出现 `M_KOJO`、`TALENT`、`TARGET`、`D`、`PRINTDATA` 等游戏名词 |
| **kojo-adapter-sdk** | `GameAdapter` 契约、`eventCatalog`、`domainSymbols`、`profile`、`presentation`、`storageClasses`、`poolStyle`、`randStyle`、`encodingPolicy`、`layerPolicy`、`diagnosticNamespace`、`conformanceSuite`、`sourceMap`、`capability` | 不提供具体游戏事实 |
| **kojo-adapter-eratw** | eraTW 的九事件、CSV/ERB 符号、存储期映射、取色/等待 profile、`(心形)`、`@着色`、`@颜绘`、`选项`、随机/池落点、程序层落点 | 不把游戏事实反写进 core |
| **extension / program** | 数组、`@循`/`@断`/`@续`、`@标`/`@跳`、`@巡`/`@复`、`@函`/`@返`、递归 | 不改核心叙事语法；不做闭包/函数指针/动态函数名 |

### 1.2 Feature classification

| 特性 | 层 | eraTW | core 验收 |
|---|---|---|---|
| 五个锚点、台词、`>`、插值 | core | 支持 | 必过 |
| `?` / `? 否` | core | 支持 | 必过 |
| `# 变量` / `# 常量` | core 语法；存储期 lowering 走 adapter | 支持 | 必过 |
| `# 表` / `# 池` / `# 模` | core 语法；lowering 走 adapter | 支持 | 必过 |
| `@算`（状态更新） | core | 支持 | 必过 |
| `@随机` / `@组` | core 形状；落点走 adapter | 支持 | 必过 |
| `@原生` | core | 支持 | 必过 |
| `@织` | core 形状；事件值走 adapter | 支持 | 必过（形状） |
| `# 机` | core 形状；事件目录走 adapter | 支持 | 必过（形状） |
| `# 视` | core 形状；符号走 adapter | 支持 | 必过（形状） |
| `(心形)` / `@着色` / `@颜绘` | adapter presentation | 支持 | 不阻塞 core |

| `@巡` / `@复` | program extension | 支持 | 不阻塞 core |
| 等待 / 取色 profile | profile | 支持 | 由 profile 测试覆盖 |

### 1.3 不做游戏方言

六部语料没有一部需要"语法方言"；差异都能表达为 adapter 数据 / profile：

- 事件名与事件形状 → `eventCatalog`
- 我/你/她、角色变量 → `domainSymbols`
- 取色、等待、文本载体 → `profile`
- 心形、着色、颜绘、选项 → `presentation`
- 变量存储期 → `storageClasses`
- 池/随机落点 → `poolStyle` / `randStyle`
- 数组/循环/跳转能力 → `programFeatures`

方言只有在某个 adapter 用数据/profile 表达不了时，才允许引入；目前不引入。
（注意与 §3.3 的 `# 方言` 区分：那一枚是**跨方言共用的断言记号**，不引入任何方言语法，判据见 §12.3 同条的说明行。）

### 1.4 完整性的边界

程序层让 Kojo 2.0 具备通用计算能力，但不把 Kojo 变成通用应用语言。2.0 明确**不做**：

- 闭包、函数指针、动态函数名（动态调用走 `@原生` 的 `CALLFORM`）；
- 类、对象、继承、泛型；
- 多维数组、数组字面量、数组切片；
- 通用属性访问（只保留 `数组.长度` 这一种特殊形式）；
- 异常/线程/协程/异步；
- 跨文件导入与模块系统（先由 adapter / 工程层解决）。

这些不是"以后一定加"，而是当前 scope 的硬边界；需要时走 `@原生` 或后续 extension。

## 2. 五个锚点与词法边界

### 2.1 五个锚点

| 行首 | 名称 | 用途 | 正典例子 |
|---|---|---|---|
| `#` | 声明 | 幕、视角、机关、变量、常量、表、池、模板 | `# 表 心情 由 恋慕` |
| `@` | 调度 | 算、着色、颜绘、随机、组、循、断、续、标、跳、巡、复、函、返、原生、织 | `@算` / `@着色 0xFF8080` / `@颜绘 笑顔` |
| `>` | 旁白 | 动作、环境、心理、声音 | `> 晨光透过鸟居。` |
| `?` | 批注 | 条件分叉；`? 否` 收束条件链 | `? 恋慕 >= 500` |
| `!` | 触发 | 调用池、模板、函数 | `! 早安问候` |
| （无） | 台词 | `角色：「…」`，让对话成为视觉主角 | `灵梦：「{你}今天来得挺早嘛。」` |

`@` 家族里的 `@循` / `@断` / `@续` / `@标` / `@跳` 属于 program extension；其余是 core 或 presentation。

### 2.2 `@算` 是块头，不是每行锚点

`@` 家族大多是块级的：`@算`、`@着色`、`@随机`、`@组`、`@循`、`@巡`、`@复`、`@函`、`@原生`。`@颜绘` 是单行演出指令，不是块头。

不给单行表达式加锚点；`@算` / `@函` / `@循` / `@巡` / `@复` 的缩进体内，表达式裸写（示例见 §8.1）。

- `@算` 是块头，不接行内内容。
- `@算` 不创建作用域、不偷偷造变量；`临时` 必须已声明。
- 块内不写台词/旁白；要演出，先结束 `@算`。
- `@算` 的完整定义见 §8.1。

### 2.3 `=` 与 `~` 都不是行首锚点

保留为运算符/默认值：

- `=`、`+=`、`-=`、`*=`、`/=`
- `==`、`!=`、`>=`、`<=`
- `数值=10`
- 旧写法的行尾 `~`（迁移为 `续`）

退场：

- 行首 `=`：2.0 报迁移批注，顶层状态更新用 `@算`。
- 行首/行尾 `~`：2.0 一律报迁移；行尾 `~` 迁移为 `续`，不再接受。

**返回值也只写 `@返`**，不写 `= 返` 或裸 `返`：

```kojo
@函 斐波那契(n)
    ? n <= 1
        @返 n
    ? 否
        @返 斐波那契(n - 1) + 斐波那契(n - 2)
```

### 2.4 词法边界

- 只有**行首**五个半角符号是顶层锚点；行内的 `>`、`?`、`!` 仍是普通字符或表达式运算符。
- `# 幕`、`# 机` 等声明词，`#` 与词之间**有空格**；`#DIM`、`#FUNCTION` 等原生预处理器没有空格，必须放进 `@原生`，2.0 不直通。
- `@算`、`@着色`、`@颜绘`、`@随机`、`@组`、`@循`、`@断`、`@续`、`@标`、`@跳`、`@返` 是保留控制词；原生标签必须放进 `@原生`，或用 `@标`。
- `>`、`?`、`!` 后必须跟空白（或行尾）。
- `//` 是 2.0 **整行**注释；不支持行尾注释。`;` 只作为 `@原生` 里的 ERB 注释。
- `[插槽]` 只在 `# 模` 内、行首出现时有语法意义；`[条件]` 是旧写法，2.0 不认，报迁移。
- `[ ]` 作为数组下标时只能跟在标识符/表达式之后，不能出现在行首。
- 2.0 缩进只用空格，一级 4 空格；Tab 只允许出现在 `@原生` 块体里。混用 Tab/空格缩进报错。
- 标识符：以字母、下划线或汉字开头，后续可含字母、数字、下划线、汉字；不含空白和全角标点。保留前缀 `__kojo_`。
- `@续` 与行尾 `续` 是两个字面相同、位置不同的东西：

| 写法 | 位置 | 含义 |
|---|---|---|
| `续` | 叙事/台词/旁白/空行行尾 | 不等待 |
| `@续` | `@循` / `@巡` / `@复` 体内行首 | 跳过本次循环剩余部分 |

### 2.5 花括号引用

- 叙事文本里的 `{…}` 是插值；详见 §4.12。
- 调度区表达式里，`{名字}` 是**简单名字引用**，等价于裸 `名字`；只接受单个标识符，不把整段表达式塞进花括号。例：`{目标}的好感度 += {数值}`。
- `{我}` / `{你}` / `{她}` 是 adapter `domainSymbols` 提供的域符号；不能声明成变量。
- `{角色}的<属性>` 只在 adapter 的 `domainSymbols` 声明了该属性时成立；不是通用对象模型。未知属性 error。
- `@巡` 的局部绑定（`{值}` / `{下标}` / `{角}` / `{名}` / `{项}` / `{键}`）在遍历体内遮蔽同名文件变量。

### 2.6 转义

2.0 文件里：

- 行首 `\` 把下一个字符还原为普通文本：`\> 这不是旁白。`、`\? 这不是条件。`、`\= 这不是迁移诊断。`
- 文本里的 `\{` / `\}` 输出字面花括号；`\\` 输出反斜杠。
- `@原生` 块内不做这些转义。
- 没有旧写法的转义豁免；所有文件都按 2.0 规则解析。

## 3. 文件结构与声明

（完整文件骨架见 §3.8；本节只给规则。）

### 3.1 没有版本声明

- 文件直接从声明或正文开始，不写版本号。
- 语言只有 2.0；编译器没有"按版本号切换语法"的分支。
- 旧文件由迁移工具一次性转换；迁移后源文件就是 2.0。
- 不提供"版本号缺省当某版"的兜底；未知声明一律按 `core/decl/unknown` 报错。

### 3.2 声明区规则

- **单行声明**（`# 幕`、`# 视`、`# 机`、`# 变量`、`# 常量`、`# 方言`）连续写，不空行；整组与正文之间空一行。
- **块声明**（`# 表`、`# 池`、`# 模`、`@函`、`@织`）前后各空一行。
- `@算`、`@着色`、`@随机`、`@循`、`@巡`、`@复` 是**可执行块**，按正文位置执行，不是声明。
- `# 表`、`# 池`、`# 模`、`# 变量`、`# 常量`、`@函`、`@织` 声明提升；同名声明是错误。
- 所有声明只能出现在**文件顶层**；不能把 `# 表` / `# 池` / `# 模` / `# 变量` / `# 常量` / `@函` / `@织` 写进 `@算`、`@循`、`@随机`、`# 池`、`# 模` 等块里。
- `# 幕` **不提升**：它按书写顺序建立场景序列，是文件正文的一部分。
- `# 机` 一个文件只写一个；`# 视` 一个文件只写一个（2.0 不支持幕内切换视角）。
- `# 机` 的值只能是当前 adapter `eventCatalog` 里的条目。

### 3.3 短声明词

| 声明 | 含义 | 例子 |
|---|---|---|
| `# 幕` | 场景标题/段落；多个幕按书写顺序演出，不是函数 | `# 幕 神社清晨` |
| `# 视` | 视角；声明 `{我}` 指向谁 | `# 视 灵梦` |
| `# 机` | 机关：这个文件挂在哪个引擎事件上 | `# 机 指令 310` |
| `# 变量` | 运行期变量；类型、初值、存储期 | `# 变量 临时 整数` |
| `# 常量` | 编译期常量；可用于表端点、数组长度、颜色 | `# 常量 最大好感 整数 = 1000` |
| `# 表` | 静态词条表；按表达式分档，产出文字或数值 | `# 表 心情 由 恋慕` |
| `# 池` | 条件台词池；`?` 分支，裸引号是省略说话人的台词 | `# 池 早安问候` |
| `# 模` | 编译期模板；参数 + `[插槽]` | `# 模 娇羞退场(原因)` |
| `# 方言` | 方言断言：这份文件**自证**属于哪个方言；可选、**只断言不赋值**（不产生第二真源），与解析结果不一致是 error 不是 warning；参数对 core 是不透明字符串，core 不校验它属于哪个方言 | `# 方言 <方言名>` |

### 3.4 `# 变量` 与 `# 常量`

#### 3.4.1 语法

```kojo
# 变量 <名> <类型> [= <初值>] [场景|存档|会话]
# 常量 <名> <类型> = <值>
```

```kojo
# 变量 临时 整数
# 变量 今天已触发 整数 = 0 存档
# 变量 名字 字符串
# 变量 队列 整数[10]
# 变量 队员 字符串[4] 存档
# 常量 最大好感 整数 = 1000
# 常量 亲近线 整数 = 500
# 常量 标题 字符串 = "神社的清晨"
```

#### 3.4.2 类型

| 类型 | 说明 | 默认值 |
|---|---|---|
| `整数` | 引擎整数；也用于 0/1 条件 | `0` |
| `字符串` | 文本；双引号字面量 | `""` |
| `整数[N]` | 一维整数数组，长度 `N` | 全 `0` |
| `字符串[N]` | 一维字符串数组，长度 `N` | 全 `""` |

- `N` 必须是正整数，或一个已声明的整数 `# 常量`。
- 数组下标 **0 基**；`队列[0]` 是第一个元素，`队列.长度` 是声明长度 `N`。
- 2.0 不支持多维数组、数组字面量、数组切片、数组整体赋值。
- 没有 `逻辑` 类型；条件用整数，`0` 为假，非 `0` 为真。比较表达式产出 `0/1`。
- 不做隐式类型转换。字符串与整数混用报错；需要转换时用 adapter 声明的内建函数，或走 `@原生`。

#### 3.4.3 初值与常量

- `# 变量` 的初值可选，只允许**字面量**：整数字面量、字符串字面量、十六进制颜色字面量。不得写表达式、插值、函数调用。
- 数组声明不允许初值；所有元素按类型默认值初始化。
- `# 常量` 必须有初值，只允许字面量或由其他常量组成的常量表达式；不得调用函数、不得引用变量。
- 常量可以用于：表端点、数组长度、`@着色` 颜色、条件、普通表达式。
- 常量循环引用（`A = B`、`B = A`）是编译期 error。
- 常量不占运行期存储；不生成 ERB 全局变量。

#### 3.4.4 存储期

| 存储期 | 生命周期 | 初值时机 | 典型用途 |
|---|---|---|---|
| `场景`（默认） | 一次事件/一次监听调用内 | 每次进入该单元时 | 临时计算、循环变量、局部快照 |
| `存档` | 跟随存档 | 新游戏时；读档时恢复 | "今天已触发"、长期关系值 |
| `会话` | 一次游戏进程 | 新游戏/重启时；不随读档恢复 | 本次启动内的缓存、调试计数 |

- `场景` 变量按**事件/监听调用**分配，不按函数调用分配；`@函` 被同一事件调用时共享该事件的场景存储。
- `场景` 变量在 `# 机` 场景与 `@织` 监听之间**不共享**；跨事件状态用 `存档` 或 `会话`。
- `存档` 变量的具体落点（`SAVEDATA`、`CFLAG`、`TCVAR` 或 adapter 自有槽）由 `storageClasses` 声明；未声明即 error。
- `会话` 变量在读档后不恢复；不要用它保存剧情状态。
- 旧版的 `别名` 不再是 2.0 语法；迁移工具把它转成 adapter 变量映射或 `@原生`。2.0 正文直接使用 adapter 字典里的名字，不把 `CFLAG:TARGET:1088` 写进正文。

#### 3.4.5 命名空间

- 文件作用域共用一套名字：变量、常量、表、池、模板、函数。
- 同名声明 error；不允许变量遮蔽表/池/模板/函数。
- 函数参数可以遮蔽文件变量；`@巡` 的 `{值}`/`{下标}`/`{角}`/`{名}`/`{项}`/`{键}` 等局部绑定可以遮蔽文件变量；除此之外没有块级声明。
- `{我}` / `{你}` / `{她}` 是域符号，不允许声明成变量或常量。
- 以 `__kojo_` 开头的名字保留给编译器；作者声明即 error。
- 禁止隐式声明**作者自定义名字**：对未声明名字赋值、读取、当表端点或数组长度，全部 error。
- **adapter 游戏变量是外部符号，不是隐式声明**：eraTW 的 `恋慕`、`CFLAG` 别名、adapter 字典里的变量由 `domainSymbols` / 变量 schema 解析，不需要用 `# 变量` 声明。如果确实要遮蔽同名 adapter 变量，可以显式声明；编辑器给遮蔽提示，不静默改变语义。

#### 3.4.6 与 `@算` 的关系

- `@算` 不创建作用域；它只是把一段状态更新圈出来。
- `@算` 里出现的每个名字都必须已在文件里声明，或是参数/循环绑定/域符号/adapter 游戏变量。
- 场景变量的初始化发生在单元入口，不发生在 `@算` 行。

### 3.5 `# 机`：核心只定义形状

> **机关 = 这个文件挂在哪个引擎事件上。**
> 正典写法带事件类型和参数：`# 机 指令 310`、`# 机 事件 100`、`# 机 初见`。

核心不做"指令 / 事件 / 初见"的封闭枚举；这些值来自当前 adapter 的 `eventCatalog`：

- `eventCatalog` 定义事件名、参数形状、调用方式、是否有守卫、是否共享钩子。
- `# 机` 只负责"声明本文件挂到某个事件"。
- 未知事件报错时，列出当前 adapter 的可用事件，而不是内置九事件。
- 旧写法 `# 时机 指令 310` 不再等价：2.0 报 error + 迁移到 `# 机 指令 310`。
- 2.0 一个文件只写一个 `# 机`。多个挂点拆文件；旧版多个 `时机` 块不再支持，迁移时按挂点拆分。

### 3.6 `# 视`：代词表写死

| `# 视` | `{我}` | `{你}` | `{她}` |
|---|---|---|---|
| `# 视 灵梦` | 灵梦 | 玩家 | 当前目标（可能是灵梦，也可能是别人） |
| `# 视 目标` | 当前目标 | 玩家 | **error** |
| 没有 `# 视` | **error** | 玩家（adapter 声明时） | **error** |

- `# 视 目标` 下，`{我}` 与 `{她}` 会重合，语义混乱；`{她}` 必须报错。作者要用 `{我}`，或让 adapter 在 `domainSymbols` 里声明一个第三方符号。
- 没有 `# 视` 时，`{我}` 和 `{她}` 报错；`{你}` 只在 adapter 声明了玩家符号时可用。
- 说话人可以是角色名、`{我}`、`{你}`，或 adapter 已声明的角色符号；解析不到的名字报错。
- 核心不内置 `TARGET` / `MASTER`。`{我}` / `{你}` / `{她}` 的落点由 adapter 的 `domainSymbols` 决定；未知符号必须报错，不静默映射。

### 3.7 `# 幕` 的归属

- `# 幕` 属于 `# 机` 声明的事件；没有 `# 机` 的文件不能有 `# 幕`，也不能有顶层叙事。
- `# 机` 是文件级声明，可以写在声明区的任意位置；`# 幕` 只要求文件中存在 `# 机`，不要求 `# 机` 在它前面。为了可读性，推荐把 `# 机` 放在 `# 幕` 之前。
  - 错误文案：`# 幕 需要先声明 # 机；这个文件要挂到哪个事件？`
- 多个 `# 幕` 按书写顺序演出；`# 幕` 不是函数、不创建作用域、不产生返回值。
- `# 幕` 是标签作用域的边界：`@标` / `@跳` 不能跨幕。
- `@织` 块内不能写 `# 幕`；`@函` 块内不能写 `# 幕`。
- 没有 `# 幕` 时，整个 `# 机` 文件就是一个场景。

### 3.8 一个完整文件的骨架

```kojo
# 幕 神社清晨
# 视 灵梦
# 机 指令 310
# 常量 亲近线 整数 = 500
# 变量 今天已触发 整数 = 0 存档
# 变量 心情快照 字符串 场景

# 表 心情 由 恋慕
    0..99     疏远
    100..499  平常
    亲近线..  亲近
    否        未知

> 晨光透过鸟居，斑驳地洒在石阶上。
灵梦：「{你}今天来得挺早嘛。」(微笑)

@算
    心情快照 = 心情

! 早安问候
```

## 4. 叙事区：文本三正交

### 4.1 叙事区与调度区

| 区域 | 位置 | 默认脸 | 计算怎么写 |
|---|---|---|---|
| **叙事区** | 顶层正文、`# 幕` 下、`@着色` 体内、`@随机` 候选/`@组` 体内、`# 池` 分支、`# 模` 体内、`选项` 体内 | 台词、旁白 | `@算` 块；program 控制块 |
| **调度区** | `@算`、`@函`、`@循`、`@巡`、`@复` 的缩进体 | 计算、控制、动作 | **表达式裸写**；动作可 `!`；台词/旁白显式写 |

`@循` / `@巡` / `@复` 的体内虽然默认是调度脸，但允许显式写 `>` 和 `角色：`；不允许裸文本行。

### 4.2 叙事区示例

```kojo
> 晨光透过鸟居，斑驳地洒在石阶上。
灵梦：「{你}今天来得挺早嘛。」(微笑)

@算
    今天已触发 = 1

! 记录("今天已经打过招呼了")
```

- 叙事区里出现裸表达式，读者会以为漏了符号；状态更新用 `@算` 圈起来。
- 动作仍用 `!`。
- 需要循环/跳转时用 §9 的 program 控制块，不在叙事区裸写控制流。

### 4.3 调度区的裸写规则

```kojo
@函 增加羁绊(目标, 数值=10, 理由="日常")
    {目标}的好感度 += {数值}
    ! 记录("[{目标}] 因为 {理由} 增加了羁绊")
```

- 赋值/增量直接写；数组元素赋值也直接写：`队伍状态[0] = "健康"`。
- 调用用 `!` 最清楚；裸写 `记录(...)` 允许但轻提示。
- 纯表达式（没有赋值、没有调用、没有返回、没有控制转移）报错。
- 台词/旁白用 `>` 或 `角色：`。
- `@算` 在调度区里是可选的视觉分组块，不是必需项。

### 4.4 裸行判定顺序

调度区里，裸行按以下顺序判定：

1. 以 `>` 开头 → 旁白。
2. 以 `角色：` 开头 → 台词。
3. 以 `?`、`@`、`!` 开头 → 对应结构和动作。
4. 以标识符、`{…}`、数字、`(` 开头，且含赋值运算符（`=`、`+=`、`-=`、`*=`、`/=`）→ 赋值/增量。
5. 以 `名字(` 开头 → 函数调用（允许，但建议写 `!`）。
6. 以 `名字[` 开头且含赋值运算符 → 数组元素赋值。
7. 其他 → 报错：这里像旁白又像表达式，请补 `>`、赋值运算符或 `@返`。

`@断` / `@续` / `@返` / `@跳` 都以 `@` 开头，归第 3 条。

### 4.5 台词

```kojo
灵梦：「{你}今天来得挺早嘛。」(微笑)
灵梦：「不过，{我}可没准备{你}的早饭哦。」(别过头)
```

- 说话人 + 全角冒号 + `「」`。
- 每句台词重复说话人；不提供省略说话人的连续台词。
- 说话人可以是角色名、`{我}`、`{你}`，或 adapter 已声明的角色符号；解析不到的名字报错。
- `你：「…」` 是玩家台词的 2.0 写法；`你` 作为普通说话人解析，不再走旧版 `心形` 块内"剥前缀"的特殊路径。
- 台词内可以写 `{…}` 插值。
- 台词行尾可以挂一个表演提示，见 §4.8。

### 4.6 旁白

```kojo
> 晨光透过鸟居，斑驳地洒在石阶上。
> 灵梦拿着扫帚，心不在焉地扫着落叶。（叹气）
```

- `>` + 空格 + 正文。
- 旁白里的插入语用全角 `（……）`，它是正文，会打印。
- 旁白行可以带 `{…}` 插值。
- `>` 只声明"这是旁白"，不声明颜色；颜色由 `narrationColor` / `colorMode` 决定。

### 4.7 文本三正交：speech / color / wait

`>` 只声明"这是旁白"，不声明颜色；`角色：` 只声明"这是台词"，不声明等待。

| 轴 | 写法 | 落点 |
|---|---|---|
| **speech** | `角色：「…」` / `> …` | 台词 / 旁白 |
| **color** | `profile.dialogueColor` / `profile.narrationColor` / `adapter.colorMode` | 作者色 / 默认色 / plain |
| **wait** | 行尾 `续` / 无 `续` | 不等待 / 按 `profile.waitDefault` |

空行也遵守同一套等待规则：

| 写法 | 打印 | 等待 |
|---|---|---|
| `空行` | 一个空行 | 按 `profile.waitDefault` |
| `空行 等待` | 一个空行 | 强制等待 |
| `空行 续` | 一个空行 | 强制不等待 |

- `空行 续` 在 2.0 **保留**，不再迁移成 `空行`；两者语义不同。
- `空行` 是语句，不是物理空行；物理空行仍然结束条件链。
- 旧 `旁白色` / `口上色` 不再写进 2.0 脚本；迁移到 project/file profile 的 `narrationColor` / `dialogueColor`。
- 没有 `waitDefault` / `narrationColor` 的独立转译器必须报错，不能静默选。
- 同一个 `>` 旁白，在 eraTW 可以落 `PRINTFORMDW`，在 eraSQN/eraKoumakan 可能落作者色 `PRINTFORML` 或 plain `PRINT`；这是 adapter profile 的事，不是语法的事。

### 4.8 表演提示：`(心形)` 与 adapter presentation

- 台词或旁白行尾的半角 `(…)` 是**表演提示**。
- `(心形)` 是 eraTW adapter 声明的已知提示：这一行改用 `HPH_PRINT`；模式由台词/旁白与 `续` 决定（`w/l/dw/dl`）。
- 未知提示（`(微笑)`、`(别过头)`、`(叹气)`）是导演批注，不打印；保留在 source map 与产物 `;` 注释里。
- 旁白内部的 `（……）` 全角括号是正文，会打印。
- 单独一行 `(心跳声)` 不合法：写 `> （心跳声）` 打印，或挂到某句台词/旁白行尾。
- 一行只挂一个行尾提示组。
- adapter 没有声明 `心形` presentation 时，`(心形)` 必须报"当前 adapter 不支持"，不能生成无效 ERB。

```kojo
灵梦：「其实……{我}一直在等你。」(心形)
> 她别过头，耳尖红了。(别过头)
```

> **规范级约束（2026-10-21 语言实现审阅补充）**：`(心形)` 落 `HPH_PRINT` 时，作者文本要按引擎 `ReadString` 语义编码（`"`、`\` 必须处理）；不可安全表达时 fail-closed 报 error。任何"作者文本进入引擎字面量"的路径（心形、`# 表` 引号值、`# 模` 参数替换、`# 池` 台词）都走同一个编码器，不允许逐处手写转义。

### 4.9 2.0 叙事区硬规则

2.0 文件里，叙事区只接受这些脸：

| 允许 | 说明 |
|---|---|
| `角色：「…」` | 台词 |
| `> …` | 旁白 |
| `# 池` 内的裸引号 | 省略说话人的台词，默认 `{我}`，局部区 |
| `选项` 内的 `「标签」：` | UI 字面量，局部区，待定 |
| 行内 `{…}` / `{条件 ? A : B}` | 插值 |
| 行尾 `续` | 不等待 |
| `空行` / `空行 等待` / `空行 续` | 显式空行与等待控制 |
| 行尾演出提示 | `(心形)` 等；由 adapter 支持 |
| `?` 条件链 | 条件分叉 |
| `! 池名` / `! 模名(...)` / `! 函名(...)` | 触发池、模板、函数 |
| `@算` / `@着色` / `@随机` | 状态更新、演出、随机 |
| `@循` / `@断` / `@续` / `@标` / `@跳` / `@巡` / `@复`（program） | 控制流；feature 开启时可用 |
| `@原生` | 原生逃生舱 |
| `# 表` 引用 | 值查找 |
| `// 注释` | 整行注释 |

以下旧写法**一律 error + 一键迁移**，完整对表（全部条目与目标写法）见 §12.1；本表只列"叙事区允许的脸"，不重复迁移条目。

`选项` 是唯一例外：它是 **2.0 待定 UI**，不是旧语法例外；保留为局部字面量区，使用时报"待定 API"warning。

### 4.10 迁移只改源码；裸引号/裸旁白一律报错

- 迁移工具只做源码变换：读旧文件、写 2.0 文件；不生成旧语法分支，不保留旧语法解析器。编译器只认 2.0，旧写法不进入 AST/产物，迁移完成前不编译。
- 没有分期接受、没有"旧文件例外"；旧写法不参与 2.0 golden，只参与迁移测试（报错、自动修复、修复后可编译）。
- 裸 `「…」` 与裸文本旁白在 2.0 报错，按 §12.1 迁移；唯一局部例外是 `# 池` 里的裸引号（正典）与 `选项` 里的 `「标签」：`（UI 字面量，待定）。

### 4.12 插值：`{…}` 与 `{条件 ? A : B}`

- `{…}` 只出现在叙事文本、字符串字面量和调度区表达式的"名字引用"位置。
- 叙事文本里的 `{…}` 可以是表达式：`{恋慕 + 10}`、`{心情}`、`{条件 ? "A" : "B"}`。
- 调度区里的 `{名字}` 只接受单个标识符，等价于裸名字；不把整段表达式塞进花括号。
- 三元条件表达式只在插值/表达式中使用；不在条件链里替代 `?`。
- 字符串字面量用双引号；内部 `{…}` 也插值；需要字面花括号写 `\{` / `\}`。
- 不允许嵌套花括号；需要嵌套时用括号组织表达式。
- 表值是静态字面量，不做插值。
- 未知名字、未知域符号、未知表名：error，不静默留空。

**解析优先级（从高到低）：**

1. 函数参数；
2. 循环绑定（`{值}` / `{下标}` / `{角}` / `{名}` / `{项}` / `{键}`）；
3. 文件变量 / 常量；
4. 表名（值查找）；
5. adapter 游戏变量 / adapter 角色符号；
6. `domainSymbols` 域符号（`{我}` / `{你}` / `{她}`）。

参数遮蔽变量；循环绑定遮蔽变量；文件变量/表名可以遮蔽 adapter 游戏变量，编辑器给提示；变量与表不能同名（§3.4.5），所以第 3/4 步不会真正争抢。域符号不允许被声明成变量，所以第 6 步也不会被遮蔽。`恋慕` 这类 eraTW 变量走第 5 步，不需要 `# 变量` 声明。

```kojo
> 她今天看起来{心情}。
灵梦：「{恋慕 >= 亲近线 ? "你最近……有点不一样。" : "今天也一起加油吧。"}」
```

### 4.13 空行、注释、缩进、标点

**空行：**

| 位置 | 规则 |
|---|---|
| 单行声明之间 | 不空行 |
| 单行声明区与正文之间 | 空一行 |
| 块声明前后 | 空一行 |
| 条件链 `?` 内 | 不空行；物理空行即断链 |
| `# 表` 行内 | 不空行；物理空行即结束表 |
| 场景/块之间 | 空一行 |
| `@原生` 内部 | 原样保留 |

**注释：**

- 2.0 正典：整行 `//`；可写在任意缩进。
- `//` 不参与叙事，也不进入玩家文本；产物里转成 `;` 注释，source map 保留。
- **不支持行尾注释**。台词、URL、颜文字里的 `//` 是正文。
- 注释行不打断条件链；物理空行才打断。
- `# 表` / `# 池` 内允许整行 `//`，忽略且不结束块；物理空行才结束块/链。
- `;` 在 2.0 只允许出现在 `@原生` 里；2.0 叙事区的 `;` 注释报错。
- 没有旧写法的 `;` 豁免；迁移工具负责改成整行 `//`。

**缩进：**

- 2.0 一级 4 空格；缩进必须一致。
- Tab 只允许出现在 `@原生` 块体里；Kojo 结构行用 Tab 缩进报错。
- 去缩进到同级或更浅，块结束；空行不参与缩进计算。

**标点：**

- 叙事区：全角 `「」`、`。`、`（……）`。
- 结构区：半角 `>=`、`<=`、`+`、`=`、`!`。
- 台词行尾表演提示：半角 `(心形)`；旁白内部插入语：全角 `（……）`。
- 声明标题不写冒号：`# 幕 神社清晨`、`# 表 心情 由 恋慕`、`# 池 早安问候`、`# 模 娇羞退场(原因)`。
- 条件行不写冒号；表头不写冒号。
- 对话冒号固定全角 `：`。

> **规范级约束（2026-10-21 语言实现审阅补充）**：全角标点（`：`/`＝`/`？`/`，` 等）在表达式/条件/声明位置必须是**同一个入口**的 error 诊断；禁止逐调用点手挂守卫。诊断列一律 **1 基、UTF-16 码元**，折行与 `@原生` 去缩进必须能折回物理行列。

## 5. 条件链

```kojo
? 恋慕 >= 500
    > 她停下扫帚，眼神柔和下来。
    灵梦：「其实……{我}一直在等你。」(心形)
    灵梦：「一起吃早饭吧？」
? 恋慕 >= 100
    灵梦：「早上好，今天天气不错呢。」
? 否
    灵梦：「……早。」
```

- 连续、同缩进的 `?` 行构成一条条件链；第一个成立的分支执行。
- 不自动排序；重叠条件由作者负责；只对"永远到不了"的分支给 warning。
- `? 否` 只收束最近一条链，必须贴在链尾；物理空行会结束链，空行后的 `? 否` 是孤儿。
- 链内不空行；注释不打断链；去缩进、物理空行、新的顶层锚点结束链。
- `?` 行尾不写冒号。
- 普通条件链可省略 `? 否`；`# 池` 和 `# 表` 必须写默认分支。
- 条件占角色文本子集代码 15.4–25.4%，是跨游戏共同表面。

### 5.1 条件表达式

- 条件必须是整数表达式；比较表达式产出 `0/1`。
- 运算符沿用现有中文表：`等于` / `不等于` / `且` / `或` / `非` / `不在`；符号形式 `==` / `!=` / `&&` / `||` / `!` 等价。
- 不得在条件里写赋值、`@` 语句、`!` 触发或 `?` 链。
- 函数调用允许，但应当无副作用；编辑器对已知的打印/写状态函数给 warning。
- 条件表达式不自动求值、不排序、不常量折叠；只做 adapter 符号解析与类型检查。
- 条件里的名字解析遵守 §4.12 的优先级。

### 5.2 SIF 优化

单语句分支允许 emitter 自动降 `SIF`：

```kojo
? 恋慕 >= 500
    灵梦：「……」
```

可以落 `SIF` + 一条打印，而不是完整 `IF/ENDIF`。但这是 emitter 优化，不改变源语义；`? 否` 和嵌套块仍按完整条件链处理。

### 5.3 旧写法迁移

`如果 / 否则如果 / 否则`、`分支：` + `[条件]`、`当 / 是 / 否则` 一律 error + 迁移（目标写法见 §12.1）；同一条链里混用 `?` 和 `如果` 单独报 error，迁移工具会统一改写为 `?`。

### 5.4 链在程序块里的边界

- `@循` / `@巡` / `@复` 体内的 `?` 链按同一规则收束；去缩进到循环体基准或遇到物理空行即结束。
- `@随机` 的候选边界由 §8.4 管：裸 `?` 链不能直接做候选，必须包进 `@组`。
- `@着色` 体内的 `?` 链可以把同一颜色应用到所有分支；颜色块的配对见 §8.2。

## 6. `# 表`

```kojo
# 常量 亲近线 整数 = 500

# 表 心情 由 恋慕
    0..99     疏远
    100..499  平常
    亲近线..  亲近
    否        未知
```

### 6.1 形态

- 块头：`# 表 <名称> 由 <表达式>`，不写冒号。
- 行：`<范围> <值>`，两列，空白分隔。
- 范围：
  - `0..100`：闭区间；
  - `500..`：大于等于 500；
  - `..100`：小于等于 100；
  - `5`：精确值；
  - 端点只允许十进制整数字面量或已声明整数 `# 常量`；不允许变量、函数调用、算术表达式。
- 值列：
  - **先 trim 首尾空白**，内部空白保留；
  - 裸文本 = 字符串；整数 = 数值；
  - 需要保留首尾空白时用双引号字符串；引号内支持 `\"` / `\\`；
  - 不能写 `{表达式}`，不做插值。
- `否 <值>` 必须最后，且必须有值；缺失、空值、重复 `否`、`否` 后面还有行，都是 error。
- 行间不空行；物理空行结束表；表前后各空一行。
- 表内允许整行 `//` 注释，注释不结束表。

### 6.2 语义：静态、非重叠、无"第一条命中"

- 表是静态声明、运行期求值的计算表：声明不执行、不创建变量；被引用时按当前表达式值分档。
- **编译期检查同一张表的范围两两不重叠**；重叠即 error，不进入运行期。
- 开放区间按静态端点判重叠：`0..100` 与 `..50` 重叠；`500..` 与 `400..600` 重叠；精确值落在区间内也是重叠。
- 有 `否` 兜底，所以不要求范围覆盖全部整数；允许空洞。
- 不排序、不合并、不猜；作者写什么顺序，诊断就按什么顺序指出冲突。
- 源表达式只求值一次；所有行的值必须同一类型（全字符串或全整数）。
- 表名是文件作用域编译期名字，不能和变量、常量、池、模板、函数重名。
- 表可以引用别的表，但要做循环检测。
- 动态阈值不进 `# 表`；用 `?` 链。

### 6.3 落点

- 落点不是新运行时：优先 `SELECTCASE`（全是闭区间/精确值且无重叠）或 `IF/ELSEIF` 链（有开放区间）。
- 保持"源表达式只求值一次"：先算进隐藏槽 `__kojo_table_*`，再分档。
- `否` 落 `ELSE`。
- 重叠、类型混合、动态端点、缺 `否`、空 `否` 都是编译期 error，不能静默取第一条。
- 语料的分档主要靠 `SELECTCASE`（eraTW 口上 46,446 块）与 `DATAFORM`；`# 表` 是这些模式的糖，不是新引擎能力。

### 6.4 怎么用

```kojo
> 她今天看起来{心情}。
```

```kojo
? 心情 == "亲近"
    > 她看你的眼神比平时更软。
```

```kojo
@算
    心情快照 = 心情
```

- `心情快照` 必须是已声明变量（`# 变量 心情快照 字符串`）。
- 表在每次引用时按当前值计算；需要固定当时结果时才用 `@算` 记快照。
- 只打印不同反应时，用 `?` 链或 `# 池`，不要硬造变量。

### 6.5 旧 `当` 写法

`当 / 是 / 否则` 与表达式 `当` 一律 error + 迁移到 `# 表` / `?`（§12.1）；`# 表` 是值查找，不替代 `当` 语句块的全部场景，需要语句块时用 `?` 链；迁移工具无法等价改写时报 error 并建议 `@原生`，不生成半旧半新的产物。

## 7. 池、模板、函数、选项

| | `# 池` | `# 模` | `@函` |
|---|---|---|---|
| 本质 | 条件台词片段 | 编译期文本模板 | 运行期 ERB 函数（program） |
| 参数 | 无 | 有，字面量/简单标识符 | 有，默认值只允许字面量 |
| 调用 | `! 池名` | `! 模名(实参)` + 缩进块填 `[插槽]` | `! 函名(实参)` 或表达式位置 |
| 展开时机 | 编译期 | 编译期 | 运行期 |
| 产物符号 | 无 | 无 | 有 ERB 函数名 |
| 适合 | 条件台词 | 带槽的可复用演出 | 读写状态、返回值、复杂计算 |
| 验收层 | core | core | program |

### 7.1 `# 池`

```kojo
# 池 早安问候
    ? 恋慕 < 100
        「……早。」
    ? 恋慕 < 500
        「早上好，今天天气不错呢。」
    ? 否
        「亲爱的，早安~」(拥抱)
        > 她把脸埋进你的肩膀。

! 早安问候
```

- 池体是一条 `?` 链；每个分支可以有多行。
- `! 池名` 在编译期展开为该分支内的**所有文本行**（台词/旁白/嵌套 `?`/`@随机`），不是"返回最后一句"。
- 裸引号 = **省略说话人的台词**，默认说话人是 `{我}`（`# 视` 的角色）；要换说话人写完整 `角色：「…」`。
- 没有 `# 视` 时，池内裸引号 error；`# 视 目标` 时默认说话人是当前目标。
- 池内允许：`角色：`、`>`、裸引号、`?`、`@随机` / `@组`、`! 池名` / `! 模名`。
- 池内**禁止副作用**：`@算`、赋值、`! 函名`、`@织`、`@着色`、`@循`、`@标` / `@跳`、`@原生`、`# 幕`。
- 池内的 `@随机` 只能是**纯文本随机**；候选里出现 `@算`/赋值/`! 函名` 等副作用，按池的禁止副作用规则 error。
- `? 否` 必须有、必须最后，且分支不能为空；每个分支至少有一行可打印文本（嵌套 `?` 的分支也要最终能打印）。
- 池是编译期的，不生成 ERB 函数，不占全局名；池名与变量/常量/表/模板/函数共用一个文件命名空间。
- 池调用不能出现在表达式位置；它不是值，不能赋给变量。

**落点：**

- 池是**条件选择**，落 `IF/ELSEIF/ELSE`；如果所有条件都是对同一个判别式的等值比较，可优化为 `SELECTCASE`。
- 纯文本、无副作用的池**不能**落 `PRINTDATA/DATAFORM`：那是随机候选族，不是条件选择。
- `PRINTDATA/DATAFORM` 只用于 `@随机` 的纯文本候选（§8.4）。
- 有副作用或需要条件求值顺序的池仍然落 `IF` 链；池本身不允许副作用，所以这条主要约束嵌套的 `@随机`。
- 当前 adapter 不支持 `IF` 链时，报"不支持"；不能静默改成随机文本。

### 7.2 `# 模`

```kojo
# 模 娇羞退场(原因)
    > （她红着脸，因为{原因}而不知所措）
    [插槽]
    > （随后匆匆跑开了）

! 娇羞退场("被夸奖")
    灵梦：「才、才没有很开心呢！」
```

- 模板参数在编译期替换；参数只允许字面量或简单标识符。
- `[插槽]` 最多一个；调用处缩进块就是插槽内容。
- 调用处没有缩进块、模板却有 `[插槽]`：报错；反过来也报错。
- 模板可嵌套，但要做循环检测和展开深度上限。
- 必须支持展开预览；source map 同时指向调用处和模板定义行。
- 模板内不得藏副作用；副作用应在 `@函` 或 `@算` 里。
- 模板内允许：`角色：`、`>`、`?`、`@随机` / `@组`（纯文本随机）、`[插槽]`。
- 模板内禁止：`@算`、赋值、`! 函名`、`@着色`、`@循` / `@断` / `@续`、`@标` / `@跳`、`@原生`、`# 幕`。
- 模板不是运行期函数，不产生 ERB 符号；不要指望它做递归。

### 7.3 `@函`

```kojo
@函 增加羁绊(目标, 数值=10, 理由="日常")
    {目标}的好感度 += {数值}
    ! 记录("[{目标}] 因为 {理由} 增加了羁绊")
    @返

! 增加羁绊(灵梦, 20, "送礼物")
```

- `@函` 生成运行期 ERB 函数；可以读写状态，可以返回值。
- 参数默认值只能是字面量；ERB 的实参省略与显式 0/空串不可区分。
- 函数体：计算/赋值裸写；调用 `!`；条件 `?`；循环 `@循` / `@巡` / `@复`；返回 `@返`。
- 需要打印时用 `>` 或 `角色：`；不允许裸文本行。
- 不支持闭包、函数指针、动态函数名；动态调用只能走 `@原生` 的 `CALLFORM`。
- 表达式位置的函数应当无副作用；会打印/写状态的函数用 `!` 语句调用，不要塞进条件或插值。
- `@函` / `@返` 是 **program extension**：eraTW adapter 默认支持，但不阻塞 core 验收。
- 同名函数按 Layer 模型判定（§10.5）：
  - `unique`：同层重复 = error；
  - `shared-hook`：多定义 = 合法；
  - overlay（翻译/多版本覆盖）：合法；
  - 其余 = 真冲突。
- 不能只给低级别 warning 然后让后装载者静默覆盖。

**返回语义：**

- **只有显式 `@返` 才返回值。**
- 没有 `@返` 的函数是 void；调用处不能把它的结果赋给变量。
- `@返` 无值 = 返回 void；`@返 表达式` = 返回值。
- 同一个函数的 `@返` 必须全部是"有值"或全部是"无值"；混用 error。
- **非 void 函数必须每条可达路径都以 `@返` 结束**。编译器做保守检查：函数体末尾必须是 `@返`，或顶层 `?` 链带 `? 否` 且所有分支都以 `@返` 结束；无法证明时报 `core/func/missing-return`。
- 不提供隐式"返回最后一条表达式"的规则。
- 返回值在编译期视为动态类型；赋给已声明变量时，adapter 可做运行期/静态检查；core 不做跨函数类型推断。
- 递归、互递归见 §9.5；没有尾调用优化，受引擎调用栈限制。

### 7.4 `# 模` 与 `@函` 怎么选

- 只是嵌一段剧本/台词，希望零运行时开销：`# 模`。
- 需要读写 `CFLAG`/`TCVAR`、需要返回值：`@函`（program）。
- 只是按条件挑一句台词：`# 池`。
- 只是把数值分档成文字或档位：`# 表`。
- 需要循环/数组/跳转：program 控制块，见 §9。

### 7.5 `选项`：待定

`选项` 不是叙事，是 UI。2.0 先保留它为**局部 UI 字面量区**：

```kojo
选项：
    「用亲吻代替回答」：
        灵梦：「……唔。」
    「摸摸头」：
        灵梦：「……好。」
```

- `「标签」：` 在这里是按钮文字，不是台词；不受裸引号硬删影响。
- `选项` 块内部正文仍按 2.0 叙事规则写；裸引号只豁免按钮标签。
- 一个场景（一个 `# 机` 文件）最多一个 `选项`，不可嵌套；多轮选择走 `@原生` 或后续 `@选项` 设计。
- `@选项` / `@选` 的名字与形态待定；2.0 暂不把它写进核心正典清单。
- 2.0 文件使用 `选项` 时给独立 warning："待定 API，未来可能变化"。
- 归层：adapter UI / presentation，不是 core。

## 8. 调度区与演出块

### 8.1 `@算`：状态更新块（core）

```kojo
@算
    今天已触发 = 1
```

```kojo
@算
    临时 = {目标}的好感度 + {数值}
    临时 = 临时 * 2
    {目标}的好感度 = 临时
```

- 块头，不接行内内容；缩进收口，无结束词。
- core 块内：赋值、增量、`!` 调用、`?` 条件。
- program 开启后，块内还可以写 `@循` / `@断` / `@续` / `@复` / `@巡` / `@跳`。
- 块内不写台词/旁白；不创建作用域；名字必须已声明。
- `@算` 里的 `!` 应当是计算型调用；打印/演出不要放在 `@算` 里，放叙事区。
- `@算` 不偷偷造变量；临时变量也要 `# 变量` 声明。
- 顶层用它把状态更新和叙事分开；在调度区内可再用来做视觉分组。
- `@算` 不是"每行表达式"的替代品；它只圈出一段计算。

### 8.2 `@着色`：adapter presentation

```kojo
@着色 0xFF8080
    灵梦：「这行是红色。」
    > 她的耳朵也红了。
> 这行恢复默认色。
```

- `@着色 <颜色>` 是块头；颜色可以是十六进制字面量或已声明整数常量。
- 块体是正常叙事块；台词/旁白/`?` 链/`@随机` 都可写；program 开启后也可以写 `@循` / `@复` / `@巡`，控制转移按 §9.7 自动清理颜色。
- 自动生成 `SETCOLOR` … `RESETCOLOR`，不让作者手工配对。
- **嵌套规则（写死）：**
  - 任何 `@着色` 词法上位于另一个 `@着色` 块内，都是 error，不管中间隔了多少层 `?`。
  - `@着色` 块内可以写 `?` 链；`?` 分支内不能再嵌 `@着色`。
  - 要在不同条件用不同颜色，写平级 `@着色` 块，外面套 `?`：

```kojo
? 心情 == "亲近"
    @着色 0xFF8080
        灵梦：「……嗯。」
? 否
    @着色 0x8080FF
        灵梦：「……早。」
```

- `@着色` 块内写 `@算` 没有输出，给 warning；允许但不推荐。
- `@断` / `@续` / `@返` / `@跳` 离开 `@着色` 块时，编译器自动插入 `RESETCOLOR`；作者不用手工补。
- 归层：eraTW adapter 的 presentation；其他 adapter 未声明即报"不支持"，不生成无效 ERB。
- 旧版 `着色` / `color` 块报 error + 迁移到 `@着色`（§12.1）。

### 8.3 `@颜绘`：adapter presentation

```kojo
# 视 灵梦

@颜绘 笑顔
@颜绘 笑顔 服1
@颜绘 発情 裸 _1
@颜绘 你 自慰 裸
```

- `@颜绘` 是单行演出指令，按正文位置执行，不是块头；它本身不打印文本。
- 参数：`[对象] [表情] [服装] [差分] [特效]`。
  - 对象省略 = `我`（`# 视` 的角色）；写 `你` = 玩家。
  - 只有第一个词恰为 `我` / `你` 时才解析为对象；其余第一个词一律是表情。
  - 对象解析遵守 §3.6：没有 `# 视` 时 `我` 报错；`你` 需要 adapter 声明玩家符号。
  - 其他角色不开放 `@颜绘` 语法，走 adapter 基础库函数（如 `显示表情(...)`）或 `@原生`。
  - 表情省略 = adapter 声明的默认表情；eraTW = `通常`，由 adapter 在生成时补齐（`PRINT_FACE_PLAYER` 不依赖引擎默认）。
  - 服装 / 差分 / 特效可省略；要跳过前一格、只给后一格时，用 `""` 占位。
- 值只接受裸词或双引号字符串；不做插值/表达式。需要动态值时走 adapter 基础库函数或 `@原生`。
- eraTW 落点：
  - `我` → `CALL PRINT_FACE, TARGET, <表情>, <服装>, <差分>, <特效>`；尾部空参数省略。
  - `你` → `CALL PRINT_FACE_PLAYER, MASTER, ...`。
  - 高级参数（`立绘选择`、`EFFECT_OVERRIDE`）不进 core 语法，需要时用 `@原生`。
- adapter 未声明 `presentation.face`：`core/face/unsupported` error；参数超过 4 个：`core/face/args` error。
- 旧写法 `显示表情(...)` 仍可作为基础库函数调用；`@颜绘` 是它的专用糖，不是替代。

### 8.4 `@随机`：core 形状，adapter 落点

```kojo
@随机
    灵梦：「……呼。」
    灵梦：「再、再摸摸嘛。」
    灵梦：「……」
```

多行候选必须用 `@组`：

```kojo
@随机
    @组
        灵梦：「……呼。」
        灵梦：「……呼……嘻嘻。」
    @组
        灵梦：「再、再摸摸嘛。」
        > 她把脸别了过去。
```

- `@随机` 的**每个直接子项**是一个候选，等概率；直接子项只能是：
  - 一条文本行（台词/旁白/`空行`）；或
  - 一个 `@组`。
- 多行、`?` 链、`@算`、`!` 调用、`@循` 等控制流/副作用，必须包进 `@组`；裸 `?` 链直接做候选是 error（提示"用 @组 包起来"）。
- `@组` 只在 `@随机` 内有效，一个组算一个候选；`@组` 不嵌套，`@随机` 不嵌套。
- 至少两个候选；只有一个候选报错"随机没有分叉"。
- `@随机` 内不允许物理空行；需要分隔用 `@组`。注释行允许，忽略。
- 候选内部按 2.0 叙事规则写；裸旁白/裸引号仍然报错。
- `@随机` 不能直接塞进 `@算`；需要随机演出时回到叙事区。
- 隐藏槽前缀 `__kojo_` 由编译器分配；作者不要手写 `RAND`/`LOCAL`。

**落点（写死）：**

- 候选全是**单行纯文本**、且 adapter 支持文本变体 → `PRINTDATA/DATAFORM`。这里的"纯文本"指没有 `?`、没有 `@算`/赋值/`!`、没有 `@着色`、没有 `空行`、没有 `{…}` 运行期插值，也没有会切换打印函数的行尾提示（如 `(心形)`）；带这些内容一律走下一条。
- 候选是多行纯文本、用 `@组` 且 adapter 支持分组文本变体 → `PRINTDATAL/DATALIST`（或 adapter 等价物）；否则 `RAND + SELECTCASE`。
- 候选内有 `?` 链、`@算`、赋值、`!` 调用、`@着色`、特殊行尾提示等任何控制流/副作用 → **必须** `RAND + SELECTCASE`。
- `PRINTDATA/DATAFORM` 是随机候选族；它**不能**表达条件池。池的落点见 §7.1。
- 旧版 `随机：` / `组：` 在 2.0 报 error + 迁移到 `@随机` / `@组`；没有旧语法模式。

### 8.5 `@原生`：core 逃生舱

```kojo
@原生
    ; 逃生舱：底层 ERB 代码
    CALL HPH_PRINT "w"
```

- 块体比 `@原生` 深一级；缩进围栏，不用花括号（会和 ERB `{}` 打架）。
- 块内不解析任何 2.0 语法；`;` 是 ERB 注释，`[插槽]` 只是普通字符，`//` 也不是 2.0 注释。
- 空行原样保留；source map 逐行保留。
- 去缩进到同级或更浅，块结束；EOF 也结束。
- 空块报错。
- 糖视图无法表达的 ERB 走 `@原生`，不报错。
- 旧版叙事区的原生行在 2.0 报 error；必须迁到这里，没有直通模式。

**去缩进规则（写死）：**

1. `@原生` 块体 = 紧随其后、缩进**严格大于** `@原生` 行缩进的所有非空行；遇到缩进小于等于 `@原生` 行的非空行，块结束。
2. 块体内所有非空行必须至少比 `@原生` 行深一级（2.0 一级 = 4 空格）；出现"比 header 深、但不足一级"的行，报 `core/native/indent`，不猜它属于块内还是块外。
3. 去掉的基准缩进 = 块体内所有非空行的**最小前导空白**；内部相对缩进原样保留。
4. 空行不参与基准缩进计算，输出为空行。
5. 块内 Tab 原样保留；不要用 Tab 写 Kojo 结构缩进。

**允许位置：**

- 顶层正文、`@算`、`@函`、`@循`、`@巡`、`@复`、`@织` 体内允许。
- `# 模`、`# 池`、`@着色`、`@随机` 候选/`@组` 内禁止（会破坏纯文本/颜色配对/随机落点）。

### 8.6 `@织`：core 形状，事件目录走 adapter

```kojo
@织 回合末 之后
    ? 天气 == 雨
        > 雨声盖住了她的脚步。
    ? 否
        > 她轻轻关上了门。
```

| 写法 | 落点 | 语义 |
|---|---|---|
| `@织 <事件>` | 普通监听 | 普通桶 |
| `@织 <事件> 之前` | `#PRI` | 普通监听之前；`接管` 更前 |
| `@织 <事件> 之后` | `#LATER` | 普通监听之后 |
| `@织 <事件> 接管` | `#ONLY` | 独占：其他监听全部不执行 |

约束：

- 事件名、参数、dispatch model、priority model 来自 adapter 的 `eventCatalog`；九事件不是 core 枚举。
- 同一事件可有多个 `@织`，全部执行；桶内按装载顺序。
- `之前 / 之后 / 接管` 只有在 adapter 声明 `priorityModel = emuera-buckets` 时才可用；否则报"不支持"。
- **同一事件、同一层（非 overlay）出现多个 `接管`：编译期 error**，不等到编辑器保存。
  - 不同 overlay 层（翻译/多版本）的 `接管` 合法，按 `LayerPolicy` 处理；编辑器必须显示所有接管者。
  - `接管` 会压掉同事件其他监听；编译器对每个被压掉的监听给 warning，并列出接管者。
- 监听内运行期错误无隔离：CodeEE 会中断整条链，后续监听不执行；`TRY` 接不住内部错误。
- `@织 读档 之后` 在 `SYSTEM_LOADEND` 后执行；`SAVEDATA`/`CHARADATA SAVEDATA` 已恢复，`GLOBAL` 不恢复；新游戏只触发 `初见`。
- `@织` 是声明，不是场景；按引擎事件调用，不按 `# 幕` 顺序执行。
- `@织` 块内不能写 `# 幕`；`@织` 块有自己的监听单元，`@标` / `@跳` 不能跨出该单元。
- `@织` 不能带函数参数、不能 `@返`、不能用 `!` 调用、不能声明成 `@函`。

**事件参数与修饰词解析：**

1. 修饰词集合固定为 `之前` / `之后` / `接管`，是保留词；事件名不能与修饰词同名。
2. 解析时先匹配行尾修饰词；剩余部分按 `eventCatalog` 的事件名与参数形状解析。
3. 事件名用最长匹配；参数由 adapter 声明形状（几个参数、整数/文本、是否可省略）。
4. 未知事件、参数个数/类型不符、修饰词重复（如 `之前 之后`）、`接管` 与其他修饰词并用：全部 error。
5. 事件目录可以为参数声明保留词冲突；冲突在 adapter 装载时校验，不把歧义留到用户文件。

#### `# 机` 与 `@织` 的区别

- `# 机 指令 310`：这个文件是指令 310 的口上场景。
- `@织 回合末 之后`：这个文件还向全局回合末事件挂了监听。
- 一个文件可以同时有两者。

## 9. 程序层：数组、循环、跳转、递归

### 9.1 作用域与开关

程序层是 **program extension**，不是 core 叙事面的一部分：

- adapter 通过 `programFeatures` 声明支持哪些能力：`arrays`、`while`、`goto`、`recursion`、`foreach`、`repeat`。
- eraTW adapter 默认全部开启，并纳入 eraTW 验收线。
- 未开启的能力被使用时，报 `core/feature/unsupported`，并指出当前 adapter 支持哪些；不能静默降级。
- core 叙事验收不依赖程序层；只要 `@原生` 在，语言整体仍有逃生能力。
- 旧版有 `循环`、`标签`、`跳到`、`数据表` 等能力；2.0 在程序层提供 canonical 对应。这是语言完整性，不是保留旧语法：旧写法仍然 error + 迁移。

**建议写法与 v0.9 正典的映射（写死，防止行首 `=` 回归）：**

| 建议的示例 | v0.9 正典 | 理由 |
|---|---|---|
| `= 体力恢复 0` | `# 变量 体力恢复 整数 = 0` | 行首 `=` 不回归；声明归 `#` |
| `= 体力恢复 += 10` | `体力恢复 += 10` | 调度区表达式裸写 |
| `= 返 n` | `@返 n` | 返回值只有 `@返` |
| `= 队伍状态[0] = "健康"` | `队伍状态[0] = "健康"` | 赋值语句裸写，`=` 是运算符 |
| `= 人数 = 队伍状态.长度` | `人数 = 队伍状态.长度` | 同上 |
| `@循` / `@断` / `@续` | 同左 | 收进 program extension |
| `@标` / `@跳` | 同左 | 收进 program extension，加单元/块限制 |
| 数组 `[ ]` / `.长度` | 同左 | 收进 program extension，一维、0 基 |
| 递归 `@函` | 同左，但必须显式 `@返` | 不提供隐式返回 |

### 9.2 数组

声明见 §3.4：

```kojo
# 变量 队伍状态 字符串[3]
# 变量 人数 整数
```

访问与赋值在调度区裸写：

```kojo
@算
    队伍状态[0] = "健康"
    队伍状态[1] = "受伤"
    队伍状态[2] = "健康"
    人数 = 队伍状态.长度
```

- 下标 **0 基**；`队伍状态[0]` 是第一个元素，`队伍状态[2]` 是第三个。
- 下标表达式必须是整数；数组元素类型由声明决定。
- 读数组元素可以出现在表达式、条件、函数实参、插值中：`{队伍状态[0]}`。
- `.长度` 是数组唯一的特殊属性，产出声明长度 `N`；不支持其他属性访问。
- 不提供数组字面量、多维数组、切片、整体赋值、整体比较。
- 越界：
  - 字面量下标越界：编译期 error；
  - 常量折叠后可证的越界：编译期 error；
  - 动态下标：2.0 不做自动边界检查，行为跟随 adapter/引擎；eraTW adapter 可在调试构建插入检查并给 warning。
- 数组的存储期与 `# 变量` 相同（`场景` / `存档` / `会话`）。

遍历数组用 `@巡`（§9.3）：

```kojo
@巡 队伍状态
    ? {值} == "受伤"
        > 第{下标 + 1}位队员需要治疗。
```

`@巡` 数组时绑定 `{值}`（元素）和 `{下标}`（0 基下标）；它们遮蔽同名文件变量。遍历期间不要修改数组长度；修改元素可以，但不要依赖遍历快照之外的顺序。

### 9.3 循环：`@循` / `@断` / `@续`，以及 `@巡` / `@复`

#### `@循`：条件循环

```kojo
# 变量 体力恢复 整数 = 0

@循 体力恢复 < 100
    体力恢复 += 10
    ? 体力恢复 == 50
        > 她感觉好一些了。
        @续
    ? 体力恢复 > 80
        > 她完全恢复了！
        @断
    > 正在休息中……
```

- `@循 <条件>` 是块头；条件在**每次迭代前**求值；条件为假时零次或多次执行。
- 条件必须是整数表达式；`0` 为假，非 `0` 为真。
- `@断` 跳出最近一层循环；`@续` 跳过本次迭代剩余部分，进入下一次条件判断。
- `@断` / `@续` 只能出现在 `@循` / `@巡` / `@复` 体内；出现在外面 error。
- `@续` 是行首调度词；行尾 `续` 是等待标记，两者不混用（§2.4）。
- 循环体内允许叙事行（`>`、`角色：`）和 `?` 链；计算行裸写。
- 作者负责终止条件；`@循 1` 这类明显恒定条件给 warning（可能是有意无限循环）。
- 不支持 `@循` 的 `否则` / `结束` 词；缩进收口。

#### `@复`：固定次数

```kojo
@复 3
    灵梦：「……唔。」
    > （心跳声）
```

- `@复 N`：重复 N 次；N 是正整数字面量或整数常量。
- `@复` 内允许 `@断` / `@续`；语义同 `@循`。
- **`@复 当 <条件>` 删除**；条件循环统一写 `@循 <条件>`。一个语义只留一张脸。

#### `@巡`：遍历集合

```kojo
@巡 队伍
    ? {角}的体力 <= 0
        > {名}看起来累坏了，倒在了地上。
    ? 否
        > {名}安静地跟在你的身后。
```

- `@巡 <集合>`：运行期遍历；集合由 adapter 声明。
- 数组绑定 `{值}` / `{下标}`；角色集合绑定 `{角}` / `{名}`；其他 adapter 集合绑定 `{项}` / `{键}`（由 adapter 声明）。
- 集合为空时整块跳过；遍历期间不要修改集合结构。
- 降糖为索引循环；不生成闭包。
- 未声明的集合名：error；集合元素类型由 adapter 声明。
- `@巡` / `@复` 是 program extension；eraTW adapter 默认支持，不进入 core 首发验收线。

### 9.4 跳转：`@标` / `@跳`

```kojo
# 变量 选择 整数

@标 主菜单
> 请选择你的行动：
? 选择 == 1
    @跳 战斗
? 选择 == 2
    @跳 休息
? 否
    @跳 主菜单

@标 战斗
> 你拔出了武器……
@跳 主菜单
```

跳转是低层构造；能写 `@循` / `?` / `@巡` 时优先写它们。`@标` / `@跳` 用于菜单回跳、多结局、状态机这类结构化写法不自然的地方。

**作用域：**

- 标签属于**一个单元**：
  - `# 机` 文件里的一个 `# 幕` 场景；
  - 一个 `@函` 函数；
  - 一个 `@织` 监听。
- `@跳` 只能跳到同一单元内的标签；不能跨 `# 幕`、不能跨函数、不能跨监听、不能跨文件。
- 没有 `# 幕` 时，整个 `# 机` 文件是一个场景单元。
- 标签名只在单元内解析；不同单元可以重名。同一单元内重名 error。

**摆放：**

- `@标 <名>` 只能出现在单元体的**顶层**：场景顶层、函数体基准缩进、监听体基准缩进。
- `@标` 不能出现在 `?` 分支、`@循` / `@巡` / `@复` 体内、`@随机` 候选/`@组`、`@着色` 块内。
- 这样保证不可能"跳进一个结构化块"。
- `@标` 可以出现在引用它的 `@跳` 之前或之后；标签声明提升。
- `# 模` / `# 池` 内禁止 `@标` / `@跳`（编译期展开，标签会重复）。

**跳转：**

- `@跳 <名>` 可以在同一单元的任何位置；可以跳出 `?` / 循环 / `@着色` / `@随机` 分支。
- 不能跳进任何结构化块（因为标签不允许放在块内）。
- 跳出循环结束当前迭代；生成器不维护运行期循环栈。
- 跳出 `@着色` 时，编译器自动插入 `RESETCOLOR`。
- 跳出函数/监听：不允许；用 `@返` 结束函数，监听自然结束。
- 向后跳给 warning（可能形成无限循环）；编辑器不禁止。
- `@跳` 的目标未声明：error；`@标` 重复：error。
- 不做计算跳转；动态跳转走 `@原生` 的 `GOTO`/`CALLFORM`。

### 9.5 递归

`@函` 可以调用自身或互相调用：

```kojo
# 变量 结果 整数

@函 斐波那契(n)
    ? n <= 1
        @返 n
    ? 否
        @返 斐波那契(n - 1) + 斐波那契(n - 2)

@算
    结果 = 斐波那契(10)
```

- 递归是 program extension；adapter 声明 `recursion` 后可用。
- 只有 `@返` 返回值；没有隐式返回，不写 `= 返` 或裸 `返`。
- 同一函数的 `@返` 必须全部有值或全部无值；混用 error。
- 函数声明提升；互递归合法（A 调 B、B 调 A），但必须都有终止路径。
- 没有尾调用优化；递归深度受引擎调用栈限制；eraTW adapter 可在预览/调试中给深度 warning。
- 返回值在编译期视为动态类型；赋给已声明变量时由 adapter 做可选的静态/运行期检查。
- 递归函数不应在条件表达式里做重计算；条件应保持可读、可预测。
- `@函` 的参数默认值只允许字面量；递归调用不改变这条规则。

### 9.6 表达式

#### 字面量与名字

- 整数字面量：十进制；十六进制只用于颜色/常量场景：`0xFF8080`。
- 字符串字面量：双引号；支持 `\"`、`\\`、`\{`、`\}`；内部 `{…}` 插值。
- 名字：文件变量、常量、函数参数、循环绑定、域符号。
- 调度区里 `{名字}` 等价于裸名字；只接受单个标识符。
- 数组元素：`名字[整数表达式]`。
- 数组长度：`名字.长度`，只读整数。
- 函数调用：`名字(实参, ...)`；实参按位置，默认值只允许字面量。
- 角色属性：`{角色}的<属性>` 仅当 adapter 的 `domainSymbols` 声明该属性；不是通用对象访问。

#### 运算符与优先级

从高到低：

| 优先级 | 运算符 | 说明 |
|---|---|---|
| 1 | `( )`、`[ ]`、`.长度`、`函数(...)` | 分组、下标、长度、调用 |
| 2 | 一元 `-`、`!` | 取负、逻辑非 |
| 3 | `*`、`/`、`%` | 整数乘除余；除法向零截断 |
| 4 | `+`、`-` | 整数加减；字符串 `+` 拼接 |
| 5 | `<`、`<=`、`>`、`>=` | 比较，产出 0/1 |
| 6 | `==`、`!=` | 相等，产出 0/1 |
| 7 | `&&` | 逻辑与，短路 |
| 8 | `\|\|` | 逻辑或，短路 |
| 9 | `? :` | 三元条件（只用于表达式/插值） |

- 赋值 `=`、`+=`、`-=`、`*=`、`/=` 是**语句**，不是表达式；不能写在条件或三元分支里。
- 不支持 `++` / `--`、`**`、位运算；需要时走 adapter 内建函数或 `@原生`。
- 字符串 `+` 只接受两个字符串；整数与字符串混用 error，不做隐式转换。
- 比较要求同类型；数组不能整体比较，只能比较元素/长度。
- 条件表达式里的函数调用应当无副作用；编辑器对已知打印/写状态函数给 warning。
- 行首 `!` 是触发；表达式内部的 `!` 是逻辑非。纯表达式行不允许，所以不会把 `!名字` 误读成"逻辑非语句"。
- 除零、取模零：字面量可证时编译期 error；否则运行期由 adapter/引擎处理。
- 三元表达式不写赋值；分支应为纯表达式。需要分支副作用时用 `?` 链。

#### 赋值

```kojo
@算
    临时 = {目标}的好感度 + {数值}
    临时 += 1
    队伍状态[0] = "受伤"
    人数 = 队伍状态.长度
```

- 赋值左边必须是已声明变量、已声明数组元素、函数参数/循环绑定（后者按 adapter 规则可写），或 adapter `domainSymbols` 声明为可写的角色属性（如 `{目标}的好感度`）。
- 角色属性的可写性由 adapter 声明；未知属性/只读属性 error，不静默丢弃赋值。
- 不允许给常量、表名、池名、模板名、函数名赋值。
- 数组元素赋值的下标必须是整数；元素类型必须匹配。
- `+=` / `-=` / `*=` / `/=` 只用于整数；字符串只用 `+` 拼接或整体赋值。

### 9.7 控制转移与清理

| 离开的结构 | 编译器必须做什么 |
|---|---|
| `@着色` | 插入 `RESETCOLOR` |
| `@断` / `@续` | 清掉当前颜色块；跳到最近循环的出口/下一轮 |
| `@返` | 清掉所有打开的颜色块；结束函数 |
| `@跳` | 清掉所有打开的颜色块；跳到同单元标签 |
| `@随机` 候选 | 无运行期栈；候选结束即结束 |
| `@巡` / `@复` / `@循` | 无运行期栈；跳出即结束当前迭代 |

- `@断` / `@续` / `@返` / `@跳` 不允许把颜色泄漏到块外。
- `@跳` 不允许跨单元，因此不需要清理函数栈/监听栈。
- `@原生` 内的控制转移不受这些规则保护；作者自己负责配对颜色和标签。

## 10. Profile、Unit 与 Adapter 契约

这一节是 SDK 的地基，不是为了"以后扩展"，而是现在就约束 core 不要长歪。

### 10.1 `GameAdapter` 最小契约

| 字段 | 作用 |
|---|---|
| `id` / `version` | adapter 标识 |
| `gameFingerprint` | CSV/ERH/引擎版本/汉化版本；换盘可检测 |
| `eventCatalog` | 事件名、参数、调用方式、dispatch model、priority model、守卫 |
| `domainSymbols` | 我/你/她、角色变量、名字函数、未知符号策略 |
| `profile` | 取色、等待、池/随机落点、功能开关 |
| `presentation` | `(心形)`、`@着色`、`@颜绘`、`选项` 等演出/UI |
| `storageClasses` | `场景` / `存档` / `会话` 的落点与初始化策略 |
| `programFeatures` | `arrays` / `while` / `goto` / `recursion` / `foreach` / `repeat` |
| `encodingPolicy` | UTF-8/UTF-16LE、BOM、EOL、混合 EOL |
| `layerPolicy` | unique / shared-hook / overlay |
| `diagnosticNamespace` | adapter 专属诊断码 |
| `sourceMap` | 至少行级；包装/伴生函数映射事件头 |
| `capability` | 是否执行代码、可写路径、网络/文件访问边界 |
| `conformanceSuite` | golden + differential + smoke + encoding |

### 10.2 Profile

| 字段 | 取值 | 说明 |
|---|---|---|
| `narrationColor` | `author` / `default` / `auto` | `>` 旁白的取色；不默认"默认色" |
| `dialogueColor` | `author` / `default` | `角色：` 台词的取色 |
| `waitDefault` | `wait` / `continue` | 无 `续` 时的默认等待；没有全局值 |
| `colorMode` | `D` / `plain` | adapter 是否支持 `D` 系打印 |
| `poolStyle` | `if` / `selectcase` | 池的条件选择落点；`selectcase` 只是等值优化，不是语义 |
| `randStyle` | `printdata` / `printdatal` / `rand-selectcase` | 随机文本落点；控制流/副作用强制 `rand-selectcase` |
| `presentation` | 声明支持的演出 | `心形` / `着色` / `颜绘` / `选项` |
| `features` | extension 白名单 | `program` / `functions` / `loops` / etc. |
| `programFeatures` | 细粒度开关 | 见 §9.1 |

- `poolStyle` 与 `randStyle` **分开**；不再用一个 `textVariantStyle` 混住"条件选择"和"随机选择"。
- `poolStyle = if` 是默认；`selectcase` 只在所有条件都是同一判别式的等值比较且无副作用时由编译器选择。
- `randStyle = printdata` 只用于单行纯文本候选；`printdatal` 只用于 adapter 支持的分组纯文本；其余一律 `rand-selectcase`。
- 默认值来自 project/file profile，不来自 core。
- 独立转译器缺 profile：报错，不静默选。
- eraTW 的取色由 project/file profile 决定；旧 `旁白色` / `口上色` 迁移到 `narrationColor` / `dialogueColor`，不是 core 全局规则。

### 10.3 存储期与 `storageClasses`

| 存储期 | adapter 必须声明 | eraTW 参考落点 |
|---|---|---|
| `场景` | 每个事件/监听调用独立；入口初始化 | 生成函数内的局部/唯一前缀槽；退出即丢弃 |
| `存档` | 随存档保存/恢复；新游戏初始化 | `SAVEDATA` / `CFLAG` / `TCVAR` 或 adapter 自有槽 |
| `会话` | 进程内保留；读档不恢复 | 唯一前缀的会话变量；新游戏/重启清零 |

- 未声明的存储期：error；不能猜。
- 同一 `# 变量` 的存储期在编译期固定；不能运行时切换。
- `存档` 变量必须有稳定的槽标识；换盘/换汉化通过 `gameFingerprint` 检测。
- `场景` 变量不得跨 `# 机` 与 `@织` 共享；需要共享时用 `存档`/`会话`。

> **实现前置（2026-10-21 审阅补充，P0 风险）**：`场景/存档/会话` 需要**项目级稳定槽位分配器**（跨构建不搬槽、换盘可检测、写坏存档有防御）；设计稿只给契约字段，分配策略必须在 C1 契约冻结前专项设计。

### 10.4 Unit：编码 / EOL

- 每个源文件/产物是 Unit，不是全仓一个编码。
- 必须保留：
  - UTF-16LE BOM
  - UTF-8 BOM / plain UTF-8
  - CRLF / LF / 混合 EOL
- 不能在保存时全仓归一化；编码/EOL 变化要显式提示。
- `gameFingerprint` 用于发现换盘导致的变量表/位表错位。

### 10.5 LayerPolicy

| 模式 | 语义 |
|---|---|
| `unique` | 同层同名 = error |
| `shared-hook` | 共享事件钩子多定义 = 合法（如 eraSQN EVENTTRAIN） |
| `overlay` | 翻译/多版本覆盖层 = 合法 |
| 其他 | 真冲突 |

- 重复函数的诊断必须按 Layer 判定，不能一律"后装载者覆盖 + 低级别 warning"。
- 事件监听的多定义、函数的同名、口上的覆盖层，三者不要混为一谈。
- `@织 ... 接管` 的多重冲突按 §8.6 处理：同层多个 `接管` 编译期 error；overlay 层合法但要显示。

### 10.6 Diagnostic namespace

- 核心诊断码保持闭集，只增不改。
- adapter 新码 additive，走命名空间：
  - `unit/*`
  - `event/*`
  - `symbol/*`
  - `text/*`
  - `variant/*`
  - `overlay/*`
  - `raw/*`
- 未知事件 / 未知符号 / 缺 profile / 未开启 feature：error，不静默。
- 糖视图无法表达的 ERB：走 raw，不报错。

### 10.7 Source map

- 至少行级；能覆盖每一行产物。
- 包装函数/伴生函数映射事件头。
- 文本行映射回 DSL 源行。
- 模板展开同时指向调用处与模板定义行。
- 池展开同时指向调用处与池定义行。
- `@原生` 逐行映射；`@随机` 的隐藏槽映射到块头。
- 回滚/预览都能定位到原始 ERB 或 DSL 行。
- 坐标口径（2026-10-21 审阅补充）：1 基行列、**UTF-16 码元**；折行（`续`）与 `@原生` 去缩进必须折回物理行列；诊断与跳转共用同一换算入口。

### 10.8 Capability / 安全

- 第三方 adapter 如果执行代码，必须声明 capability：
  - 不能绕过游戏目录只读；
  - 不能任意写盘；
  - 不能读取用户凭据；
  - 网络/文件访问有边界。
- 数据型 adapter 优先；代码型 adapter 加完整性校验。
- `@原生` 的内容属于作者项目，不因 adapter 而获得额外写盘权限。

### 10.9 Conformance suite

- golden：DSL → ERB 的固定期望产物。
- differential：原 ERB vs 转译产物的输出序列。
- smoke：真实壳。
- encoding/EOL 保留。
- 事件名/守卫/颜色/等待读数。
- 程序层：数组/循环/跳转/递归的 golden 与清理规则（颜色不泄漏、跳转不跨单元）。
- 不能只做 schema 校验。

### 10.10 Feature gate 行为

- adapter 未声明某能力时，使用该构造是 error，不是 warning，也不是静默删除。
- 错误文案要指出：
  - 当前 adapter；
  - 缺哪个 `programFeatures` / `presentation` / `storageClasses`；
  - 可替代写法（例如"用 `?` 链 / `@原生`"）。
- 关闭 program 不影响 core 叙事；但 `@原生` 仍可用，作者仍有逃生舱。

## 11. 错误批注与诊断码

### 11.1 批注格式

```text
[批注] 第 12 行：这张表缺一个“否”。
恋慕不在列表里时，心情是什么？
```

- 错误阻断编译；warning 不阻断。
- 所有批注带 source map，能点回源行。
- 批注尽量短：一行定位，一行建议；不写长篇解释。
- adapter 诊断走命名空间，不覆盖核心码。

### 11.2 典型批注

```text
[批注] 第 8 行：这句是旁白还是台词？
旁白请写 `> 她点了点头。`；台词请补说话人：`灵梦：「…」`。

[批注] 第 9 行：裸引号不再是台词。
在 2.0 里请写 `角色：「…」`；只有 `# 池` 和 `选项` 里的引号是局部例外。

[批注] 第 12 行：`心形` 语句退场了。
在台词/旁白行尾写 `(心形)`；当前 adapter 未声明心形演出时会报错。

[批注] 第 15 行：`着色` 块改成 `@着色`。
写成 `@着色 0xFF8080`，块内的 `RESETCOLOR` 由编译器配对。

[批注] 第 18 行：`随机` 块改成 `@随机`。
每个直接子项是一个候选；多行候选用 `@组` 包起来。

[批注] 第 21 行：`分支：` 已退场。
用 `?` 条件链，或把台词池写成 `# 池`。

[批注] 第 24 行：2.0 叙事区不认 `;` 注释。
请写整行 `//`；`;` 只留给 `@原生` 里的 ERB。

[批注] 第 27 行：原生 ERB 不能直接混在叙事里。
请放进 `@原生` 块，或写成 `!` 调用。

[批注] 第 30 行：这张表的 `0..100` 和 `50..150` 重叠。
心情在 50..100 时该取哪一行？请拆开端点或改成一张不重叠的表。

[批注] 第 33 行：`@续` 只能在循环里用。
如果你想表达“这一行不等待”，把 `续` 写在行尾，不要写 `@续`。
```

### 11.3 Core 诊断码

> 码表是闭集，只增不改；adapter 码必须加命名空间。下列是 2.0 首批稳定码。

**声明与名字**

| 码 | 级别 | 含义 |
|---|---|---|

| `core/decl/unknown-type` | error | 类型不是 `整数`/`字符串`/一维数组 |
| `core/decl/bad-initializer` | error | 初值不是字面量或类型不符 |
| `core/decl/unknown-storage` | error | 存储期不是 `场景`/`存档`/`会话` 或 adapter 未声明 |
| `core/decl/reserved-name` | error | 使用 `__kojo_` 前缀或域符号名 |
| `core/decl/unknown-name` | error | 对未声明名字赋值/读取 |
| `core/decl/not-top-level` | error | 把声明写进可执行块/池/模板 |
| `core/decl/bad-array-size` | error | 数组长度不是正整数/整数常量 |
| `core/decl/const-cycle` | error | 常量循环引用 |
| `core/decl/const-not-constant` | error | 常量初值引用变量/调用函数 |

**类型与表达式**

| 码 | 级别 | 含义 |
|---|---|---|
| `core/expr/type-mismatch` | error | 赋值/运算/比较类型不符 |
| `core/expr/assign-to-constant` | error | 给常量/表/池/模板/函数赋值 |
| `core/expr/readonly-target` | error | 给只读角色属性赋值 |
| `core/expr/bad-index` | error | 下标不是整数 |

| `core/expr/divide-by-zero` | error | 字面量可证除零 |
| `core/expr/not-expression` | error | 纯表达式行/条件里写赋值 |

### 12.2 验收线

**2.0 编译器验收（必过）**

1. **单一模式**：源文件只按 2.0 解析；没有版本声明，也不存在旧版编译分支。
2. **旧写法全部失败**：§12.1 的旧写法不能进入 AST、不能产出 ERB；每一条都有迁移诊断。
3. **迁移闭环**：每条旧写法给出一键修复；修复后的文件按 2.0 编译通过；不能自动修复的，明确建议 `@原生`。
4. **2.0 golden**：五个锚点、`角色：`/`>`、`?`、`# 变量`/`# 常量`、`# 表`、`# 池`、`# 模`、`@算`、`@随机`/`@组`、`@原生`、`@织` 形状。
5. **adapter 契约**：`eventCatalog` / `domainSymbols` / `profile` / `storageClasses` 的 fixture 测试。
6. **声明**：类型、初值、数组、存储期、命名空间、禁止隐式声明。
7. **`# 表`**：静态非重叠、缺 `否`、空 `否`、类型混合、值列 trim、求值一次。
8. **`# 池`**：默认说话人 `{我}`、`? 否` 非空、池内禁止副作用、`IF/ELSEIF` 落点。
9. **等待**：`空行` 三态、`waitDefault`、缺 profile 报错。
10. **`# 视`**：`# 视 目标` 下 `{她}` error。
11. **插值 / 隐藏槽 / source map**：优先级、`__kojo_`、逐行映射。
12. **`选项`**：2.0 待定 warning，不当作旧语法；不作为旧语法例外。
13. **诊断码**：稳定、可引用；adapter 码 additive。

**program 验收（语言完整性）**

1. 数组：声明、下标、`.长度`、越界字面量检查、`@巡` 绑定；
2. `@循` / `@断` / `@续`：条件循环、最近循环、循环外 error；
3. `@复`：固定次数；`@复 当` 不再存在；
4. `@标` / `@跳`：同单元、跨单元 error、块内 `@标` error、向后跳 warning；
5. 递归 `@函`：显式 `@返`、互递归、无隐式返回、返回种类一致；
6. 控制转移清理：颜色不泄漏、跳转不跨单元、无运行期循环栈；
7. feature gate：未开启能力 error，不静默降级；
8. source map：数组/循环/跳转/递归都能回到源行。

**eraTW adapter 验收（必须做满）**

1. **真实语料迁移**：自动迁移率、剩余 error 清单、迁移后壳冒烟；行为 differential 对比"旧产物行为 vs 迁移后 2.0 行为"，不以旧产物为基线。
2. 九事件 / `# 机` / `@织` / 多 `接管` 编译期 error / 被压监听 warning；
3. `narrationColor` / `waitDefault` / `colorMode` 读数；
4. `(心形)` / `@着色` / `@颜绘` / `选项` 的 eraTW 表现；
5. 编码/EOL 保留；
6. `storageClasses`：`场景` / `存档` / `会话` 的落点与读档行为；

8. `# 池` → `IF/ELSEIF`；纯文本随机 → `PRINTDATA/DATAFORM`；副作用随机 → `RAND+SELECTCASE`。

**extension 验收（可选，不阻塞 core）**

- `选项` 的 UI 局部区；
- 未来第二个 adapter 的 shared-hook / plain / DATAFORM 路线；

### 12.3 非目标

- 不把 kojo-core 做成"所有 era 游戏的通用应用语言"。
- 不把面板/按钮/导入/监听这类 UI/系统构造塞进核心。
- 不先改名现有包；先加 additive SDK facade，契约稳定后再迁移。
- 不先做市场/认证；先有稳定契约、eraTW adapter、第二/第三 adapter、conformance kit。
- 不在六部语料没有证据时引入语法方言。
  - 与 §3.3 `# 方言` 的区分（写明，以免这一条把那个词位一起挡掉）：本条禁的是**某个方言专属的语法**——为 eraTW / eraFL 中任意一家单开词位、写法或解析分支，那会让语法按方言分叉（回归面乘 N，见 `docs/ARCH-language-unification.md` 的 D10 / R6）。`# 方言` 不属于这一类：它是**跨方言共用的断言记号**，词形与参数规则对所有方言一模一样，取值只是一个对 core 不透明的名字。它是该方案**唯一**新增的词位（同稿 §5.3），此后任何方言差异一律不进语法。

## 13. 本稿已拍板的点

1. **eraTW-first + SDK-ready**：eraTW 语法做满；core/adapter/SDK 分层同步打底。
2. **单一模式**：2.0 只有一种编译模式；没有版本声明；旧写法一律 error + 迁移；不保留旧版编译路径，也不以旧产物为基线。
3. **五个锚点**：`# @ > ? !`；台词无符号；行首 `=` / `~` 不回归。
4. **叙事区硬删**：裸旁白、裸台词、`｢｣`、`你：`、整行纯条件、叙事区原生行、`;` 注释、`续` 别名、`分支：` + `[条件]`。
5. **演出新家**：`心形` → `(心形)`；`着色` → `@着色`；`随机`/`组` → `@随机`/`@组`。
6. **`选项` 待定**：保留为 adapter UI 局部字面量区；2.0 warning，不是旧语法例外。
7. **声明族补齐**：`# 变量` / `# 常量`，类型、初值、一维数组、存储期、文件命名空间、禁止隐式声明。
8. **`# 表`**：两列、静态非重叠、`否` 必填且非空、值列 trim、落 `SELECTCASE`/`IF` 链。
9. **`# 池`**：编译期条件展开；裸引号默认 `{我}`；禁止副作用；`? 否` 非空；落 `IF/ELSEIF`。
10. **等待三态**：`空行` 按 `waitDefault`；`空行 等待` 强制等待；`空行 续` 强制不等待，2.0 保留。
11. **代词表**：`# 视 目标` 下 `{她}` error；没有 `# 视` 时 `{我}` error。
12. **随机候选**：直接子项只能是单行文本或 `@组`；控制流/副作用必须在 `@组` 内；`@随机`/`@组` 不嵌套。
13. **着色嵌套**：`@着色` 不能词法嵌套；外层 `?` + 平级 `@着色` 可以；控制转移自动 `RESETCOLOR`。
14. **函数返回**：只有 `@返`；无 `@返` = void；返回种类一致；不提供隐式返回。
15. **`@原生` 去缩进**：基准 = 块内非空行最小前导空白；相对缩进保留；块体必须更深一级。
16. **`# 幕` 归属**：必须有 `# 机`；多幕按顺序；不能在 `@织`/`@函` 内；标签不跨幕。
17. **`@织` 多接管**：同事件同层多个 `接管` 编译期 error；overlay 例外；被压监听 warning。
18. **旧写法处理**：`如果`/`当`/`循环`/`调用`/`返回`/`初回`/`隐藏时机`/`别名` 等在 2.0 一律 error + 迁移；只有 `选项` 作为 2.0 待定 UI 给 warning。
19. **插值优先级**：参数 > 循环绑定 > 变量/常量 > 表名 > 域符号；参数/循环绑定可遮蔽变量。
20. **诊断码表**：core 闭集只增不改；adapter 码 additive / namespaced；所有批注带 source map。
21. **隐藏槽前缀**：`__kojo_` 保留；作者变量/常量/函数不能以它开头。
22. **`# 表` 值列**：首尾 trim、内部空白保留；需要保留首尾空白时用引号。
23. **程序层**：数组、`@循`/`@断`/`@续`、`@标`/`@跳`、递归、`@巡`/`@复` 属于 program extension；eraTW 默认支持并纳入 eraTW 验收，不阻塞 core。
24. **`@颜绘`**：`[对象] [表情] [服装] [差分] [特效]`；对象只开 `我` / `你`；eraTW 落 `PRINT_FACE` / `PRINT_FACE_PLAYER`；其他角色走基础库函数或 `@原生`。
25. **冲突统一**：赋值不回归行首 `=`；返回值只写 `@返`；`[ ]` 只做后缀索引；`@续` 与行尾 `续` 靠位置区分；`@复 当` 删除。
26. **池/随机落点纠正**：池 → `IF/ELSEIF`；纯文本随机 → `PRINTDATA/DATAFORM`；副作用随机 → `RAND+SELECTCASE`。
27. **不做游戏方言**：差异优先用 adapter 数据 / profile；方言是最后手段。
28. **编码/EOL 是 Unit 属性**：按文件保留，不全局归一化。
29. **source map 覆盖每一行产物**：包装/伴生函数映射事件头；池/模板/原生/随机都有映射。
30. **安全边界**：adapter capability 明确代码执行/写盘/网络；数据型优先。
31. **完整性口径**：语言整体图灵完备（program + `@原生`）；core 叙事面保持小而干净。
32. **迁移只改源码**：迁移工具只写 2.0 源码；编译器不保留旧语法分支；验收只以 2.0 为基线，用迁移前后行为 differential 检查迁移质量。

> **实现前置（2026-10-21 语言实现审阅补充，D0 一并拍板）**：4 条结构约束写在 §4.8（引擎字面量统一编码器）、§4.13（全角标点唯一入口 + 坐标口径）、§10.7（坐标/折回物理行）、§10.3（存储期分配器）；另需拍板"项目级分析层"的包归属（重名/Layer/`接管` 的项目级判定）。

## 附录 B：eraTW adapter 参考

> 以下是 eraTW adapter 的数据，不是 core 枚举。其他 adapter 可以完全不同。

### B.1 事件目录（eraTW / Emuera）

| 中文 | 引擎事件 |
|---|---|
| `初见` | `EVENTFIRST` |
| `训练` | `EVENTTRAIN` |
| `读档` | `EVENTLOAD` |
| `商店` | `EVENTSHOP` |
| `购买` | `EVENTBUY` |
| `指令` | `EVENTCOM` |
| `训练结束` | `EVENTEND` |
| `回合末` | `EVENTTURNEND` |
| `指令结束` | `EVENTCOMEND` |

- `# 机` 使用这些事件名。
- `@织` 的 `之前/之后/接管` 只在 `priorityModel = emuera-buckets` 时生效；落 `#PRI/#LATER/#ONLY`。
- `EVENTFIRST` / `EVENTEND` / `EVENTTURNEND` 是强制事件；`EVENTLOAD` 在读档后触发。
- 监听内错误无隔离；`接管` 高风险；编辑器要显示冲突。

### B.2 域符号

- `{我}` / `{你}` / `{她}` 的落点由 `domainSymbols` 决定。
- eraTW 常见：`TARGET`、`MASTER`、`CALLNAME`、`CFLAG`、`TALENT`、`TCVAR`。
- 其他游戏可能是 `対象`、`奴隷`、`被害人編號`、`ANAME(対象)` 或中文变量；不得内置。
- 未知说话人/未知符号 error。

### B.3 存储期

- `场景`：生成函数内的局部/唯一前缀槽；入口按声明初值初始化；退出丢弃。
- `存档`：`SAVEDATA` / `CFLAG` / `TCVAR` 或 adapter 自有槽；读档恢复。
- `会话`：唯一前缀的会话变量；新游戏/重启清零；读档不恢复。
- 所有存储期必须有稳定槽标识；换盘/汉化用 `gameFingerprint` 检测。

### B.4 Presentation

- `(心形)` → eraTW `HPH_PRINT`；模式由台词/旁白与 `续` 决定。
- `@着色 0xRRGGBB` → `SETCOLOR` … `RESETCOLOR`。
- `选项`：局部 UI 字面量；`PRINTBUTTON` + `INPUTS` + 分支；待定。
- 取色：由 project/file profile 决定；旧 `旁白色` / `口上色` 迁移到 `narrationColor` / `dialogueColor`。

### B.5 文本载体

- `PRINTFORM*`：基础输出。
- `PRINTDATA/DATAFORM`：**随机**文本变体；不是条件池。
- `PRINTDATAL/DATALIST`：分组随机文本（eraTW 支持时）。
- `HPH_PRINT`：eraTW 心形演出。
- `# 池` → `IF/ELSEIF/ELSE`（或等值 `SELECTCASE`）。
- `@随机` 纯文本单行 → `PRINTDATA/DATAFORM`；多行/副作用 → `RAND+SELECTCASE`。
- erafl 的 `'= @"..."` 字符串值：adapter 扩展；核心不假设所有文本都是 PRINT。

### B.6 程序层落点

- 数组 → `#DIM` / `#DIMS` 或 adapter 存储槽；一维、0 基。
- `@循` → `WHILE … WEND`（或引擎等价物）。
- `@复` → `REPEAT … REND` / `FOR`。
- `@巡` → 索引循环；数组/角色集合由 adapter 提供绑定。
- `@断` / `@续` → `BREAK` / `CONTINUE`（或等价跳转）。
- `@标` / `@跳` → `$标签` / `GOTO`；标签单元化，不能跨事件/函数。
- `@函` / `@返` → `#FUNCTION` / `#FUNCTIONS` + `RETURN`；递归受引擎栈限制。
- 控制转移离开 `@着色` 时先 `RESETCOLOR`；离开循环无运行期栈。

### B.7 编码 / EOL

- UTF-16LE BOM、UTF-8 BOM/plain、CRLF/LF/混合 EOL 按 Unit 保留。
- 保存时不得全仓归一化。
- `gameFingerprint` 用于发现换盘/汉化导致的变量表错位。

## 附录 C：SDK 路线图

> 原则：不是"以后再做 SDK"，而是现在用 SDK 边界约束语法；但实现顺序仍是 eraTW 先做满。

1. **Phase 4：参数化 2.0 核心语法**：锁定 eraTW adapter 的 `eventCatalog`、`domainSymbols`、`profile`、`presentation`、`storageClasses`；把 core 语法落到 adapter 契约。
2. **Phase 5：程序层与验收**：数组、`@循`/`@断`/`@续`、`@标`/`@跳`、递归、`@巡`/`@复` 的 lowering 与 golden；feature gate；控制转移清理；source map。
3. **第二个 adapter：eraKoumakan**：验证 plain / DATAFORM / 无 `D` / 无 `@着色` 路线。
4. **第三个 adapter：eraSQN**：验证 shared-hook、守卫、巨型 `EVENTTRAIN`、`NO:TARGET` 路线。
5. **第四个 adapter：erafl**：验证字符串值、`RESULTS` 元数据、`PRINTDATA` 路线。
6. **SDK 工具化**：conformance kit、CLI、类型定义、文档；此时再谈发布/认证/市场。
7. **方言**：只有在某个 adapter 用数据/profile 表达不了语法差异时才引入；六部语料目前不需要。

### C.1 SDK 契约补充

- `gameFingerprint`：CSV/ERH/引擎版本/汉化版本。
- `encodingPolicy`：UTF-8/UTF-16LE、BOM、EOL、混合 EOL。
- `layerPolicy`：翻译/多版本覆盖的合法重复规则。
- `storageClasses`：场景/存档/会话的落点与初始化。
- `programFeatures`：数组/循环/跳转/递归/遍历/重复。
- `diagnosticNamespace`：adapter 专属诊断码，additive，不覆盖核心码。
- `conformanceSuite`：最小 golden + differential + smoke。
- `capability`：代码执行、可写路径、网络/文件访问边界。
- `sourceMap`：至少行级；包装/伴生函数映射事件头。

### C.2 不做什么

- 不把 `kojo-core` 做成"所有 era 游戏的通用应用语言"；核心是"可移植的口上表面 + 事件声明"。
- 不把面板/按钮/导入/监听这类 UI/系统构造塞进核心；它们走 adapter / `@原生`。
- 不先改名现有包；先加 additive SDK facade，契约稳定后再迁移。
- 不先做市场/认证；先有稳定契约、eraTW adapter、第二/第三 adapter、conformance kit。
- 不在六部语料没有证据时引入语法方言。
- 不做闭包、函数指针、动态函数名、类/对象、多维数组、数组字面量、通用属性访问、异常/线程/协程。

---

### 一句话总结

**eraTW 语法做满，SDK 现在打底；核心只共享"口上表面 + 事件形状"，游戏事实全部进 adapter。**
叙事面保持五个锚点和干净的脸；程序层用 `@循`、数组、`@标`/`@跳`、递归补足表达力；`@原生` 保证任何 ERB 都有落点。这样既不会为了通用而削掉 eraTW 的表达力，也不会让核心被某一部游戏的事实绑死。
