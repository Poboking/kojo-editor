## 2. 重复模式编目

频次口径：对四面文件族（文件名含 `性交系コマンド/奉仕系コマンド/愛撫系コマンド/絶頂`）的 grep 计数（`命中行数 / 出现于 N 份文件`），UTF-8 文件；CP932 漏计可能性存在，量级不影响排序。

> **验收批复核**（2026-10-14，`find -iname '*.erb' \( -name '*性交系コマンド*' -o … \) -print0 | xargs -0 grep -oE … | wc -l`）：族集 **449 份**（原稿 454）；`IF LOCAL && TFLAG:193` **445 处 / 109 份**（原稿 419/105）；`NOWEX:` **7,489 / 316 份**（原稿 6,424/306）；`IF LOCAL && NOWEX` **639 / 113 份**（原稿 612）；`SELECTCASE RAND:` **6,989**（原稿 6,839）；`HPH_PRINT` **29,312 / 149 份**（原稿 28,775/136）。原稿系统性偏低约 5–15%（取材时的目录遍历口径差异，非张冠李戴）。**排序与全部结论不变**；正文沿用原稿数字，读者按量级读，别当精确值引用。

### M1 委托桩（wrapper → `_1`）

**定义**：`@M_KOJO…_<i>` 只有两行——`CALL …_<i>_1` + `RETURN RESULT`；正文全在 `_1`。
**频次**：`^CALL M_KOJO.*_1$` 4,621 处；`^RETURN RESULT$` 4,715 处。
**出处**：
- `個人口上/035 Iku …/M_KOJO_K35_奉仕系コマンド.ERB:7-9`：`@M_KOJO_MESSAGE_COM_K35_80` / `CALL …_80_1` / `RETURN RESULT`；
- `個人口上/010 Suika …/M_KOJO_K10_性交系コマンド.ERB:7-10`：桩里多一行 `CALL TRAIN_MESSAGE`（调教文本先播）；
- `個人口上/049 …TOKI/M_KOJO_K49_奉仕系コマンド.ERB:355`：`CALL TRAIN_MESSAGE1`——作者在 `M_KOJO_K49_一些函数.ERB:1` 自建的变体（不是笔误，是自定义钩子）。
**现状糖**：`时机 指令 80：` 一条即生成 桩+正文 两函数（仓库 `packages/plugins/kojo-sugar/src/codegen.ts:434-440`）。**写侧已消灭；读侧（投影）就是 E13 的报红点**（见 §4）。
**痛点**：手写要背 `_1` 后缀与 `RETURN RESULT` 顺序；`CALL` 目标差一个字符即静默全哑。

### M2 記入チェック信封（`LOCAL = 1` + `IF LOCAL`）

**定义**：正文函数开头 4 行注释带 + `LOCAL = 0/1` + `IF LOCAL … ENDIF` + `RETURN 1`；`0` = 停用占位。
**频次**：`^LOCAL = 1$` 4,202 处；含子信封的 `IF LOCAL` 行 7,252 处 / 429 份文件。
**出处**：
- `M_KOJO_K12_性交系コマンド.ERB:13-18`（`LOCAL = 1` + `IF LOCAL && TFLAG:193`）；
- `M_KOJO_K35_奉仕系コマンド.ERB:241-243`：`LOCAL = 0` 的整段空模板（脚手架占位，84/85 皆如此）；
- `M_KOJO_K49_奉仕系コマンド.ERB:97 与 101`：**同一函数里 `IF LOCAL` 出现两次**（外层信封 + 正文里又套一层同名守卫）——作者手动扩段时的叠床。
**现状糖**：codegen 自动产（`codegen.ts:440-464`；空正文产 `LOCAL = 0`）。
**痛点**：信封值（0/1）与正文是否填过没有一致性约束——`M_KOJO_K63_奉仕系コマンド.ERB:61` 就写着 `LOCAL = 0` 但正文填了一整段（口上被自己关掉）。糖写侧已免疫；投影读侧要能识别"0=关"这一显示语义。

### M3 多信封分段（一个函数内 N 个 `LOCAL(=n)` + `IF LOCAL && <条件>` 段）

**定义**：绝顶/性交面把"子类"做成同函数内重复的信封段，每段一个守卫条件。
**频次**：`IF LOCAL && TFLAG:193` 419 处 / 105 份文件（性交面立位段）；`IF LOCAL && NOWEX` 612 处 / 108 份文件（绝顶子类）；`^LOCAL = ` 全部形态远大于 M2 单段口径。
**出处**：
- `M_KOJO_K101_絶頂 .ERB:16-22`：`LOCAL = 1` + `IF LOCAL && NOWEX:噴乳`；
- `M_KOJO_K101_絶頂 .ERB:43-52`：外层 `IF LOCAL` 里再嵌 `LOCAL:1 = 1` + `IF NOWEX:五重絶頂`（**LOCAL:1 被赋值却没进条件**——手写分段的典型失配）；
- `M_KOJO_K12_性交系コマンド.ERB:16-19 + 74-77`：`IF LOCAL && TFLAG:193`（立位段）段首直接 `GOTO _SEIJYOUI15` 跳到下一段——用标签绕过没写的段。
**现状糖**：**半可写**（校准，见 §3.0 探针 R1/R2）。`如果 NOWEX:噴乳：` **今天就能写**，零 error，产物逐字 `IF NOWEX:噴乳`；不可写的是 **`LOCAL`**——`如果 LOCAL && NOWEX:噴乳：` 报 `unknown-identifier`「LOCAL」（`LOCAL` 不是引擎变量族头，而 `resolve` 只认族头：仓库 `packages/plugins/kojo-sugar/src/index.ts:313-318`）。⇒ 段门的缺口在**信封槽**，不在 NOWEX 字典（P-2 因此不是 P-1 的可写性前置，见 §4）。家族表已列 `NOWEX`（`kojo-sugar/src/index.ts:296`）但无表数据（`packages/plugins/eratw-adapter/src/variable-schema.ts:140-152` 按 CSV 文件名建表 ⇒ 只有 `EX` 族），其后果发生在具名属性与反查，不在条件直译（见 M9 与 P-2）。
**痛点**：一个绝顶函数手写 5–10 段 × 每段 4–6 行脚手架；`LOCAL` 与 `LOCAL:1` 复用失配（上面第二例）静默改变分支条件。
