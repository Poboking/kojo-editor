# kojo-editor

> 口上编辑器 —— 面向 eraTW（及后续 era 系游戏）口上作者的结构感知编辑器。
> 架构采用「一切皆插件」的解耦设计：**内核零游戏知识**，扩展新游戏 = 新增一个适配器插件，内核零改动。

## 为什么

eraTW 口上生态的现状：2,285 个文件、99,028 个函数的剧本库，工具链却停留在记事本 + 全文 Grep。
作者的真实痛点（详见 `docs/RESEARCH.md`）：

- 函数归属与触发时机全靠 Grep（官方教程的答案就是"去 Grep `KOJO_MESSAGE_SEND`"）；
- 函数名写错 = 静默失效，家族完整性靠人肉核对；
- 改一行台词要"开游戏 → 玩到对应状态 → 肉眼验收"，深条件状态要 grind 十几分钟；
- 编码混杂（Shift-JIS / UTF-8-BOM），改坏文件是常态。

本项目的答案是三个递进的工具层：**导航与校验** → **脚手架与置换** → **状态快照回放**。

## 架构

```
┌─────────────────────────────────────────────────┐
│ 插件层（一切皆插件）                              │
│  erb-parser │ eratw-adapter │ sav-parser │ ...  │
├─────────────────────────────────────────────────┤
│ 槽位注册表（同槽多注册 + order 显式排序）           │
├─────────────────────────────────────────────────┤
│ 内核（只做四件事）                                │
│ DI 容器 │ 事件总线 │ 存储域 │ 文件 IO              │
└─────────────────────────────────────────────────┘
```

铁律与关键机制：

1. **内核源码中不允许出现任何具体游戏名**（eraTW / eraK / …）。一切游戏知识只在 `game.adapter` 插件。
2. **插件间禁止直接 import**，只能通过 `@kojo/plugin-api` 的类型 + 内核服务（DI）交互。
3. **依赖缺位不静默**：状态面板强制显示 `active / inactive(缺 X) / error(原因)`，依赖满足后自动激活（反 cordis 的 `__INACTIVE__` 死锁教训）。
4. **生命周期完全可逆**：deactivate 时自动逆序执行 disposer、撤销槽位、释放服务（开发工具必须能热重载插件）。
5. **写保护是内核级不变量**：游戏目录整体只读，只有显式批准的白名单路径可写；写前自动备份 + 原子写；**编码读时探测、写时保持**。

完整设计见 `docs/ARCHITECTURE.md`，调研依据见 `docs/RESEARCH.md`。

## 目录

```
packages/
├── plugin-api/          # 唯一公共契约包（类型 + 纯函数工具，零平台依赖）
├── kernel/              # 内核：DI / 事件 / 存储域 / 文件 IO / 槽位 / 插件运行时
├── plugins/
│   ├── erb-parser/      # ERB 结构感知解析 + 全量函数索引（v0.2 起订阅 project.opened 自动建索引）
│   ├── eratw-adapter/   # eraTW 全部领域知识（唯一允许出现游戏名之处：家族识别 + 约定规则）
│   ├── convention-linter/    # 约定校验引擎（零游戏知识；内置通用规则）
│   ├── ui-convention-report/ # 校验结果面板（ui.panel 贡献；点击问题跳转）
│   ├── ui-kojo-navigator/    # 函数树导航面板（角色→家族→面→函数；点击跳转）
│   └── ui-plugin-status/# 插件状态面板（首个 ui.panel 贡献示例）
└── app/                 # 桌面壳：Tauri（Rust：IO 原语）+ React + Monaco
    └── src-tauri/       # Rust 宿主：文件字节/目录/编解码/对话框 14 条命令
docs/                    # 架构 / 调研 / ADR
fixtures/                # 结构样本（真实游戏数据不入库）
```

内核运行在 WebView 前端（TS 同构、可在 Node 下全量测试），Tauri 侧只提供 PlatformBridge 原语——详见 `docs/adr/0003-shell-architecture.md`。

## 开发

```bash
pnpm install
pnpm test              # vitest：157 项单元 + 集成测试（未设游戏目录时集成冒烟自动跳过）
pnpm typecheck         # root 包类型检查
pnpm audit:decoupling  # 「一切皆插件」解耦审计（内核零游戏名 / 插件依赖纪律）
```

真实工程集成冒烟（需要本地 eraTW 目录，不设置则自动跳过）：

```bash
KOJO_SMOKE_PROJECT="D:/path/to/eratw" pnpm test
```

## 运行桌面壳

```bash
pnpm --filter @kojo/app tauri dev     # 首次需 cargo 编译 Tauri 依赖树（约 20-30 分钟）
```

启动后：选择 eraTW 游戏目录 → 确认写权限（可拒绝，只读浏览）→ 侧栏浏览角色/口上文件 → Monaco 中编辑（Ctrl+S 保存，保编码 + 自动备份）；侧栏「约定校验」面板列出全部问题，点击即跳转到对应文件行；「函数树」面板按 角色 → 家族 → 面 → 函数 浏览 99k 函数（角色下拉 + 函数名搜索），点击任意函数即定位。
